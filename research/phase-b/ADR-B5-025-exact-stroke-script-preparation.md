# ADR B5-025 — Bind local script bytes before hosting consent

Prepare an explicit Stroke CSV through the existing durable export/publication path,
retaining project revision, master hash, output identity and quantization/review metadata.
A later upload must verify those bytes and obtain its own disclosure consent. Combining
preparation with implicit cloud hosting would hide which content left the machine and
make a failed reply difficult to reconcile.

The CSV carries neutral samples. The analytic adaptation module assumes quintic curve
execution, which a list of percent-position endpoints cannot establish for Handy firmware.
Do not convert that proposal into a script while retaining its physical bounds. Preserve
this distinction in the receipt and qualify actual device behavior before admission.

Reuse the existing reservation and no-clobber exporter rather than add a second publication
store. Historical receipts do not inspect or restore mutable destination files. Unknown
publication outcomes retain their original identity and refuse blind retry. The typed receipt identifies the new format; the export ledger keeps the actual Stroke
axis so portable project capture remains compatible. Project state and physical authority
remain unchanged. No network disclosure or human acceptance is inferred from preparation.
