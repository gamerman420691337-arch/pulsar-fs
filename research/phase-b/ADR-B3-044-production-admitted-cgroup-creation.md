# ADR B3-044: commit creation admission before production launch

Status: production routing and staged-byte custody verified by terminal current-source gates; legacy/native-image obligations remain open; release remains unqualified.

Route tracked ordinary jobs, live inference and encoded-source capture through the admitted creator. Validate existing bindings before ledger activation, publish format 4, commit schema 20/minimum 4 in the authority transaction and create resources only after that commit. Preserve existing CUDA and worker requirements when raising the barrier. Historical-reader fixtures must construct their actual preceding formats rather than invoking the newly upgraded production writer.

Transfer prepared snapshots and their claim into creation custody before fallible creation. On failure, retire the group once, retain all claims through independently acknowledged staging cleanup and avoid re-demanding an already cleared group obligation. On success, transfer both owners into worker custody before exposing a group handle or spawning. Share admitted preparation between the fixed three-input inference path and two-input encoded-source path.

Untracked standalone helpers retain their explicit ownership mode. Native image capture, legacy resources, root/boot relocation, exhaustive engine crash cuts and independent acceptance remain unfinished. A new healthy path does not qualify an older orphan or authorize production GPU admission.
