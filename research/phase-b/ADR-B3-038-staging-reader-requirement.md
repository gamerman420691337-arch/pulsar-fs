# ADR B3-038: bind required staging ledger semantics before creation

Status: mandatory schema-19 reader requirement implemented; six focused requirement checks, native compatibility, 956 workspace/494 feature cases, current native retiming/WAL and 235 structural checks pass. Production staging format and arming remain pending.

The format-2 worker fence does not record staging obligations. Adding a separate file or only a newer ledger header would permit a missing or downgraded ledger to evade the new requirement. Use a conditional schema-19 reader barrier and an exact host-local worker-binding layout with a required minimum ledger version, preserving its scope. Schema 19 must require the new layout; loss of the column must not look like an optional legacy binding. Require the ledger version before reconciliation and writable SQLite startup. Existing readers reject schema 19 during their read-only probe; retain an actual preceding reader and verify both positive opening and pre-write refusal. The initial layout-only variant passes native refusal checks but cannot distinguish a removed column from an original legacy layout under schema 17. Retain that intermediate evidence without treating it as the completed barrier.

Keep the requirement host-local. Logical project export must not grant ownership over source-host staging paths. Preserve the existing schema-17/schema-18 and portable CUDA checks in legacy subjects and carry their full requirements into schema 19; the binding extension must neither remove their active-table requirements nor refresh away an outstanding staging requirement. Future staging admission must durably publish the requirement before creating temporary bytes. Unknown, missing, changed or downgraded requirements refuse instead of reconstructing authority from a pathname.

This decision does not by itself define or enable ledger format 3. Creation-error custody, all staging/native-image transfers, durable cleanup, cgroup creation intent and full engine crash recovery remain required. In particular, the passing test-only lifecycle prototype is not production integration, and the existing actual engine-primitive crash counterexample remains open until the relevant path is repaired.
