# ADR B2-004: Portable candidate interval restrictions

Status: implemented locally; qualification remains open.

The preceding native interval increment did not retain active restrictions for cloned proposals. Two independent native schema-8 reproductions show that removing job authority also removed scope, allowing an explicit whole commit to delete outside motion. Original worker declarations already survive as archival bytes, so discarding the restriction is unnecessary.

Separate application scope from execution identity. Add optional checked `PackageCandidate.project_interval`; derive native restrictions through the existing typed evidence parser and resolve clone aliases through the verified canonical origin graph. New declarations must equal original restrictions; namespace disagreements refuse. Legacy formats recover original settings without rewriting originals or executing archived paths. Imported jobs remain inert.

Store resolved imported restrictions in a separate engine-owned table, including explicit whole-project scope. Existing snapshot and commit/merge guards consume it. Rebase copies it transactionally. Bounded legacy recovery verifies root/identity/origin bindings and original worker evidence, checks local candidate correspondence, then publishes all missing policy rows with schema 9. Failed recovery does not publish that barrier or default an unresolved alias to whole-project scope. Auxiliary layout preparation can remain; no destructive rollback is implied.

Require portable format 7 for active interval declarations and retained format-7 ancestry. Older readers refuse unsupported subjects before publishing a clone. Preserve simpler minimum package versions and original bytes. Schema 9 blocks schema-8 engines from bypassing imported restrictions. This supersedes B2-003's portable-format and clone-scope deferral; its native selection/lattice/context/clock contracts remain in force.

Authenticated native tests retain protected/missing-axis/outside motion through clones and application, reject widened/omitted restrictions, exercise stale rebase and restart, recover genuine old clone subjects with source paths unavailable, and independently exercise missing-evidence and historical-reader refusal. These checks establish only their local software scope; model/media, physical Handy, platform, human and release qualification remain open.

See ../../docs/PULSAR_PORTABLE_INTERVAL_SCOPE.md and its exact source/binary/test receipt. Recovery of already committed damage is an explicit user-history decision; migration never silently rewrites it.
