# Own original HSP synchronization before consuming native readiness

Give HSP preparation its own original request, journal history and native owner.
Hosted synchronization requires a hosted controller and acknowledged program setup;
reuse its fixed clocksync transport and conservative clock mathematics without
manufacturing those hosted subjects. Reserve the request before owned work, retain
one original budget captured before locks, and claim durably before the single
effectful synchronization GET. Replay can finish metadata but cannot repeat the
request or reconstruct clocks from history.

Retain readiness only from current accepted HSP evidence, fresh native device reads
and an independent server sample. Bind subsequent source facts to that exact clock,
including its full uncertainty and original expiry, on both sides of durable
claim I/O. Transport retains the original deadline and retirement checks.
Readiness leaves playback disabled and requires a separate admitted source and
explicit control intent before a native handoff can consume it.

Journal v12 seals one preparation-to-child link and transfers route custody only
with the child's first durable Setup claim. A merely Prepared or Cancelled child
cannot release its parent's attempted synchronization custody. Exact aggregate
recovery includes both histories, preserves Unknown, and releases only matching
joined native owners. Preserve v11 bytes and empty-extension identities; startup
and status never restore native authority. See [the preparation guide](../../docs/PULSAR_HANDY_HSP_PREPARATION.md).
