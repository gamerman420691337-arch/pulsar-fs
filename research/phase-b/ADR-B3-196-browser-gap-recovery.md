# ADR B3-196: Resume original values uploads after lost outcomes

Bind edit values to separate original Begin and Finish request identities before
admission. Retain the admitted lease, obtain authenticated accepted-prefix status
and resume remaining bytes only. Mark finalization attempted before dispatch;
retry the original Finish directly through the Engine's existing durable receipt.
Validate scope, boot, endpoint, digest, byte range, expiry and progress before bulk.

Do not silently abandon unknown outcomes or fabricate replacement identity. Keep
browser gap proposals as explicit synthesized motion requiring separate review and
commit. Same-server recovery is implemented; server-loss journaling and managed
release remain explicit follow-up obligations.

See [contract and evidence](../../docs/PULSAR_BROWSER_GAP_RECOVERY.md).
