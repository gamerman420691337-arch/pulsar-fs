# ADR B3-113: bounded coarse proposals with full-resolution flow checks

Status: implemented software; native coverage and qualification recorded separately.

The actual 18-original-pixel camera-shift fixture exposes a resolution-dependent limit. At the new 480 by 640 decoded view it moves 10.666667 pixels per pair, beyond the local six-pixel search. The worker correctly retains unavailable coverage and refuses standard export. At the explicit 135 by 180 view the same source moves three pixels, remains supported and exports constant position 50. Discarding detail to fit a local search is not the desired final behavior.

Preserve accepted local matches exactly. For rejected points in views whose smaller dimension is at least 256, try two bounded box-average half-resolution levels. Pixel-center mapping is `(p + 0.5) / scale - 0.5`; odd trailing rows/columns are cropped and edge support is refused. A coarse match is only a proposal. Recenter fixed 32 by 32 tiles on the original point and proposed full-resolution destination, then run the existing checked forward/backward solver at full resolution. Reverse matching uses the actual forward destination; differing tile origins cancel in the cycle error. Publish only a supported final correspondence, with the original point coordinates and full-resolution error. No padding or clamped edge point becomes evidence.

Maintain existing shape, one-million-pixel, 64-point, texture, photometric, iteration and forward/backward bounds. The new per-component displacement bound is explicit, finite and no greater than 34 pixels; the default three-level search uses 26. Region consistency still requires three points and a two-thirds one-pixel consensus. Legacy separation keeps its 8.5-pixel admission; the worker uses the declared multiscale bound. Missing or inconsistent support remains unavailable. At the worker boundary, preserve the initial 16 target samples; for eligible larger views with fewer than three supported points, try up to 48 additional distinct interior samples. Record the actual count and retain the 64-point cap and existing three-point consensus admission. The initial native multiscale experiment supported only two points in the last 18-source-pixel pair; that partial result is retained rather than lowering the threshold.

Record configured maximum level, recovered point counts and the component bound alongside target/background vectors. Detector generation uses recipe v3. Clock custody accepts both v2 archived receipts and v3 detector receipts while retaining mode/configuration/identity checks. Temporal and no-model recipes are unchanged. This is an additive output diagnostic, not a new client-supplied evidence authority.

Pyramidal sparse flow and iteration limits are established technique context in the [official OpenCV documentation](https://docs.opencv.org/4.13.0/dc/d6b/group__video__track.html). This implementation uses Pulsar's existing checked solver and independent box proposals/tile refinement; it does not claim OpenCV numerical parity. See [scoped experiments](../../docs/PULSAR_MULTISCALE_FLOW.md). Full model quality, arbitrary large motion, performance and release/device/human qualification remain separate.
