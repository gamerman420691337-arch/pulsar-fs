# ADR B6-007: Owner-selected packs use the pinned CPU generation boundary

Status: implemented locally; broader qualification remains open.

Inert offline intake establishes declared-byte integrity, not permission to execute a supplied model. Add a separate durable host-owner selection containing the exact manifest digest, optimistic revision, selecting session/request and profile. Require explicit unqualified native-execution approval for selection; deactivation records a new revision without granting approval. Historical request replay returns the prior receipt without changing the current choice.

A selection never loads the supplier runtime or native dependencies. Require the exact engine-pinned CPU runtime and implemented preprocessing/resource envelope. Repeat full pack integrity checks at generation, snapshot the opened model descriptor, compare its exact identity, retain manifest/profile/approval bytes in content-addressed execution dependencies, and recheck the current selection in the project admission transaction. Preserve captured dependencies on retry and archival clone; imported evidence cannot select or authorize a model pack.

Store the first selection together with schema-12 reader protection and request replay. Preserve that boundary through existing project recovery/export/import paths. Worker settings and the portable format stay unchanged: opaque dependency evidence is retained without a new authority field in the portable manifest. The standalone CLI obtains the exact recorded choice/profile and submits the dedicated project generation command; rendered desktop parity remains owed.

Owner approval is scoped to future offline generation, not publisher authenticity, redistribution rights, compatibility qualification or model/media quality. Accepted jobs remain pinned when selection changes. Do not describe deactivation as cancellation or use authored CPU graphs as evidence of learned-model accuracy.
