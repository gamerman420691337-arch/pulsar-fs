# Stash integration: verified broker contract

Research date: 2026-09-29. Official upstream inspected at commit `b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6` (the then-current `develop` HEAD). This is a source compatibility target, not a claim about the user's installed Stash version. No local Stash was contacted and no media or credentials were transmitted. Legacy Pulsar source was inspected read-only.

## Verified API behavior

- Missing-script discovery uses `findScenes` with `scene_filter: {interactive: false}`. **`interactive` is a Boolean**, not `{value, modifier}`. `FindFilterType` supplies `page`, `per_page`, `sort`, and `direction`; negative `per_page` requests everything. The implementation defaults the page to 1 and page size to 25. Use bounded positive pages and a total limit. Sources: [filter schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/filters.graphql#L6-L14), [interactive field](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/filters.graphql#L339-L343), [pagination implementation](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/pkg/models/find_filter.go#L87-L118).
- Scene records expose `id`, `interactive`, `files`, and `tags`. Video files expose IDs, server-side paths, fingerprints, dimensions, and duration. A returned path belongs to Stash's filesystem namespace; it is not an instruction to access an arbitrary local path. Sources: [scene schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/scene.graphql#L36-L83), [file schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/file.graphql#L77-L108).
- Scene `interactive` reads the **primary file's stored flag**. Scan computes that flag by checking existence with `Lstat` of the sibling formed by replacing the video extension with `.funscript`; it does not parse or qualify the script. Consequently `interactive:false` can be stale, and must never authorize overwriting an existing local script. Sources: [interactive resolver](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/internal/api/resolver_model_scene.go#L351-L360), [scan detection](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/pkg/file/video/scan.go#L40-L56), [sibling naming](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/pkg/file/video/funscript.go#L8-L14).
- `Scene.files` loads the association list; the inspected resolver does not designate the first element as primary. The public Scene schema lacks a `primary_file_id` field. For automatic generation, reject ambiguous multifile scenes or require explicit file selection. Sources: [file resolver](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/internal/api/resolver_model_scene.go#L46-L68), [Scene schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/scene.graphql#L36-L83).
- `metadataScan(input)` returns a **job ID (`ID!`)**, not success Boolean. `findJob(input:{id})` returns nullable Job with status and error. Statuses are READY, RUNNING, FINISHED, STOPPING, CANCELLED, FAILED; a missing job returns null. `ScanMetadataInput.paths` and `rescan` allow a targeted rescan. FINISHED alone does not establish scene attachment; re-query the scene. Sources: [mutation/query schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/schema.graphql), [job schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/job.graphql), [missing-job resolver](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/internal/api/resolver_query_job.go#L22-L30), [scan input](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/metadata.graphql).
- Preserve tags using `bulkSceneUpdate(input:{ids:[scene_id],tag_ids:{ids:[tag_id],mode:ADD}})`. The schema offers ADD, SET, REMOVE; ADD applies unique append to existing relationships. This avoids the lost-update risk of fetching a tag list and then replacing it. Sources: [bulk update schema](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/graphql/schema/types/scene.graphql#L163-L193), [relationship update implementation](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/pkg/models/update.go#L123-L135).
- Authentication accepts `ApiKey` header (also an `apikey` query parameter, which Pulsar should not use). Querying `paths` can return a funscript URL with the configured API key; omit paths/stream URLs from discovery and retained receipts. Sources: [session authentication](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/pkg/session/session.go#L151-L169), [URL resolver](https://github.com/stashapp/stash/blob/b6b09dd5fd9b6be6e36deb3d20bc5c4cf52450a6/internal/api/resolver_model_scene.go#L148-L164).

## Legacy differences

`/home/brianklam/Desktop/Funscripts/pulsar/src/stash/client.rs` currently sends an object for `interactive`, reads only one page, treats a non-Boolean metadata scan response as successful, and updates `tag_ids` with a singleton list. The official schema above contradicts the filter/scan assumptions and supplies a tag-preserving alternative. Its GraphQL helper also treats any `errors` key (even an empty array) as failure, and substitutes null for missing data; the migrated broker should validate typed responses and reject nonempty errors without retaining server error text that may reveal credentials or paths.

## Proposed implementation contract

These are Pulsar design recommendations inferred from the verified behavior, not additional Stash guarantees.

1. Engine owns bounded network requests, endpoint policy, credential resolution, authority, and effect receipts. Client sends typed operations, never raw GraphQL or a plaintext API key. Credential environment name is persisted; the value stays in memory. Default to the explicit loopback endpoint; a remote endpoint requires explicit configuration. Reject userinfo/query/fragment and redirects so a key cannot migrate to another origin. Require HTTPS for a remote credential-bearing endpoint.
2. Discovery returns a capped, deduplicated scene snapshot, count, pagination completeness, and explicit per-scene eligibility. Use fixed operation documents, positive page sizes, bounded response bytes, and a request deadline. Materialize selection before producing scripts or scanning: changing the missing-scenes filter while paging can skip scenes. Counts are advisory because Stash provides no snapshot transaction through this API.
3. File eligibility requires exactly one selected video, configured component-boundary path mapping or explicitly granted local root, a canonical regular local file under that root, and no existing sibling script (including symlinks). Remote download/streaming is a separate authorized feature. Persist server path and local path distinctly; metadata scans use the server namespace. Revalidate input/output identity immediately before export.
4. Generate through existing revision-bound Pulsar jobs. Record scene/file IDs, source fingerprint, project revision, job/candidate IDs, export hash, and outcome. Existing output must be reported as skipped/conflict; export must use atomic no-clobber publication. Never infer overwrite consent from the remote database flag.
5. Link only successfully exported files. Submit a nonempty, explicitly selected server-path list; never send empty paths/null (which might broaden scan scope). Retain returned scan ID; bounded polling distinguishes submitted/running/failed/cancelled/unknown from verified-linked. Retry may enqueue duplicate scans, so reconcile a recorded job before resubmission. A null job is unknown, not success. After FINISHED, fetch the scene again and verify `interactive:true` and expected file identity.
6. Tag creation is optional and separately reported. First exact-match lookup; if create fails or has uncertain delivery, re-query before retrying. Attach with ADD and verify presence. Failure to tag does not invalidate an exported script; failure to rescan does not justify regenerating it. Report partial failures and a non-success aggregate result for requested effects that remain failed/unknown.

## Required compatibility tests

Use an offline mock server, not the user's Stash: strict Boolean filter; multi-page bounded discovery and repeated IDs; rejected multifile selection; path-prefix collision/traversal/symlink; existing script despite `interactive:false`; secret-free logs and rejected redirects; GraphQL nonempty errors/null data/malformed or oversized body; metadata scan returning ID; RUNNING then FINISHED and successful re-query; FAILED/CANCELLED/null job/deadline; ADD preserves preexisting tags and retries remain unique; generation failure prevents scan/tag; restart reconciles an already submitted scan. Real installed-version compatibility remains unverified until explicitly exercised.
