# ADR B3-085: authenticated assistant proposal attempts

Status: authenticated asynchronous Linux proposal path implemented; application effects, first-party controls and qualification pending. Full roadmap INCOMPLETE.

## Decision

Clients select an exact host-registered lifetime profile and submit bounded text against a current project revision. Keep runtime/model paths and system context host owned. Require both Read and Edit; issue durable attempt/receipt identities before dispatch; bound retained and active operations. Run the existing sealed/shared/cgroup parent. Recheck current authority/revision and original execution identities before completion. Commit cancellation, session revocation and owner withdrawal before captured signalling. Preserve failed completion publication for observation-driven metadata retry, without repeating inference. Interrupt on restart and require fresh host registration/request.

Reports propose data only. The initial context exposes future sample strides, with actual target/review/edit context and explicit effects/undo remaining next. This is no default/bundled quality selection, public owner setup, installed Python requirement or native client execution. Standing profile permission is trusted embedding configuration, expires at restart and is withdrawable; application action approval is independent.

## Evidence

Eight source-operation tests and a separately executed authenticated pinned Qwen3 request pass. Missing Read or Edit independently refuses before context/state access. Cancellation receipt refusal preserves state/unsignalled handles; completion-write refusal retains a result and repairs metadata through observation without inference replay. The actual proposal reaches retained Completed status with unchanged project and confirmed worker retirement. Earlier compilation, routing/authorization mistake, nonexistent test target and broad import/native-cleanup failures are retained.
