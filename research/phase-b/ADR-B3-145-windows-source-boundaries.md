# ADR B3-145: Windows source boundaries and portable test evidence

Status: Windows GNU compilation corrected; portable emulated tests FAIL. Native Windows/MSVC/runtime/packaging qualification remain open.

The actual offline Windows GNU workspace/all-target check first refuses an ignored WASM controller test that imports Unix permissions without a Linux gate. Its documented delegated Linux cgroup requirement is now enforced by target scope. The next check exposes production inference of the optional Stash source receipt and action ancestry through branches absent on Windows, plus test helpers referring to gated publication/fence APIs. Give prepared source its explicit private tuple alias; keep action ancestry scoped to the Unix branch that produces/consumes it. Match mixed Stash export helper gates to their already-Unix callers, scope custody assertions to the available fence, and make the database-only no-download-reply helper portable. Gate imports/limits to their actual platform users. No enabled effect, export semantics, unsupported platform refusal or qualification boundary is changed.

The full offline Windows GNU workspace/all-target source check and 38 linked portable test executables now build. Compilation is insufficient. Isolated Wine 11.19 execution returns 571 passed, 54 failed and 3 ignored tests across 34 passing and 4 failing executables. Failures are retained: Clients 22, Protocol library 23, annotated generation 1 and live CUDA reports 8. Many positive fixtures use Unix absolute paths, and two Client positives exercise retained package handles explicitly unsupported on Windows. A canonicalized Windows extended-path spelling also differs from its uncanonicalized expected path. Keep these as open investigations; do not widen runtime validators or convert unimplemented functionality into a passing fixture claim.

Linux Core/Protocol suites pass; rebuilt Engine/Clients pass 841/322 with 70/8 ignored. Both strict Linux lint configurations, all-target check, formatting, native build, 445 architecture checks and 36 source guards pass. These do not prove Windows or all-feature runtime behavior. The first obsolete Client test executable invocation is retained separately; final Linux Client evidence uses the executable emitted by the current build.

The diagnostic harness runs all discovered cross-built test executables under a fresh private RAM Wine prefix, with network and PID isolation. It retains public test logs and exact binary identities, then waits for its prefix server and destroys the namespace. No native Windows machine, GUI acceptance, accelerator or platform release gate is substituted by emulation. See [scope](../../docs/PULSAR_WINDOWS_SOURCE_CHECK.md).
