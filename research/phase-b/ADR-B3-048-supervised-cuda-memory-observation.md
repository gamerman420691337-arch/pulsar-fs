# ADR B3-048: Supervised CUDA memory observation and image handback

Status: Implemented internal probe/admission prerequisite; production inference jobs remain disabled.

GPU accounting previously accepted caller-supplied observations; its research example used an unconfined host utility without a standalone observation deadline. Production needs actual device-bound measurements from a supervised native process, while keeping foreign driver code outside the authority process.

Add a confined memory-observer role using the owned image/device/module mount assembly and shared custody. A role-tagged sealed loader relay distinguishes inference from observation. The initial executable hashes mounted bytes before selecting the captured loader; the observer executable checks them again. The explicitly captured CUDA driver verifies the worker's actual logical ordinal, UUID, PCI address, inventory, total capacity and API version. Captured NVML selects that UUID, reads it back and queries total/free/used bytes. No inference session or CUDA context creation API is requested. Driver/NVML initialization are native effects, not pure parsing or a promise of zero driver resource use.

After an initial native query, retain both libraries and perform the full image recheck, then query memory again. Only that final query's original CLOCK_MONOTONIC start time is returned. The prior ordering measured before the final full-image hash and correctly failed the one-second freshness gate in an actual native run. Re-querying after the integrity work preserves that gate; it does not refresh an old sample by changing its timestamp. Runtime device identity is checked again around the measurement. This does not establish immutable backing bytes or attest arbitrary native code.

The parent bounds framed transport, diagnostics, cancellation and child polling; it rejects trailing output, unsuccessful exit, wrong request/device/capacity fields, future timestamps and age over one second. Exact retirement returns the uniquely typed image/device asset only after users, cleanup and group retirement. Image storage survives; probe CPU capacity releases. The final admission method rechecks the loaded owner policy, captured declaration, request digest and sample freshness, then uses the pool's locked aggregate RAM/job/GPU admission. Total capacity is the smaller SDK/NVML total and available capacity is capped by that total. Both original totals remain in the response; their difference is not explained away.

The NVML C ABI follows installed `/opt/cuda/include/nvml.h` and NVIDIA's [device-query documentation](https://docs.nvidia.com/deploy/archive/R550/nvml-api/group__nvmlDeviceQueries.html) and [v1 memory structure](https://docs.nvidia.com/deploy/archive/R550/nvml-api/structnvmlMemory__t.html). Linux's v1 structure uses three unsigned 64-bit counts, with used including reservations. Missing symbols and unsuccessful statuses refuse. This remains NVIDIA/Linux-specific; no MIG, other-vendor or platform qualification follows.

An explicitly configured native fixture captures the preceding 74-library image plus a declared NVML library, exercises actual confined measurements, image handback, a fresh 64 MiB offline accounting claim, refusal of a second offline claim, release and cancellation-before-spawn cleanup. The fixture supplies a durable admitted group, not a committed Engine GPU job. Direct shipped observation roles refuse without confinement/private relay. No production inference, physical VRAM quota, model/media, Handy, platform or release acceptance is established.

Evidence: [checkpoint](../../docs/evidence/roadmap-2026-10-07/cuda-memory-broker/checkpoint.json). Initial failures and their source/evidence limitations are retained separately. Production resolution, inference launch/egress, durable result acceptance and restart remain the next integration work.
