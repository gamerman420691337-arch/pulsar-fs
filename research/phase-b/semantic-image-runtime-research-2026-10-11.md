# Local semantic image runtime for constrained Pulsar proposals

Research date: 2026-10-11. Status: **source-supported candidate, no inference or task qualification**. Scope: image pixels → learned vision-language inference → bounded pattern proposal → existing independent validation and owner approval. No model download, model execution, training, user-media change, keys, or excluded FunGen weights occurred in this research. Only this note was created; no temporary files or clones were created.

## Finding and proposed route

Use **SmolVLM-256M-Instruct plus its matching multimodal projector** as the smallest practical initial image-only candidate found in the inspected first-party runtime support list. It is a candidate for evaluation, not proof of adequate pattern quality. The official publisher describes image/text input, a compact SigLIP encoder and SmolLM2 decoder, and Apache-2.0 licensing. The model's generic image benchmarks do not measure Pulsar pattern generation. [Publisher card, pinned revision](https://huggingface.co/HuggingFaceTB/SmolVLM-256M-Instruct/blob/7e3e67edbbed1bf9888184d9df282b700a323964/README.md), [supported runtime models](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/docs/multimodal.md#L60-L66).

A short one-shot experiment can use `llama-mtmd-cli` from the already-pinned llama.cpp source. A product implementation should prefer a small Pulsar-owned executable linked to `libmtmd`, `libllama`, and the pinned common template/sampling helpers: it can accept bounded RGB bytes and emit exactly one JSON proposal without terminal output conventions. Image encoding is a separate model component: matching text GGUF and mmproj are both necessary. Text-only Qwen plus labels or a filename does not establish pixel conditioning. [Runtime architecture](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/README.md#L17-L37).

## CLI: real grammar and headless path, with compatibility traps

Source establishes the following chain: `--json-schema-file` converts to `params.sampling.grammar`; mtmd initializes `common_sampler_init(model, params.sampling)`; generation calls `common_sampler_sample` and `common_sampler_accept(..., true)`. The common sampler installs and enforces the grammar. This is constrained inference, not a prompt asking for JSON. Reuse finite enums/consts and independent cross-field validation; do not assume every JSON Schema keyword is supported. [Arguments](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/common/arg.cpp#L2271-L2307), [sampler initialization](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/common/sampling.cpp#L216-L309), [sampler enforcement](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/common/sampling.cpp#L605-L683), [schema limits](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/grammars/README.md).

`llama-mtmd-cli` selects one-shot mode only when both prompt and image list are nonempty. It loads actual image bytes, inserts the media marker if absent, evaluates the image/text chunks, emits generated pieces, suppresses EOG text, and ends with whitespace. Positive `-n` limits generation; a negative value becomes `INT_MAX`. It may return success after exhausting tokens with incomplete JSON: parsing must fail closed. SIGINT produces exit 130 and interruption text, which must be rejected. The one-shot branch does not echo the prompt. [One-shot branch](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd-cli.cpp#L424-L518), [generation](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd-cli.cpp#L217-L257), [exit](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd-cli.cpp#L596-L600).

Use a dedicated argument list; do **not** copy the current completion flags. `--single-turn`, `--conversation`, `--no-display-prompt`, `--no-context-shift`, and `--system-prompt-file` are not declared for MTMD in this pin. `-f` is available; `-sys` accepts a system string and includes MTMD. No automatic downloads or URL inputs. The following is an implementation sketch to confirm against a built candidate's help, not an executed command:

```text
llama-mtmd-cli -m /assistant/model.gguf --mmproj /assistant/mmproj.gguf
  --image /assistant/input.png -f /tmp/user.txt
  -sys <bounded system string> --json-schema-file /tmp/proposal.schema.json
  --offline --jinja --no-mmproj-offload -ngl 0
  -c 2048 -n 1024 -t <admitted threads> -tb <admitted threads>
  -b 256 -ub 128 --seed 42 --temp 0
```

Both `-ngl 0` and `--no-mmproj-offload` matter: the latter independently disables projector GPU offload. Build `llama-mtmd-cli` with CPU-only backends and preferably `MTMD_VIDEO=OFF`, `LLAMA_SUBPROCESS=OFF` for still images. [Offload controls](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/common/arg.cpp#L2581-L2655), [build target/dependencies](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/CMakeLists.txt).

Default logger sends generic `LOG` output to stdout and ordinary diagnostics to stderr. `--log-jsonl` changes that routing and must be prohibited. Read bounded stdout and stderr concurrently, require successful exit, parse the **entire** stdout as JSON with JSON whitespace permitted, and reject truncation, interruption text, extra objects and trailing non-whitespace. Do not search for braces or apply the completion EOG trailer. [Actual logger routing](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/common/log.cpp#L90-L110).

## Library adapter: bounded pixel input without file decoding ambiguity

The C API exposes `mtmd_init_from_file(mmproj, text_model, params)`, `mtmd_bitmap_init(width, height, data)`, tokenization, chunk counting and encoding. Bitmap bytes must be exactly `width × height × 3`, RGB interleaved. `mtmd_tokenize` requires matching media-marker/bitmap counts; `mtmd_tokenize_from_parts` avoids marker parsing. `mtmd_helper_eval_chunks` encodes image chunks and decodes their embeddings into the language context. This establishes actual pixel conditioning. [Initialization/bitmap contract](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd.h#L97-L175), [tokenization](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd.h#L286-L331), [evaluation/counting](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd-helper.h#L83-L107).

Normalize one approved still image upstream into a bounded derived RGB image (for example at most 512 × 512 = 786432 bytes); preserve original media and record original/derived identities and preprocessing version. Validate dimensions, exact byte count and digest before dispatch. Mount sealed RGB/projector artifacts with fixed guest paths; never allow arbitrary host paths. The adapter should format the pinned model template, count text plus image tokens/positions and reserve generation space before evaluation, set `use_gpu=false` and admitted threads, sample with the existing finite schema, and emit one bounded proposal body on stdout. Release every bitmap/chunk/sampler/context on error; parent tree retirement remains the fallback for hung native calls. Compressed helpers accept more formats and can invoke ffmpeg for WebP/video, making raw RGB preferable for a closed still-image path. [Compressed helper behavior](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd-helper.h#L56-L81).

## Resource and confinement implications

The text/vision pair is only a file-size floor. Current bwrap `--ro-bind-data` copies immutable bytes into the private mount; include projector and pixel copies in child RAM and parent capture/admission accounting, plus runtime, KV cache and vision graphs. Estimated F16 text KV for full 2048 tokens is `30 × 2048 × 2 × 3 × 64 × 2 = 47185920` bytes (45 MiB); this is config arithmetic, not measured RSS. A 2-GiB trial ceiling may be reasonable to test but is unproven; do not derive CPU latency or graph peaks from the publisher's GPU-memory claim. [Publisher config](https://huggingface.co/HuggingFaceTB/SmolVLM-256M-Instruct/blob/7e3e67edbbed1bf9888184d9df282b700a323964/config.json).

Bound decoded pixels independently from compressed length. Count actual image chunks before inference; image-token controls apply only to dynamic-resolution models, and `batch_max_tokens` is explicitly not a hard bound on the first image. Preserve whole-worker deadline, bounded output, admitted CPU threads, cancellation and cgroup peak accounting. [Limits contract](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/mtmd/mtmd.h#L107-L124).

`llama-server` accepts pixel-bearing base64 image content and schema-constrained responses. It is a technically viable alternate API, but a host TCP client cannot reach a listener isolated by existing `--unshare-all`. This pin supports UNIX socket paths via `--host ...sock`: a server and client inside the same one-shot worker namespace could communicate in private `/tmp`, with startup/readiness, bounded HTTP envelopes and both processes owned by the same cgroup. That is more lifecycle work than the direct library/CLI route; never expose a host listener or enable remote image URLs to solve it. [Server image API/schema](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/server/README.md#L1344-L1363), [UNIX socket option](https://github.com/ggml-org/llama.cpp/blob/b86d2f07542b29ab099aed34fd6b6d1b2fd4b81c/tools/server/README.md#L192).

## What can be implemented now and what needs assets/evidence

Now: add an explicit semantic-image capability/profile and projector/pixel identities; immutable capture/mount/custody accounting; request/report binding to original/derived pixels and preprocessing; a dedicated CLI adapter or small C++ mtmd executable; strict output/semantic validation; deadline/cancellation/error paths; deterministic protocol and negative-case fixtures. Keep text and image capabilities distinct and refuse image inference when assets are absent. None of these mechanical checks proves learned semantics.

New assets required: CPU mtmd-capable executable or statically linked adapter, compatible text GGUF, paired mmproj, processor/template/conversion identities, complete model/runtime licenses and third-party notices, and eventual hash declarations/installation updates. Existing text completion assets cannot perform this route. Acquisition/build and any native experiment require their own explicitly scoped work and receipts; this note supplies metadata only.

Required evaluation after acquisition: same prompt with contrasting pixel inputs and image-free/shuffled-image controls; measure learned-image dependency and semantic correctness against owner-defined examples, not merely differing strings. A still image supports suggested visual themes, not measured temporal motion/frequency. Then measure cold start, prompt/image encoding, total latency, peak cgroup RAM, malformed pixel/projector rejection, token exhaustion, cancellation and sterile offline installation. Failure should yield no proposal; model content cannot change allowed axes, range ceilings or approval authority. Qualification remains open until those checks and task thresholds are satisfied.
