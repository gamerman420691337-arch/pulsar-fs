# ADR B4-006: Explicit source-clock artifact mapping

Status: explicit engine-owned source-time publication, retained timing proof and native forward/reverse publication correspondence implemented locally; recovery/portable/environment and broader qualification remain open.

## Decision

Source-time export maps an explicitly selected current motion track through the originating immutable placement. It creates derived values without changing the project master. Source order can differ from project order: reverse placements reorder current values by source time, retaining positions, evidence labels, axis and track name.

Exact generation sample clocks take precedence over blindly inverting rounded project nanoseconds. When an action retains a generated sample's project timestamp, use that sample's original elapsed-source timestamp, retaining its source ordinal and exact quantization report. This is a clock association, not a claim that a subsequently edited position was observed in the media. Other authored timestamps use the declared inverse transform and carry no original frame claim.

The core `map_track_to_source_clock` validates placement/source correspondence, original timestamp minus origin, exact forward mapping, reported quantization, sample ordinal/time order, project order and unique nanosecond anchors. It bounds input/sample counts and refuses empty tracks, unresolved gaps, out-of-trim actions, arithmetic overflow and quantization merges. It never clips timestamps, drops colliding actions or resolves unknown coverage. Standard funscript millisecond quantization remains a separately checked export step.

## Authority and integration boundary

This pure kernel does not verify evidence custody, authenticate a caller or publish a file. Its caller must read the exact originating worker receipt under bounded admission, verify its stored artifact identity, and bind schema/project/job/attempt/source/base/configuration/placement to the selected generation. A merely well-formed sample plan is insufficient evidence.

The engine now loads the fixed attempt-relative `receipt.json` under bounded byte and sample admission. SHA-256 is computed over the same opened no-follow regular-file stream parsed by the typed reader, including trailing whitespace; trailing JSON is refused. The receipt must appear exactly once in the selected candidate's retained artifact lineage and bind schema 2, project, base revision, job, attempt, source, preset, canonical configuration hash/settings and full immutable placement. It additionally verifies the fixed attempt-relative original `program.json` against the receipt's raw program identity, parses it through the existing bounded motion reader and hashes its canonical serialization against the engine-owned originating candidate descriptor. Rebased generation candidates resolve their original bytes through bounded, recorded same-project/same-job rebase links; merged rebase motion is never substituted for the original generation artifact. Raw and canonical bytes may differ; equality is required at their declared boundaries rather than assumed across encodings. Both program and receipt bytes fit the original combined output budget. Irrelevant duplicated analysis arrays are streamed without constructing a whole JSON value. This verifies custody and binding; the core transform separately validates sample arithmetic. The publication path uses this check for both identity-clock placement and explicit source-time mapping. Ordinary nonidentity placement publication still refuses.

The `StashExportScript` request now has an explicit `source_time` flag, omitted when false to preserve legacy serialization. CLI `stash publish-script --source-time` and the desktop publication checkbox declare that intent. The engine requires a placed generation origin, verifies custody and current source derivation, maps only the selected stroke track, and uses the standard millisecond exporter with its collision/gap refusal. It retains current request/revision/owner/Export checks and descriptor-relative no-clobber publication without rewriting motion, protection or revision.

A bounded private content-addressed proof binds publication request, complete Stash capture, project/revision, selected/original candidate/job, verified receipt, original canonical program, current master, placement and final script identity to the exact per-action clock mappings. The proof descriptor is recorded with the `exports.pending` row in the same durable SQL transaction before publication. File dispatch failure remains `failed_or_unknown`; its proof reference remains retained. Successful responses carry a proof reference, and exact request replay returns the original result without another effect. The proof is unqualified and does not claim edited values are observations.

Database schema 4 makes retained timing proof references a reader boundary. Placement and proof-table migration is transactional; incomplete schema 4 refuses automatic repair without downgrading its version. The exact retained schema-3 reader must refuse this subject. Portable Stash source/proof association migration, explicit uncertain-publication disposition/adoption and durable observation history, broader negative-dispatch and environment-recovery evidence remain open.

## Local evidence

Core cases show that original fractional source timestamps survive instead of being reconstructed from rounded project time; reverse mapping preserves current values/evidence; newly authored times are explicitly mapped without frame claims; malformed sample clocks/order/ordinals, admission overflow, unresolved gaps, out-of-trim motion and lossy nanosecond merges refuse.

The native lossless RGB case decodes eight frames, generates a placed candidate at 3× project speed and restores all eight original source-frame times through the kernel. Naively inverting the rounded project time disagrees for a nonintegral sample. Positions/evidence agree and the original candidate artifact remains byte-identical. This exercises decode/generation/clock math, not authenticated Stash source-time publication, millisecond export, GUI usability, model quality, physical Handy behavior or release qualification.

Native receipt checks accept the unchanged generation receipt and reject missing/duplicated custody identity, altered byte length, schema/project/base/job/attempt/source/preset/configuration/placement/program meaning even with newly hashed altered bytes, trailing JSON, reduced byte/sample admission and a Unix final-file symlink. Restoring original receipt bytes restores acceptance; original candidate bytes remain unchanged. These cases do not establish source-time publication or durable transformed-artifact proof.

The native case also rejects changed originating candidate bytes and a mismatched canonical engine descriptor. A whitespace-formatted original candidate with separately rebound raw artifact/receipt identities is accepted only when its bounded decoded canonical motion still matches the retained engine descriptor. This exercises both identity boundaries without claiming raw byte equality across encodings.

The originating-candidate resolver checks each retained rebase edge and refuses cross-job/foreign candidates, cycles and traversal exhaustion. Current revision/source derivation remains a separate publication check.

The native compiled CLI/authenticated-engine test exercises forward and reverse 3× placements, ordinary-clock refusal, explicit source-time publication, exact original-frame millisecond times, source-order values, proof digest/context, immutable master/revision, successful replay and engine restart with no further Stash query. It uses a private mock Stash and synthetic media; installed Stash compatibility, physical playback, model accuracy and release qualification remain open.

Query-only publication inspection now separates stored dispatch state from fresh proof and descriptor-relative source/script observations. It requires current owner/Export authority before and after verification and binds the same session/project/request. A verified proof can recover planned source/script metadata for observation without manufacturing a successful publication receipt. See [publication observations](../../docs/PULSAR_STASH_PUBLICATION_OBSERVATIONS.md). Native synthetic unresolved-state checks do not reproduce lost acknowledgement; explicit adoption/disposition remains open.
