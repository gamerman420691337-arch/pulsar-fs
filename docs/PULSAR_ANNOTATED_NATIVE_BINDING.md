# Native annotated model binding

The native CPU adapter can now explicitly read and execute the separately exported annotated model ABI on already transformed RGB pairs. A shared protocol declaration owns the existing training view JSON shape and its validation; the native training planner consumes that type. The shared model contract matches the Python export metadata field for field. This does not yet connect annotated input views to public generation or profiles.

Before constructing the annotated CPU session, the streaming ONNX reader checks the model's fixed named float32 tensors, existing dependency/domain restrictions, exact versioned recipe and a valid training-intake SHA-256. Metadata entries, strings, field count and nesting are bounded; missing, duplicate, malformed and truncated bindings refuse. The model bytes are checked against their supplied artifact identity before and after session construction. The adapter exposes its validated recipe and intake identity for subsequent attempt/receipt integration.

The explicit adapter accepts `target_frame_pair [1,6,64,64]` and produces `script_position [1,1]`. Callers still own view application, resource admission, process confinement and lifetime. Public generation and the existing whole-frame constructor retain their `frame_pair` contract and refuse the annotated model. No profile fallback, activation or new GPU recipe is enabled by this checkpoint.

The retained authored fixture has 14 exact previous/current RGB pairs. Python CPU inference supplies expected positions and model/RGB/intake identities. The explicit native CPU check verifies those identities, recipe metadata and all 14 positions within 1e-6. A separate fresh-process native check confirms legacy-adapter rejection. The first harness incorrectly initialized ONNX twice in one process and hit the existing fresh-process guard; its failure is retained, and the corrected tests use separate fresh processes rather than weakening the guard. Model metadata unit coverage includes absent identities, duplicate properties and every truncated prefix; shared contract tests reject changed normalization/input names and unknown fields.

The [checkpoint](evidence/roadmap-2026-10-08/annotated-native-binding/checkpoint.json) records exact final tests, runtime identities, private authored-fixture identities and source archive/readback. These checks establish native model binding and authored CPU parity, not correct real target identification, learned quality, GPU/provider qualification or a complete generation workflow. Only authored regressions fit temporary models; no live/sterile data was decoded or fitted, existing weights and historical inputs remain unchanged, and no physical device was actuated.

Final gates: 1,063 serial workspace tests pass (59 ignored), 79 CUDA-feature worker tests pass (two explicit native fixture cases ignored by default and run separately), 31 reference Python tests pass with the newly built planner, and the default binary builds. All 276 architecture checks and 36 source guards pass. Four authored old/current planner cases produce identical JSON plans. The source archive/readback covers 379 records: 374 preceding records unchanged, four existing paths changed and one shared protocol module added. No Engine RPC, database, portable format or production inference routing changed in this checkpoint.
