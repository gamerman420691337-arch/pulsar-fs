# Capture admission receipts after Engine restart

An exact saved Start or Continue request can now return an inactive `EngineRestarted` report after the Engine boot changes. Previously the stale-boot check ran before request replay, making the existing restart-retirement branch unreachable. The fix moves that boot check after exact saved-receipt lookup, while keeping current authentication, grants and revision checks before historical observation. A new request using an old boot still refuses before admission.

Replay reconstructs historical admission metadata. It sets active false, retirement EngineRestarted, admitted pixel bytes zero and no current server elapsed clock. If inference was declared, it is Retired with no latest result. It does not restore pixels, a lease, registry entry, worker, GPU claim or device authority; it does not infer a final result from an unfinished admission receipt. A changed request fingerprint conflicts. Current revoked grants refuse. A fresh explicitly authorized Start with the new boot mints a new capture and source identity.

The authored restart regression covers original Start and explicit Continue receipts, actual Engine close/reopen, absent old runtime, rejected old intake, unknown old-boot refusal, changed-intent conflict, revision refusal, fresh admission and revoked-access refusal. The preceding refusal test now explicitly sends a new request ID with the old boot, preserving its admission boundary. The failing pre-fix run is retained alongside an initial private-field test compile error and an initial incorrect expected error for a changed request identity. Neither test correction changes the production boundary.

A new ignored native case runs an actual CUDA pair in an active capture before dropping the Engine. After reopening, it checks empty ownership/GPU/storage accounting, exact old request replay, refused old intake and Finish, and unknown old-boot refusal. It explicitly starts a fresh capture, runs three pairs, consumes Finish, verifies original bytes on schema22, performs ordinary offline generation, exercises the preceding schema21 reader barrier and reopens again. This is an in-process Engine close/reopen scenario, not SIGKILL, host crash or power-loss recovery.

Final local verification is retained in [the evidence checkpoint](evidence/roadmap-2026-10-07/live-cuda-restart/checkpoint.json): 1,031 workspace tests pass with 55 ignored cases; 549 CUDA Engine tests pass with 57 ignored cases; both explicit native scenarios and nine CPU application cases pass without skips. The default/CUDA builds, 265 structural checks, original-byte/receipt readback and typed historical-reader compatibility pass. The active native restart case takes 44.50 seconds across two separately leased captures and subsequent offline generation/reopen; that total is not a live latency measurement. The protocol and database layouts do not change. Verification uses an authored scalar graph. No private references, training or physical device are used.
