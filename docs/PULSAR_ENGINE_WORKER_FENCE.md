# Engine ownership for ordinary Linux workers

The engine owns a durable worker-fence lease. Ordinary generation, resumed jobs and preview pass that ownership into pre-spawn custody. Custody registers and synchronizes each cgroup before fork, retains the lease across the fork-to-exec interval, and clears the record only after child exit, group emptiness and durable replacement. Registration, spawn, cancellation and clear failures retain unresolved ownership through the reaper.

Before queued generation commits, the same transaction binds the lease's canonical UUID scope to the host-local database and raises its reader barrier to schema 17. Preview uses a fresh authorized transaction before launch. Dispatch requires the bound scope. The exact CUDA intent and accepted-evidence layouts also remain present, even when empty; their validators and writers preserve schema 17. Existing states without tracked launches keep their previous barrier. Portable format remains 9; the local ownership scope is not a portable project fact.

Startup reads the database and scope before writable SQLite/WAL initialization. Unknown schemas, missing/altered binding, noncanonical scope, a changed lease inode, missing bound files or a mismatched roster scope refuse. Bound state cannot silently initialize a fresh lease or scope. The lease excludes an overlapping owner; every recorded cgroup must match its identity and be empty before restart admission. Startup never signals a recorded process. Empty records are cleared durably. Automatic orphan-directory reclamation and exhaustive crash/recovery qualification remain open.

Cgroup signal and observation files are opened relative to the original held directory descriptor. Removing an empty group and creating a populated replacement at its old path cannot redirect an old owner's signal or population observation. Directory removal checks the current path's device/inode against the held owner. Pre-cancelled launches avoid dependency access, and cancellation/expiry is checked again after registration before spawn. Blocking host IO remains independently unqualified.

The [packet](evidence/roadmap-2026-10-01/engine-worker-fence/validation.json) retains exact commands, sources, executable identities and checks. Dedicated native cases cover restart refusal while an owned child remains alive, empty-roster recovery, and actual removed-directory replacement. A native CLI case opens a known schema-16 subject with the preceding reader, performs actual confined CPU synthesis, verifies the schema-17 scope and empty retirement roster, and checks old/corrupted startup with committed main/WAL hash preservation.

The current local gates pass: 928 default workspace Rust tests, 467 CUDA-feature engine tests, all 475 engine tests with ignored native cases explicitly enabled, 229 structural checks and 103 application tests without skips. The native engine cases overlap the workspace cases; these counts are separate executions, not a combined total. Default workspace and CUDA-feature gates still report 16 and 10 ignored cases respectively. Two earlier CLI startup attempts stopped before database/socket creation; a later unchanged run and the final campaign passed, without a demonstrated fix for those stalls. The first application campaign passed 102 of 103 cases; its remaining assertion expected a pre-ownership schema after CPU generation. The corrected assertion requires schema 17 and preserves both older-reader refusal checks; the focused case and full rerun pass.

This is ordinary-worker integration. Persistent live inference, encoded-source helpers, GPU/native-image/device custody and their complete restart lifetimes remain unfinished. Production CUDA admission stays disabled. These checks do not qualify models, real media, Handy, six axes, every platform, physical behavior, human acceptance or release.
