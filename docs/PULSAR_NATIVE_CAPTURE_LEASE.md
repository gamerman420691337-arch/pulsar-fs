# Native capture under an inherited live lease

The new private `capture_tracked_in_lease` entry point preserves the caller's absolute lease end through existing tracked capture. An expired or cancelled lease refuses before database/staging access. Preparation, the monitored copy loop and successful retirement use the earlier of that end and the existing local budget. Admission still requires the actual committed format-4 worker fence and schema-20 database binding. Ordinary tracked capture retains its existing behavior.

An actual confined idle-worker case consumes one second of a two-second lease before capture starts. The worker publishes a readiness marker, then sleeps without returning a capture reply. The observer confirms the child is running with RAM/storage claims held. Capture returns about one second after starting, at the original deadline, and the test then confirms full RAM/storage, process-group, staged-directory and creation/fence cleanup. The separate original real-worker capture test verifies successful authored-byte capture and image/storage/lease retention, blocked-deletion custody, failed capture and restart. Both native cases pass against the rebuilt parent and current worker configuration. Three focused capture checks also pass.

The [evidence packet](evidence/roadmap-2026-10-07/live-cuda-capture-lease/) retains before/final source archives, native logs, exact gate executable identities and serial regression results. An initial source archive contains an idle-fixture output budget missing its declared-input allowance; inspection corrected it before native execution. No failed native result is attributed to that fixture.

Final gates pass 996 workspace tests serially (54 ignored), 525 CUDA engine tests serially (52 ignored), both explicit native Engine capture cases, four CPU live application cases, five shipped CPU regressions, the default build and 259 structural checks. The nine application cases have no skips. All 346 final archived/live source records match. The native idle capture elapsed 1.000884682 seconds after the prior one-second delay in its original two-second lease; this is the authored local controller case, not product latency qualification.

These are cooperative deadline checks and authored byte/idle mechanisms. They do not prove preemption of arbitrary blocked filesystem/SQLite calls, public Engine GPU live activation, GPU computation, real-media/model quality, six-axis behavior, measured end-to-end capture latency or physical Handy/platform/human acceptance. The prior parallel fence failures and traced live-fixture failure remain unresolved. See [ADR B3-057](../research/phase-b/ADR-B3-057-native-capture-inherited-lease.md).
