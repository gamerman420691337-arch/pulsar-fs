# Cgroup configuration through held directory identity

Status: native defect reproduced and fixed. Terminal current-source gates pass 965 workspace tests (30 ignored), 503 CUDA-feature tests (24 ignored), all three explicitly enabled cgroup cases, seven native worker-retirement cases, four live-worker application cases, three engine crash cases, one portable CLI case, builds and 236 structural checks. Application cases have no skips. All 317 archived/live source records match. Receipts are in the [evidence packet](evidence/roadmap-2026-10-07/cgroup-configuration/checkpoint.json).

Worker creation opened a cgroup directory but configured memory, swap, process-count and CPU limits by pathname. It also opened the process-placement handle by pathname. A native fixture removes its own empty original cgroup, retains the original directory FD, creates a replacement at the same pathname, then invokes the extracted production configuration operation. The preceding operation succeeds against the replacement; the required refusal fails. The exact source and failing log are retained as before-cgroup.rs.txt and before.log.

Limit writes and the process-placement handle now use openat against the held directory with NOFOLLOW, CLOEXEC and NONBLOCK. A removed original refuses configuration and placement; the replacement keeps its original memory and CPU limits. Failed setup cleanup validates the recorded device/inode and empty population before removing the directory. A replaced or populated group is not deleted by that cleanup. The native regression also checks replacement preservation during cleanup. A second native case uses a kernel-rejected zero CPU quota to exercise failed setup and confirms removal of its own empty group. The earlier held-directory signal/observation test remains a separate regression.

This changes no ledger, database or portable format. It does not close the interval between mkdir and registration, the interval before the directory FD is captured, or failed cleanup custody. Durable creation intent is still required before mkdir, with a reader barrier before production admission, conservative recovery of ambiguous creation, capacity retention across failed acknowledgements, and actual process-kill cuts at each transition. No shared delegated-root sweep is authorized by a directory name alone. Native capture ownership, historical staging recovery, host I/O, supported platforms, models, real media, physical Handy operation and human/release acceptance remain open.
