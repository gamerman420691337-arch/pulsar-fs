# Pinned detector numerical comparison

Pulsar now has a reusable, opt-in numerical campaign for the official YOLO11n candidate. Production preprocessing is factored into one checked function used by the detector and campaign: bounded RGB source bytes, integer-floor nearest stretch, NCHW channel planes and float32 division by 255. The extracted function rejects malformed source buffers and unsupported tensor contracts before allocation. Ordinary model generation uses configurable analysis dimensions; the separate 64x64 path belongs to the temporal model.

The campaign uses the publisher's ordinary bus example at pinned source commit `69c95d1add13a232382e53b3aa5094ec0c7738db`, image SHA-256 `c02019c4979c191eb739ddd944445ef408dad5679acab6fd520ef9d434bfbc63`. Torch 2.11.0 with Ultralytics 8.4.175 produces a fused FP32 reference from the exact same nearest-stretched RGB tensor. The Rust campaign verifies the previously pinned model/runtime bytes and checks all 705,600 raw output values, then compares detections. A separate Python verifier compares Pulsar's detections with the publisher's own NMS, after clipping and normalization. This exercises nonempty observations rather than only absence.

On this one non-square image, input tensors were bit-identical. Maximum raw coordinate error was `0.0016326904296875` model pixels; maximum raw class-score error was `0.000008434057235717773`. All five selected detections matched classes/order. Against publisher NMS, maximum normalized box error was `0.00000010728836064011205` and maximum score error was `0.000000476837158203125`. The chosen raw tolerances are 0.03 model pixels and 0.0001 score; decoded tolerances are 0.0001 normalized coordinates and score. These thresholds are declared comparison tolerances, not measurements of motion or model accuracy. Seven deliberate class/box/nonfinite/short/empty/authority/input substitutions were refused by the comparison verifier.

The retained fixture, publisher result and comparison live under `/home/brianklam/Projects/Funscripts/assets/pulsar-detector-parity-2026-10-11`. The source producer and checker are `scripts/prepare-detector-parity.py` and `scripts/check-detector-parity.py`; the ignored Engine test requires `PULSAR_DETECTOR_PARITY_FIXTURE` and explicit execution. Model/runtime identities are pinned in the test. All native executions in this campaign run offline in a private read-only namespace with a process timeout. The isolated Python environment is temporary; global packages were not changed. No owner/session credentials were retained.

This is not parity with the default publisher predictor: that predictor uses letterbox/padding, while this campaign deliberately compares the same Pulsar stretch tensor. One ordinary COCO image is not a target-specific quality dataset, annotation manifest, script timing check, throughput benchmark, device qualification or release approval. The latest AppImage keeps its earlier package subject; this campaign does not replace its package/process evidence. No default pack, preset, selection, execution approval or release qualification was promoted.

The full Engine regression initially passed 788 tests, with zero failures and 60 ignored; the opt-in native comparison passed separately. Clippy initially refused a constant-size `chunks_exact(4)` in the new test parser; it was changed to `as_chunks::<4>()` before final checks. Final subjects, rechecks and cleanup are recorded in [the checkpoint](evidence/roadmap-2026-10-11/detector-parity/checkpoint.json).
