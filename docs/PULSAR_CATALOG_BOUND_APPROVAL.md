# Catalog-bound owner approval for future pack admission

Status: Linux engine/CLI implemented; [source-bound local checks passed](evidence/roadmap-2026-10-01/catalog-bound-approval/validation.json). This is an explicit host-owner approval for unqualified use under exact accepted offline catalog facts, not official publisher identity, rights, compatibility or quality qualification.

```sh
pulsar model pack-catalog-select BOOTSTRAP_SHA256 MANIFEST_SHA256 --expected-catalog-revision CATALOG_REVISION --expected-selection-revision SELECTION_REVISION --approve-unqualified-native-execution --request-id RETAINED_ID
```

The operation uses fresh paired-session and separate model-pack owner authority. It verifies the [installed catalog association](PULSAR_INSTALLED_CATALOG_ASSOCIATION.md), engine-pinned CPU runtime/profile contract and exact optimistic selection revision. Before the SQLite transaction publishes approval it rechecks the exact catalog revision, signed manifest membership, all-role expiry and accepted clock floor. Approval and replay receipt commit together. Exact replay returns historical approval without renewing a changed or expired catalog.

A version-2 selection report retains `catalog_binding` with the bootstrap namespace and catalog revision. Its manifest and selection revision remain in the ordinary `ModelPackChoice`. Future generation preparation and job admission, preview admission/completion and selection-bound Stash admission recheck that binding. Any catalog revision change requires explicit reapproval, even when the same manifest remains listed. Missing, corrupt, expired, rolled-back or changed catalog state refuses. No failed check silently falls back to a direct model or an unbound approval.

Metadata is offline: no online revocation freshness follows. Catalog refresh does not delete or automatically rewrite selection. Status remains recorded historical approval, so `native_execution_approved` describes the stored owner action, not proof that a future job can be admitted now. Already accepted generation jobs retain their captured inputs/approval. [Explicit approval withdrawal](PULSAR_MODEL_PACK_WITHDRAWAL.md) now cancels matching unfinished generation; automatic catalog-triggered cancellation remains separate required work. Preview completion is rechecked. Explicit ordinary unqualified owner selection can replace the binding; ordinary deactivation clears it. Both require the existing fresh owner authority and optimistic selection revision.

First catalog-bound approval raises the database reader barrier to schema 14 in the same transaction. Older engines must refuse before writable SQLite startup. Subsequent deactivation, ordinary selection, restart placement/interval recovery, Stash batch writes and portable import/export must preserve the higher barrier. Unbound selection retains version-1 report serialization without the new optional field, preserving existing request/receipt identities. Portable format 9 is unchanged: approval dependencies remain historical bytes, never imported host-owner authority. The bounded selection reader refuses reports over 1 MiB before allocating a Rust string.

[Desktop catalog controls and persistent recovery](PULSAR_DESKTOP_CATALOGS.md) are now implemented with headless/native-helper checks; native-window/human usability, online/current publisher authority, automatic catalog-triggered and live/Preview/native-preparation cancellation, rollback/update/removal transactions, retention management and platform/power-loss/real-media/model/Handy/human/release qualification remain open. Sterile references remain evaluation-only; no private training or evaluation is implied by these software checks.
