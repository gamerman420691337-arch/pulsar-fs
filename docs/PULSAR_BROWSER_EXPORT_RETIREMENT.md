# Confirmed browser export retirement and retained history

After a successful original script download, inspect its export intent again. Check
**Retire the confirmed export intent, preserving its files and history**, then press
**Retire confirmed export intent**. Retirement binds the exact original request,
revision and confirmed native-byte digest. It refuses missing acknowledgement,
unconfirmed publication/readout or changed files. It clears only the active local
pointer and retains a compact historical reference. It does not delete any script,
side journal, project, source or Engine receipt.

The same project can then inspect its committed master and explicitly prepare a
fresh export request. Repeating an old retirement returns its original receipt
without retiring a newer active request. **Refresh retained export history** lists
up to 64 records. **Download selected retained export** validates the pinned parent,
private side journal and confirmed bytes before replaying the original request
through current authenticated Engine authority. It does not replace the new active
intent or automatically republish missing/changed files.

The new format-2 catalog accepts earlier single-export/null journals without
inventing new identity. Migration is written only during a real metadata transition;
corrupt/foreign/duplicate records refuse with original bytes preserved. Historical
records omit motion samples/projections; those remain in their original private
side journals. Private journal byte/entry limits remain enforced, and full history
refuses retirement without losing the active intent. Files remain retained;
managed file reclamation, older unbound orphan reconciliation and broader crash/
platform qualification remain required. All outputs are unqualified motion.
