# CPU generation progress recovery

2026-10-12. Scoped CPU generation recovery PASS; full roadmap PARTIAL.

Finite CPU visual generation uses a private bounded progress stream between the Worker and Engine. The public WorkerRequest and final artifact framing remain unchanged. The Engine publishes a checkpoint body only after exact length and SHA-256 checks, then publishes its metadata and syncs the directory. An incomplete later body does not replace the previous completed boundary. Each attempt emits at most 128 updates; each body is bounded by the existing output byte limit. Checkpoint storage has a separate reservation and final output retains its original aggregate limit. If serialization or update count reaches the checkpoint budget, generation continues and the receipt records that checkpoint updates stopped.

Recovery captures the last completed body into the new attempt before launch. Its private boundary binds the original record and body identity to the same complete input/configuration basis, excluding only attempt ID and output directory. Changed media, tools, model, configuration, project, revision, job or resource budget refuses reuse. The initial immutable WorkerRequest checkpoint is still retained separately.

Worker state includes completed sample lineage, actions, gaps, review spans, project time, position, pixel support and the checked tracker snapshot. Tracker identities are rebound to the new attempt namespace. Floating computation and lineage values use exact bit representations. Restore validates source ordinals, original PTS, sample lattice, placement, frame context, tracker configuration, seed, view dimensions and pixel support. The decoder starts from the original source, validates and discards the retained prefix, and compares its final support frame before performing fresh analysis. This saves completed inference and image-flow computation; it does not implement codec seeking or retain an executable model/session.

The final receipt records captured origin/body identity, retained analysis count, discarded decoder prefix count, update count and checkpoint budget stops. Progress state confers no device, execution or edit authority. Master motion is unchanged until an existing authorized edit operation applies a candidate.

The owned native CPU-quota handoff passes in 185.25 seconds. It waits for 32 completed analysed frames before requesting the pinned learned assistant. The original attempt becomes `assistant_paused`; assistant completion resumes the same job automatically without AssistantStatus/List or manual ResumeJob. The resumed attempt reuses all 32 frames and performs 928 successful model runs versus 960 for a fresh uninterrupted attempt. Neutral motion, review spans and complete sample lineage match exactly after normalizing the deliberately fresh attempt identity namespace. The proposed sample-stride change is not applied, and master motion/revision remain unchanged. The authored source is 32 seconds at 30 fps, 64x64; the declared detector input is 640x640. This is computation-reuse evidence, not a speed benchmark or target-quality acceptance.
