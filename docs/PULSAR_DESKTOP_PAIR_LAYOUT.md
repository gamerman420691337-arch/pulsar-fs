# Desktop target-pair layout and native workflow

Status: PASS for the authored Linux window workflow below. Human usability and broader product/platform qualification remain open.

The actual desktop reproduced a layout defect in the preceding executable: its main image consumed almost the complete preview area, leaving the 128-pixel previous-target thumbnail clipped below metadata and behind the timeline. The repaired canvas draws previous and current targets side by side, preserves each aspect ratio, and maps current-frame coordinate overlays to the current image. A bounded scroll area retains frame clocks, target estimate and exact model/profile/runtime identities without pushing either image below the canvas.

The isolated KWin virtual/Xwayland campaign created a project, reopened it after Engine/GUI restart, imported an authored stereo video, opened the Stash controls, and loaded the annotated file model, CPU profile and source-bound target declaration through actual controls. At the first original source sample the window explicitly shows no supported pair estimate. At elapsed 0.125 seconds it shows previous frame 0 and current frame 1, original PTS 2.0/2.125 seconds and position 0.497901, the six-decimal rounding of independent fixture expectation 0.49790114164352417. Both targets remain visible at 1280 × 820 and the minimum 760 × 540 window size; scrolling metadata reaches all three complete identities. Clearing the target view clears stale textures; loading it again restores the pair.

The previous XTest/direct-event attempts did not deliver working window interactions. The older KDE [fake-input protocol](https://invent.kde.org/plasma/plasma-wayland-protocols/-/blob/master/src/protocols/fake-input.xml) was investigated but its global was absent; it was not the successful input path. All sockets, DBus, config/cache/data directories and Engine state belong to the throwaway display. No host display, user Stash or physical device was contacted. Final read-only state has one project, one source, zero jobs and project revision zero. Verified private GUI/Engine processes and the compositor are terminal. Credentials and raw databases remain excluded from the public evidence packet.
