# Desktop catalog controls and persistent recovery

Status: desktop integration implemented; [source-bound local checks passed](evidence/roadmap-2026-10-01/desktop-catalog/validation.json). Native-window and human usability qualification remain open.

The existing Offline model packs panel now includes Offline publisher catalogs. Supply the captured catalog directory, independently approved public bootstrap file/digest and exact expected revision (0 for first intake). An explicit bootstrap checkbox gates acceptance. Recorded catalog status is historical acceptance; installed association is a separate point-in-time asset/signature/expiry check. Explicit unqualified execution approval and refreshed owner selection gate catalog-bound selection. The current recorded choice shows its catalog namespace/revision when bound.

Catalog refresh and catalog-bound selection use the existing authenticated desktop runner with the separate model-pack owner capability. Exact request ID, source/bootstrap locators, digest and revision are captured before dispatch. Approval booleans are represented by the explicit captured intent, never reconstructed from a supplier response. Changing the bootstrap locator or namespace resets the relevant approvals; changed bootstrap file bytes refuse through exact engine digest checking. Namespace edits clear catalog/association caches, and manifest edits clear the old association. Late replies are rejected if their input fields changed. Busy catalog inputs are disabled. Engine [catalog intake](PULSAR_OFFLINE_CATALOG_INTAKE.md), [installed association](PULSAR_INSTALLED_CATALOG_ASSOCIATION.md) and [future admission fences](PULSAR_CATALOG_BOUND_APPROVAL.md) remain authoritative.

Refresh receipts are retained as history and trigger a separate catalog status query. They cannot populate current selection or grant generation authority. Catalog-bound selection receipts follow the existing separate owner-status query. Namespace/revision/manifest response checks reject substitutions. Read-only catalog status/association preserve the recorded selection, while mutations clear it. Restored recovery history never becomes a current generation choice.

The shared [session-bound private recovery journal](PULSAR_DESKTOP_PACK_RECOVERY.md) now captures both catalog mutations. Before storing a new catalog intent it atomically raises its client-only schema to 2, retaining old entries and the original session/credential/owner bindings. Schema 1 remains readable when it has no new catalog intent. Older readers refuse schema-2/unknown intent rather than discarding history. The barrier remains after acknowledged dismissal. Exact replay uses the retained original request/intent and fresh current capability; changed ownership/bearer binding or intent refuses. Historical replay does not renew catalog expiry or overwrite newer catalog/selection state.

No bearer or owner capability bytes are stored; only their binding digests are retained. Private ownership, no-follow/single-link checks, nonblocking lock, atomic sync/rename, 64-entry/1-MiB limits and acknowledged-only dismissal continue unchanged. Unknown outcomes, corrupted/unsafe state and full journals refuse before new dispatch; no silent retirement or orphan cleanup is added. Database schema 14 and portable format 9 are unchanged by this desktop increment.

Headless egui controls and an authored native helper share the production runner. They establish local UI/receipt/recovery behavior, not a native-window walkthrough or human acceptance. Non-Unix recovery, active update/rollback/removal, in-flight generation cancellation, official publisher/rights/compatibility/model/media/Handy/platform/release qualification remain open. Private training and sterile evaluation are unchanged.
