# Applying an assistant proposal to generation

An explicit approved generation request now applies a completed local assistant's sample-stride proposal to an existing imported media source. It creates an ordinary generation job and candidate. It does not commit the candidate, alter master motion, change protection, rerun assistant inference or operate a device.

The CLI is `pulsar assistant generate PROJECT ATTEMPT --source SOURCE --revision REVISION --request-id REQUEST --approve-generation`, with optional `--preset`, `--settings PATH` and `--model PATH`. Review the completed stride proposal and choose the source/options before approving. Inference approval on the earlier assistant Start does not approve this generation. Supply the same original request ID and exact source/options on retry; a changed declaration conflicts. Settings files use the existing bounded reader. First-party saved generation approval and desktop controls are implemented in a separate [intent and job-handoff increment](PULSAR_ASSISTANT_GENERATION_INTENTS.md); qualification remains open.

## Dispatch and authority

`GenerateWithAssistant` carries an explicit source, preset, complete settings, optional model path and approval bound to the attempt/context/proposal digests. The Engine requires current Read, Edit and Generate authority, plus ImportSource for an explicit model path. The proposal must be Completed, owned by the authenticated project/session, from this Engine lifetime and captured at the current project revision. The approval hashes must match the retained report and current Engine facts. NoAction and unrelated proposal types cannot be applied as a stride change.

The Engine derives a normal Generate command in memory, replacing only source_sample_stride from the retained validated proposal. The original approval request remains the durable identity/fingerprint/receipt subject. Source/model/view/CUDA capture and shared memory/storage/admission use the existing generation path. Authority, revision and approval context are rechecked under the transaction that publishes the job and receipt. Exact replay returns the original job without launching another worker. Failed publication rolls back request identity. Candidate review/commit/merge/protected history/undo use existing separate commands; assistant approval bypasses none of them.

Current context now also offers bounded recorded master reviews through [review evidence selection](PULSAR_ASSISTANT_REVIEW_EXPLANATIONS.md). [Target context/application](PULSAR_ASSISTANT_TARGET_APPLICATION.md) is now implemented with retained checked references and separate approval. Native learned target execution, learned review-selection qualification and undoable assistant edit recipes remain required by EDIT-01/TEST-23. Checkpoint/assistant/resume, private cancellation/approval-intent lifecycle, model/default/offline packaging and platform/media/Handy/human qualification remain open. This increment is not full assistant or roadmap completion.
