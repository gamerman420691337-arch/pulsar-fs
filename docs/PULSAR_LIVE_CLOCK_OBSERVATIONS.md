# Local monotonic capture-clock observations

The authenticated bulk handshake now measures a process-local send/receive interval around the engine's fresh lease-relative clock sample. The client retains a private observation handle bound to that connection, engine boot and complete capture identity. Its archivable facts disclose the interval and an explicit `local_monotonic_equal_rate` assumption. These are local IPC timing observations, not camera exposure timestamps, device/player rate calibration, synchronization qualification or dispatch authority.

For a server sample `S` taken while the producer request spans `A..B`, a later producer acquisition event `C` maps to the interval `S+C-B .. S+C-A`, assuming equal-rate local monotonic clocks. The interval width is the complete round trip, including request transport, server scheduling and response transport. Pulsar uses the earliest possible capture tick for age accounting; a midpoint or latest tick could make old input look younger. The mapping retains source PTS unchanged. It neither subtracts decoder delay nor treats upload time as acquisition time.

The checked core kernel rejects reversed probes, uncertainty above the admitted bound, pre-probe events, overflow and intervals that reach lease expiry. Maximum uncertainty is one second and the absolute lease remains at most thirty seconds. The process-local handle additionally refuses future acquisition events and fixed-size pixel violations. Only the actual authenticated handshake constructs it; serialized facts cannot recreate it. The runtime source event still comes from the caller and is not verified hardware provenance.

The client offers `LiveBulkClient::clock_observation()` and `upload_captured(frame, source_time, captured_instant, pixels)`. The upload helper hashes exactly one packed 64x64 RGB frame, retains the clock bracket and source timestamp in its returned stamp, and sends the conservative earliest capture tick through the existing frame channel. The engine still treats the producer's capture provenance as declared, independently rechecks authority and age, and does not adopt the client stamp as an engine attestation. Ambiguous remote/I/O exchanges poison observation use with the channel. A handshake slower than the uncertainty bound leaves the existing declared-tick interface available but exposes no usable observation; there is no automatic narrowing, clock refresh, replay or fallback to a fabricated measurement.

The shipped read-only probe command is:

```sh
pulsar live-capture clock PROJECT_ID REVISION CAPTURE_EPOCH
```

It queries the current lease, opens its authenticated bulk channel and prints that channel's measured clock facts. Closing the command closes the channel; the JSON does not grant a future uploader access to its private observation handle. Capture start/stop/revision/grants and inference authority are unchanged. No project database or portable-format migration is required.

Core tests enumerate every possible sample location in one authored interval and verify conservative age for those cases under the stated assumption. Native Unix transport tests measure an actual same-host event against a shared test clock, preserve signed rational source PTS through a captured upload, and verify poisoning. Strict CLI evidence crosses the real engine and shows boot/capture correspondence. These checks establish bounded local software correspondence only. Actual source acquisition, continuity/renewal, device clocks, player buffering, capture-to-command latency, model quality, GPU six-axis output, Handy and release qualification remain open. Training and sterile evaluation were not changed.

Native build and diff checks passed. Ninety-two capture CLI traces include the actual engine probe: its observed request interval was 189,106 ns, for that one run only. Eight new Rust regressions cover the interval kernel, private observation admission and native captured upload/poisoning. This is software correspondence evidence, not a statistical capture-to-command measurement or a platform/device qualification result.
