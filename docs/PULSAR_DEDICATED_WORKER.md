# Dedicated worker composition

Status: dedicated worker composition implemented; scoped verification PASS, full workspace tests/strict lint/global formatting FAIL. Full roadmap PARTIAL. Full roadmap remains incomplete.

Pulsar now builds two executables. `pulsar` composes the GUI/CLI and per-user engine. `pulsar-worker` accepts only existing engine-launched worker roles and bounded data input. It has no user command parser, GUI dependency or engine-server role. Their shared dispatcher preserves existing feature/platform refusals and argument checks. This keeps the four product libraries and adds one binary-only package.

The default workspace build produces both companions. Installation and release archives retain both. Owner startup selects `pulsar-worker` beside the actual executable, or an explicitly supplied absolute `PULSAR_WORKER_EXECUTABLE`; no PATH lookup or GUI fallback occurs. Explicit SDK/test `EngineConfig::new` image selection remains supported. A missing, empty or nonregular image fails before durable state initialization. Snapshot identity, custody, native dependency capture, confinement and disposal checks still apply at execution.

The preexisting WASM debug GUI image measured 150,880,258 bytes, above the 128 MiB native-image limit. This limit is preserved and shared by executable capture, editor availability and start admission. The current WASM companion measures 81,386,655 bytes and passes that limit; the current GUI image measures 150,863,020 bytes and exceeds it. The standalone package test build produces an 81,352,108-byte companion; the real confined transform/recovery tests use that image. Both build-context byte counts and hashes are retained, not inferred from the dependency graph. Matching optional features must be built for both executables. An explicit arbitrary override does not establish feature support or qualification.

The default and WASM all-target checks pass. Standalone process checks pass three tests in each build, image/config selection passes, launcher deadlines pass two tests, and the full WASM engine library suite passes 677 tests with 63 ignored. Real confined guest execution and fault retirement plus delayed-start resolution pass against the standalone companion. The worker package passes strict Clippy with `--no-deps`; including local dependencies fails on the retained 30 protocol library findings. That setup failure is retained. The short-prefix protocol rerun passes all five tests. Four failure states contain only early lock/fence files; three also contain a temporary worker snapshot. Metadata is retained and private state is removed. The socket-prefix failure and the startup failures are separate.
