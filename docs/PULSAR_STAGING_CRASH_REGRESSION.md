# Staging custody after owner death

Status: actual native primitive counterexample reproduced twice; production repair pending. This does not establish an engine/database crash gate or durable staging recovery.

The new ignored native regression re-executes its own Rust test binary as an owned child. That child opens a private worker-fence scope, creates authored staging bytes, reserves 4,096 storage bytes and a worker slot, and runs an actual `/bin/true` child in its owned delegated cgroup. Permission-denied staging deletion prevents successful retirement. After the worker exits and its cgroup is empty, cleanup continues retaining the storage claim and fence lease. Both child and parent confirm that a second bound opening refuses while this owner is alive.

The parent then sends SIGKILL only to its unreaped direct test child, reaps it and verifies the signal status. It independently reads the unchanged authored staged bytes before reopening the same bound fence. Restart succeeds despite those bytes still existing. The required refusal assertion fails, twice, with `restart admitted=true`. The existing failed-cleanup control passes when the owner survives and permissions are restored. This distinguishes process-local custody from durable recovery; it does not implicate the preceding in-process cleanup repair.

The evidence is retained under [staging-crash-recovery](evidence/roadmap-2026-10-01/staging-crash-recovery/before.json): initial compilation/execution, unchanged-binary repeat and cleanup control, binary identity, 182 production and 130 verification source records with archive readback, and 233 passing structural checks. The complete feature-suite result is recorded separately and must not conceal the deliberately failing explicit crash case. The regression remains ignored in ordinary suites because its production requirement is unresolved; running every ignored native case now intentionally exposes this failure.

The source explains the observed gap: the fence ledger persists cgroup identities, active/retired membership and the lease scope, but no staging obligation. After process death, the lease becomes available and empty recorded cgroups are reconciled. The asynchronous cleanup owner and its directory descriptors died with the process. Neither an empty cgroup nor the released process lease proves that staged bytes were deleted.

The next change must implement the [durable staging stage card](PULSAR_STAGING_JOURNAL_PLAN.md), including intent before creation, acknowledged identity before use, cleanup tombstones, reader/downgrade protection and bounded recovery. Extending only the current cleanup task would leave the reproduced failure intact. Complete engine integration, all creation/deletion cuts, unknown identities, lost acknowledgements, native-image ownership and portable correspondence remain required. No production GPU admission, physical actuation or model/media qualification changed.
