# Live CUDA preparation resource handoff

GPU preparation now releases its RAM and worker slot after the preparation thread has exited and been joined. The private `GpuPrepared` type records this transition before measured GPU observation/admission and persistent launch. Ordinary CPU preparation retains its worker admission for transfer into the CPU worker.

Snapshot storage is split into a storage-only reservation and retained by the staging owner. Durable creation retains both the shared CPU claim cell and storage before its first fallible operation; legacy staging retains the same owners. Taking the CPU claim for an ordinary worker or retiring it for GPU use does not release the snapshot storage. Cleanup retains the appropriate owners until deletion and, for durable staging, journal retirement are confirmed.

Receiving the producer's channel reply alone cannot establish thread exit. The caller observes completion under the original cancellation/deadline checks and joins only an already-finished thread. If the lease expires or is cancelled after receiving a reply while the producer is still alive, an independent retirement owner joins it and then drops the prepared bundle. Failure to start that retirement thread retains ownership until process exit. The producer also retains independent claims through its send/epilogue, including receiver loss. This is cooperative ownership; it does not preempt blocking host filesystem operations.

Three focused tests exercise successful handoff in both legacy and durable staging, exact snapshot storage/bytes, cleanup, and cancellation/deadline with a deliberately blocked post-reply producer. The blocked cases return while CPU/storage admission remains held, then release capacity after producer retirement. The blocking hook exists only in test builds.

The authored native Engine case holds a separate 1 MiB worker reservation throughout capture, preparation, observation, streaming and Finish. With the default two worker slots it completes three GPU exchanges, creates no offline job and retires all custody. Independent readback reconstructs the manifest and transcript, checks authored frame pixels/source clocks and numerical results, and verifies three model runs/nine CUDA computation events in the original trace. The held reservation demonstrates accounting capacity, not actual encoded-source decoding, control transport or measured scheduling latency.
