# Retained local batch publication handoffs

After `library-batch-prepare` and explicit `library-batch-advance` reach generation_ready, use an existing private 0700 directory for this batch's client publication journal. `library-batch-publication-prepare ID --publication-state DIRECTORY --steps N` retains up to 1..=100 private bundle stages and their exact six axis export request IDs without dispatching exports. `library-batch-publish ID --publication-state DIRECTORY --steps N` explicitly publishes at most N entries (default one), preparing a pending stage first if needed. Repeat the same command and state directory to continue. `library-batch-publication-status --publication-state DIRECTORY` checks current session authority and reads acknowledgement history without export or filesystem adoption.

The client owns this publication journal; the Engine owns retained generation, projects, imports, jobs, candidates and export acknowledgements. The journal captures the generation selection, credential digest (never the token), each prepared stage/project/revision/destination/request identity and held parent/stage device/inode identity, followed by the actual publisher acknowledgement. Every inner export still requires current Engine grants and exact current master revision. No model defaults, replacement jobs, new recovery export IDs or implicit rebase are selected.

The sequence is pending, preparing, prepared and published. Preparing is retained before local stage creation. Prepared is retained before any Engine export dispatch. Published is retained only after all exact Engine export acknowledgements, existing full master/file checks, no-replace directory rename and file/directory sync succeed. Completion is true only when every entry has its recorded publisher receipt. It is history of accepted effects, not fresh proof that destinations remain present or unchanged. The Engine batch's publication_completed remains false; it does not consume a client assertion as authoritative publication evidence. All qualified fields remain false.

A private, bounded one-MiB journal is protected by an exclusive nonblocking descriptor lock and atomic file replacement with sync. Named journal/root/lock identity and owned private single-link regular files are checked. Other sessions, damaged journals, replaced records and unsafe storage refuse without repair. Locks explicitly retire even if another process retained an inherited open-file description.

A prepared resume uses the captured stage and parent identities before any export and reuses the original export requests. A known rename conflict can retain all Engine acknowledgements and exact stage intent for a later explicit resume after the operator handles the conflict. Earlier published entries remain recorded and are skipped. Unknown Engine outcomes retain the existing publisher refusal. A lost preparation acknowledgement leaves preparing unresolved; no replacement stage is created. A lost local publish acknowledgement can leave prepared while its stage name is absent and its destination exists. Matching files do not become an acknowledgement: resume refuses instead of adopting them or submitting another intent. Recovery/disposition for these unresolved local acknowledgements is still an explicit future capability; preserve the journal and local paths.

Release of the Engine batch remains separate. Do not release its generation ledger while the publication workflow needs it for comparison; publication history remains readable with current session authority, but continuing publication requires the retained Engine batch. No automatic deletion of journals, stages, sources, snapshots or published outputs is provided. The subsequent [bounded scheduler](PULSAR_LOCAL_BATCH_SCHEDULER.md) connects generation and per-entry publication with schema-2 awaiting_generation history. General retention, partial cancellation, credential migration, continuous watching/intake and unknown-acknowledgement disposition remain open.

Implementation reuses the existing neutral publisher and adds a captured-stage preparation/resume interface rather than another export implementation. Linux/Android source branches support this flow; actual evidence is recorded separately. Other platform branches refuse before publication. There is no interactive GUI, neural quality, real-media, physical-device, physical power-loss or release qualification claim.
