Their logs remain in the [evidence packet](evidence/roadmap-2026-10-01/staging-cleanup-custody/before-capacity.log).

The shared cleanup owner moves transferred directory paths and resource custody into an independent task. It holds directory descriptors, checks inode/device correspondence before deletion, and requires the held directory's deletion to be confirmed before releasing retained resources. Failed deletion retries only the transferred owned roots. Starting and polling cleanup perform no filesystem calls. Failed task creation or task failure preserves unresolved ownership; these failure paths are not yet independently fault-injected.

Worker retirement starts cleanup only after child, transport-thread and cgroup retirement. It keeps the reservation and engine scope and does not clear the worker fence until cleanup is confirmed. Live preparation's late/lost replies use the same owner. Native capture installs custody before fallible group/command/spawn preparation, retains it through pre-spawn failures, and transfers image/staging/storage ownership into checked cleanup on explicit close or drop. Explicit native image close reports unconfirmed cleanup after its observation interval; the cleanup owner continues retaining and retrying afterward. No native library is loaded by cleanup.
