# Worker custody before registration and spawn

Ordinary Linux generation, resumed-job and preview launch now take ownership of the cgroup and admission reservation before spawning a process. A failed spawn drops through confirmed tree retirement instead of dropping an unobserved cgroup directly. The custody object allows only one spawn attempt.

The same private custody supports an optional durable worker fence. It retains the fence lease before registering the group and synchronizes registration before permitting spawn. A failed registration may have left an in-memory record even if replacement failed; pre-spawn custody therefore attempts explicit unspawned retirement. An absent record is permitted only on that unspawned path, with matching actual cgroup identity and observed emptiness. A spawned child requires observed exit as well as an empty matching group before durable retirement.

Durable clear must succeed before cgroup removal or resource release. A persistence or observation failure retains the cgroup, reservation and fence lease in the existing reaper. Clearing is recorded in custody, so later drop does not try to remove an already retired record. Failed reaper creation continues to retain ownership rather than dropping it.

Four explicitly run native cases use newly created owned cgroups: failed executable spawn clears the synchronized record before group removal; a pre-exec refusal after the forked child entered the group retires without publication; failed registration replacement retains lease/group/capacity until repair; and an exited empty tree retains those resources while durable clear is unavailable, then the reaper clears and releases them after repair. They do not signal any pre-existing or unrelated cgroup. Test reopening retries only bounded lease contention while a reaper finishes dropping its fields; production fence opening still refuses immediately.

The ordinary launcher still supplies no durable fence. Engine scope binding, startup integration and the older-reader database barrier remain required before production tracked launches. No production restart protection, engine-admitted CUDA execution or crash qualification is claimed. Database maximum schema remains 16 and portable format remains 9. Blocking host IO, GPU/native-image/device custody, portable CUDA evidence and model/media/Handy/platform/human/release gates remain open.

Exact source, binaries, commands and results belong to the [validation packet](evidence/roadmap-2026-10-01/worker-pre-spawn-custody/validation.json).
