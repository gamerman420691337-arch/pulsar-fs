# Project-time interval regeneration

Finite video generation accepts optional `GenerationSettings.project_interval`, a nonnegative, nonempty half-open range of original project nanoseconds. Legacy settings omit the field and keep whole-source behavior. For example, `"project_interval":{"start":1000000000,"end":6000000000}` selects [1 s, 6 s). Supply the usual complete settings to `pulsar regenerate PROJECT SOURCE_VERSION --revision REV --settings SETTINGS.json`; model-backed selection also requires the declared model/profile and `--model`.

The shared worker selects only original stride-aligned frames whose mapped project timestamps lie inside the range. It does not reset source ordinals, stride, source origin, placement mapping or timestamps. Immutable forward/reverse placements and selected stereo/spherical views retain their existing contracts. The decoder still traverses the sampled container to validate original pixel/PTS order; this is bounded interval perception, not a claim of random-access decoding or faster end-to-end execution.

Tracker and optical-flow context start fresh at the first selected source frame. Optional manual target seeds must lie inside actual selected support; absent or unsupported seeds cannot authorize a replacement target. Temporal/global recipes retain their existing honest synthesized/inferred/unavailable distinctions. Prefix/suffix interval coverage without a decoded sample is an explicit unavailable gap and review flag; empty selected support refuses. Receipts retain the interval plan, original ordinals, mapped clocks, source/project orders, analyzed and decoded sample counts, settings and dependencies.

Native candidate snapshots expose their interval from the retained, bounded, same-project job manifest. Rebase and restart retain it. Damaged, oversized or identity-inconsistent native metadata refuses rather than silently widening selection. Existing-project CLI regeneration merges the candidate through this exact range and preserves outside motion, protected interpolation stencils and absent axes. The engine requires an explicit contained range for retained native/imported interval merges and refuses whole-candidate replacement of an existing master. A fresh empty project can explicitly commit a candidate without destroying prior motion. Concurrent changes remain revision conflicts; no automatic rebase, protection removal or export occurs.

Compiled desktop controls expose interval generation. Applying all candidate axes uses the retained candidate interval, independent of later generation-form edits. Selected-axis merging defaults to that retained range or accepts an explicit contained subrange. Whole replacement of an existing master is disabled. Rendered human usability remains unmeasured.

Database version **9** is the current semantic compatibility barrier. It extends the preceding schema-8 native policy to independent imported restrictions. [Portable scope recovery](PULSAR_PORTABLE_INTERVAL_SCOPE.md) checks retained legacy origin/worker evidence, preserves original motion/history/protections/archives and publishes restrictions with the barrier. Missing required evidence refuses; imported jobs remain inert. Scoped packages require format 7 and older readers refuse unsupported subjects. Simpler packages retain their existing minimum format.

Evidence under `docs/evidence/roadmap-2026-10-01/generation-interval/` uses authored finite media and an authored two-box ONNX fixture. It checks target reselection on an interval, outside/protected/missing-axis preservation, whole/unscoped/widened replacement refusal, original lattice, unavailable boundaries, invalid seed refusal, metadata recovery and actual restart. Reverse placement and nonzero variable PTS/projected views have native decoder checks. The negative baseline is the retained preceding target-seed engine with newer CLI adapters; it rejects the unknown interval setting without starting an attempt or changing the master.

This implements a bounded native interval workflow, not full EDIT-03/B2/B6 closure. Interactive target reselection within a running attempt, assistant actions, richer scene selection/recovery, rendered usability, natural-media/model quality and Handy/platform/human/release qualification remain open. No training or sterile evaluation is performed by these authored fixtures.

The subsequent [portable scope repair](PULSAR_PORTABLE_INTERVAL_SCOPE.md) retains the two negative reproductions separately and verifies new clone/rebase/re-export application restrictions and legacy recovery. It does not close the broader roadmap.
