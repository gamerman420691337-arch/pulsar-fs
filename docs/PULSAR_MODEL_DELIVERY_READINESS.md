# Generation model delivery readiness

Current software update: [inert bundled pack delivery](PULSAR_BUNDLED_GENERATION_PACKS.md) now implements generation payload transport and has actual archive/cache/AppImage and confined-worker evidence. Bundled default discovery/admission, useful baseline models and edition qualification remain open. The inspection below describes the earlier fifteen-file candidate and its original source subjects.

The current runtime candidate does not deliver Core or Complete generation models. Its fifteen payloads supply the application/worker, media tools/source, assistant/runtime/model/licenses and CPU runtime/notices. The finite schema in `runtime_install.rs`, assembler and AppImage builder admits no generation-pack payload declaration. Independent offline model-pack import/selection exists, but is not a bundled first-use/default path. PKG-01, PKG-04 and PKG-05 remain incomplete for advertised generation functionality.

A bounded read of the existing `FunGen-12n-pov-1.1.0.onnx` cache file found a 10576223-byte model, SHA-256 `5dc012422463299e76a248b1bb92317365ded42aa2cb90615f04bffb9e62faf0`, with float input `images` shaped `[1,3,640,640]` and float output `output0` shaped `[1,14,8400]`. Ten class channels plus four box channels match the broad shape expected by Pulsar's YOLO channel-major adapter. This is only tensor metadata correspondence: it does not validate the complete graph, operators, preprocessing, label semantics, numerical execution, motion quality or pack compatibility.

The retained FunGen terms identify weights as covered content. The [publisher's currently observed terms](https://fungen.app/license/) also prohibit repackaging weights or making them usable outside FunGen. The local supplemental copy is version 1.3 dated 2026-08-18; the publisher page reports version 1.5 dated 2026-10-04. No additional permission was found in this inspection. Exclude this cached model from planned Pulsar bundles under those observed terms. No model execution, conversion, fitting, activation, copying or repackaging occurred. This finding does not change Pulsar's source license or decide the provenance of historical source revisions.

Next implementation must carry explicitly declared, integrity-bound generation assets through candidate assembly, archive installation/cache verification and first-use admission, retaining capability/preset/model identities and existing inference authority. It must deliver real eligible weights and support the required baseline input families, with selected defaults independent of optional packs. Merely adding a file list or shipping the assistant weights does not complete that requirement. Complete must actually include every advertised installed tier. Model selection still needs permitted candidates, runtime/preprocessing comparison and useful quality/performance evidence.

Live references remain permitted for training; sterile references remain evaluation-only. The user reports no existing annotations. These media permissions do not provide redistribution permission for third-party weights, and no target/view labels or checked alignment were invented.

The [checkpoint](evidence/roadmap-2026-10-11/model-delivery-readiness/checkpoint.json) records the inspected source, candidate, model and local-license identities. This turn establishes a delivery gap and excludes an unsuitable bundle candidate; it does not implement generation bundling, close model selection or qualify an edition. The existing 784 Engine/229 client/four packaged process results retain their own subjects and are not proof of model delivery.
