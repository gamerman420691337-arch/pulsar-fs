# Selected neutral-axis publication

An explicit selection of one through six distinct axes can be published from an exact committed project revision. `export-bundle PROJECT /absolute/new-directory --revision REVISION --axes stroke` exports only Stroke; `--axes stroke,yaw` exports those two tracks. Omitting `--axes` retains the existing six-axis default. The desktop neutral export panel captures checked axis selections with the project, revision and destination, using the shared background publisher and stop controls.

Every selected master track must exist, contain actions and have no unresolved gaps. Selection does not infer other physical axes, generate replacement motion or adapt a device. All selected tracks and existing stage members are checked before the first export request. Publication still rechecks the exact revision/master and compares each strict Funscript against its committed track before the no-replace directory rename.

Full six-axis stages retain schema 1, including compatibility with previously captured request order. Smaller selections use schema 2 with explicit named axes and original per-axis request identities. Older clients refuse schema 2. New preparation canonicalizes axis order; recovery retains the original identities. Empty or duplicate selections refuse before staging. Unexpected files, changed intent, source revision drift, missing tracks, changed member bytes and unknown Engine outcomes refuse. A failure can retain a private stage for inspection and exact resume; it must not be treated as successful publication.

`export-bundle-inspect /absolute/original-stage` is read-only. `export-bundle-resume /absolute/original-stage` uses that stage's original selection and request IDs, irrespective of current desktop checkbox settings. A successful receipt names only the selected axes and remains `qualified: false`. Existing retained audio library publication continues requiring its six-axis schema-1 recipe contract; selected-axis publication does not complete the retained visual/model batch ledger.

Verification receipts are in [the evidence packet](evidence/roadmap-2026-10-12/selected-axis-publication/checkpoint.json). Headless desktop click tests establish captured-action behavior, not rendered GUI acceptance. Deterministic audio fixtures establish publication and recovery semantics, not useful model/media motion or physical-device qualification.
