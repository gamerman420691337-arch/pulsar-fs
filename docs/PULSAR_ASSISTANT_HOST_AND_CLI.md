## Host configuration

`PULSAR_ASSISTANT_OWNER_POLICY` selects one explicitly approved startup profile. It is read by the host Engine only. The path must be absolute; policy bytes must be a current-user, private, single-link regular file of at most 16 KiB. Symlinks, unsafe metadata, changed capture metadata, unknown fields, unsupported version and absent approval refuse. Linux confinement is required. Absence preserves an empty assistant catalog.

The strict policy fields are schema_version (1), approve_inference (true for an owner-authorized run), worker_sha256, worker_bytes, runtime_path, runtime, model_path, model, cpu_threads, wall_time_ms and worker_memory_bytes. Runtime/model are existing ArtifactIdentity objects (artifact_id, sha256, byte_len); paths must be absolute. Executable/model metadata and owner aggregate RAM/deadline feasibility are checked before Engine state creation. The exact captured worker SHA/length must match before token/database initialization. Asset content hashes are independently checked during sealed execution; startup metadata is not model qualification. A valid policy registers a new lifetime profile before listener publication.

Set the policy environment variable before starting an owner-controlled Engine. Existing engines are reused; the launcher does not replace them or silently update profiles. Policy edits do not retroactively revoke a captured registration. Trusted profile withdrawal or an owner-managed restart is required. No user service, live state or encrypted secret store was changed in this increment. Model/runtime/worker pins must be deliberately updated after an owner-approved binary change. Bundled first-launch packs, platform policies and public setup controls remain open.

## First-party commands

`pulsar assistant profiles PROJECT` displays current declarations. `prepare PROJECT --profile ID --revision N --prompt TEXT --request-id ORIGINAL --output /absolute/private-intent.json` writes a bounded private intent before inference. It obtains the exact selected declaration through authenticated discovery; saves endpoint, session, non-authorizing credential digest, project/revision, original request ID, profile and text; and creates a new single-link 0600 file through a held owned parent directory. Existing paths are never overwritten. No auth token or API key is copied into the intent. Failed or uncertain publication leaves its newly created private file for inspection and cannot start inference.

`start --intent /absolute/private-intent.json --approve-inference` submits exactly those saved facts. It refuses changed endpoint/session/credential binding and absent explicit approval. Retry uses the same original ID and profile, without discovery/substitution or a new identity. Retained accepted receipts remain observational through restart/withdrawal; an unpublished intent whose old profile expired refuses instead of silently rearming. The server's fresh Read/Edit/revision fences and response validation still apply.

`status PROJECT ATTEMPT`, `list PROJECT`, and `cancel PROJECT ATTEMPT --request-id ID` expose the shared retained workflow. Results are typed JSON proposals/status. Target/review/edit context, approved project actions, protected undo and desktop controls remain pending. This CLI does not apply sample-stride changes to project/generation state yet.
