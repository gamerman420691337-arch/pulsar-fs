# Authored native persistent CUDA stream

A newly built CUDA-enabled worker completed three ordered exchanges through one loaded authored temporal model. Parent and worker agreed on the consuming Finish transcript. The original native trace contains three model runs and nine CUDA computation events. An independent reader reconstructed the manifest identity and transcript chain, checked the authored output formula and matched the original trace hash, run/node counts and node containment.

The case used the captured 75-library image, actual CUDA/NVML memory observation and a 96 MiB interactive reservation above the owner's 64 MiB offline ceiling. Replay after one exchange and cancellation after one exchange refused successful Finish and retired ownership. All three cases confirmed GPU/RAM/slot admission, staged worker/model bytes, native capture storage and worker-fence creation/group/staging records were released. Six direct-entry/unsealed/sealed-malformed relay cases refused before native loading.

The first fixture used an incorrect oracle after changing the previous frame. Its correction follows the byte-verified authored generator: `0.25 + 0.5 * mean(two normalized RGB frames)`. After that correction, native Finish exposed a real cross-process numeric bug: the default JSON float parser changed one promoted float32 value by one f64 bit. A focused reproduction failed at sample 125. The protocol now enables `serde_json`'s `float_roundtrip` feature; all 256 exercised numeric reply/transcript round trips pass. This changes numeric parsing accuracy across shared protocol users, so workspace, CPU application and ordinary-reader compatibility gates are required. The transcript comparison remains exact.

The [evidence packet](evidence/roadmap-2026-10-07/live-cuda-native-stream/) retains the failed source subjects/logs, corrected source archive, actual worker identities, original receipt/trace, exchanges and independent readback. The preceding worker used in the diagnostic failure predates the parent error-context change; the successful native run uses the newly rebuilt final worker and final source subject.
