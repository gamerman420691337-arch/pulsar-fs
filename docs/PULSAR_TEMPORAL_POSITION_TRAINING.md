# Training and temporal script-position generation

The owner permits live references for training and reserves sterile references for evaluation. `scripts/train-reference-position.py` admits only a training-only manifest rooted in the supplied `Live-Reference` folder. It snapshots bounded regular inputs into a new private run, retains original hashes and clocks, rejects ambiguous reference timestamps, and does not infer redistribution permission. Originals are unchanged. Model bytes, weights, decoded training tensors, input names and detailed intake remain in the ignored private reference-evidence directory.

The first run admitted eight matching video/script pairs. One additional pair was excluded because reference timestamps did not strictly increase; its reason is retained privately. Four bounded clips per admitted source produced 2,860 temporal frame pairs. Labels interpolate supplied script positions at exact elapsed source PTS. Decoding selects original frames by stride rather than an FPS duplication/retiming filter. Script/source alignment is explicitly unverified. Full packed-source RGB is stretched to 64×64 with nearest sampling; no target selection, projection or physical-motion annotation is inferred.

The small CPU convolutional model trained for ten epochs with seed 20261004 and four threads. Training-set MAE was 0.154411 versus 0.226414 for the constant training-mean baseline. These are resubstitution statistics. They do not measure generalization, stroke quality, target identity, creative quality or physical motion. Exported float32 ONNX output agreed with PyTorch within 8.941e-8 on the first 16 training samples. The model digest is `3f4daa94651cf5e407d2097d14e2dbf58959f7aed2af59a39f7d6a057449e816`.

The fixed runtime contract is named float32 input `frame_pair`, shape `[1,6,64,64]`, containing previous RGB then current RGB divided by 255; output `script_position` has shape `[1,1]` and lies in `[0,1]`. The decoder is `temporal_script_position`. `class_count=1` is a required legacy contract field, not an anatomical class claim. Input/output names, dimensions, types, finite values and range are checked. Detector tensors cannot masquerade as position output.

```sh
pulsar model profile PRIVATE_MODEL.onnx --width 64 --height 64 \
  --class-count 1 --temporal-script-position > PRIVATE_PROFILE.json
pulsar generate INPUT.mp4 --model PRIVATE_MODEL.onnx \
  --inference-profile PRIVATE_PROFILE.json --output NEW_OUTPUT.funscript
```

Profile bytes explicitly pin model, runtime, nearest packed-source preprocessing and strict CPU execution. There is no provider substitution or automatic activation. Generation requires 64×64 original packed-source analysis; selected-eye/spherical views are refused for this recipe. Existing placement can remap output times without changing source decoding order. A pair across a detected cut or over 500 ms lacks support. The first supported frame is an explicit synthesized neutral anchor, and unsupported later samples remain gaps. Inference positions are `inferred` and review-flagged as uncalibrated reference-script regression. It supplies no detector boxes, depth, anatomical target identity or calibrated confidence. Desktop preview therefore renders pixels without pretending detector analysis exists.

The first model is frozen before sterile evaluation. The existing sterile window, supplied annotations, timing and scorer thresholds are retained without tuning. The [checkpoint receipt](evidence/roadmap-2026-10-01/temporal-position-training/validation.json) records local gates and the independent campaign outcome. Training artifacts do not become qualified model profiles or authorize physical playback.

Invocation, tool-byte identities, Python/package versions, seed, clips, dataset identity, losses, weights and ONNX parity are retained. This is not a complete dependency lock or a guarantee across releases/platforms. PyTorch explicitly limits such guarantees in its [reproducibility guidance](https://docs.pytorch.org/docs/stable/notes/randomness.html). This first fixed-shape export uses the pinned legacy exporter and measured runtime parity; PyTorch describes its current preferred exporter in the [ONNX documentation](https://docs.pytorch.org/docs/stable/onnx_export.html).

GB-01/02 remain open for qualified tracking models, independently aligned natural-media annotations, held-out source families, approved quality and speed/memory evidence, vendor/provider coverage, calibrated confidence and a qualified fallback. This private reference-script candidate does not replace those requirements.
