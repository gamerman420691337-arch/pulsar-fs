# Held CUDA device bindings

The Linux engine helper `cuda_devices::PinnedCudaDevices` now checks a declared GPU UUID, PCI address and kernel minor against root-owned procfs information, then holds the NVIDIA control, selected GPU and UVM nodes with `O_PATH` descriptors. Enabled production inference remains CPU-only. [ADR B3-017](../research/phase-b/ADR-B3-017-held-cuda-device-bindings.md) records the prerequisite.

Expectations use bounded conventional GPU UUID syntax, a PCI address and a minor in 0–63. Kernel information must come from procfs and contain unique matching UUID, bus-location and minor fields. The character-device registry must identify NVIDIA/control and UVM majors. Final symlinks, non-character nodes, non-root ownership and device-number mismatches refuse. The helper neither opens devices for read/write nor loads modules, creates nodes or changes host permissions. Kernel minor is distinct from CUDA logical ordinal; this helper does not establish their mapping.

The caller must authorize access and retain the helper for the entire child lifetime. Binding preparation checks held inode/filesystem/device identities and makes their descriptors inheritable only in the forked child. The parent keeps close-on-exec descriptors. The example supplies `/proc/self/fd/N` sources to bubblewrap rather than selecting original device paths again.

## Verification inside confinement

A descriptor alone does not prove the mounted inode. The [bubblewrap 0.13.0 source](https://github.com/containers/bubblewrap/blob/v0.13.0/bubblewrap.c) notes that namespace binding can resolve descriptor links and that its fd-bind path needs a mounted-identity check. The device-bind route therefore has an explicit child gate: before cuDNN preload or CUDA session construction, it opens the mounted nodes with `O_PATH` and checks exact inode, filesystem and character-device numbers against a bounded read-only parent-supplied table. Missing, altered or unexpected tables refuse. This is a device-mount consistency check, not a grant of authority or physical GPU attestation.

The [authored native example](../crates/pulsar-engine/examples/native-dependency-probe.rs) now requires an explicit device expectation as its sixth argument. It holds descriptors through launch, mounts a private identity table read-only, runs the gate through captured bootstrap libraries, and preloads cuDNN only after successful verification. Host runtime directories remain absent. The final authored CUDA execution passes four numerical inferences and the strict twelve-computation-event trace; all reported library mappings remain in the captured set. A wrong mounted inode refuses at the gate. UUID, minor, nonexistent PCI location, traversal and unknown expectation fields refuse before library capture or execution output creation.

The initial parent `/proc/PID/fd` route failed because bubblewrap's user namespace could not access it. Its source, binary identity and failed output are retained separately. A transient gate compile failure from ambiguous `Read`/`Write` imports is also retained. Final evidence uses inherited descriptors, explicit mounted-node verification and corrected sources.

[Evidence](evidence/roadmap-2026-10-01/cuda-device-bindings/validation.json) binds source, Rust/build checks, actual CUDA/gate results, six refusals, cleanup and a current CPU CLI compatibility case. Native-window/full JavaScript qualification was not rerun for this helper change. No private media/model, training, sterile evaluation or Handy contact occurred.

Holding a VFS node does not freeze hardware, driver registration or physical identity across resets/reconfiguration. The future worker must check its actual CUDA device UUID/ordinal, while the owner broker must authorize the driver surface, supervise lifetime, reserve resources and bind dependency/device facts to durable attempts and recovery. Restricted sysfs remains an experimental observed set. Whole-worker VRAM enforcement, model/platform/device and release qualification remain open. The helper is Linux/NVIDIA-specific and does not claim other vendors or MIG support.
