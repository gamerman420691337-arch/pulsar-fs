# CUDA mounted-alias byte proof, 2026-10-09

Status: implemented; roadmap PARTIAL. The CUDA suite remains red on a recorded worker-fence lease failure.

The [checkpoint](evidence/roadmap-2026-10-09/cuda-alias-byte-proof/checkpoint.json) binds 408 source records, three changed paths and 405 unchanged. `cuda_mount_bytes.rs` supplies one-call byte verification; `cuda_mounts.rs` uses it within existing bootstrap checks; `native_mounts.rs` documents the distinction between authenticating each alias and hashing its shared inode. No profile, protocol, model or admission policy changes occurred.

Every alias is checked against its declared device/inode, length, read-only permissions and digest. Names referring to one unchanged inode share its fresh digest within that call. Separate inodes with identical bytes are hashed separately. Size, mode, modification time and change time are checked around hashing, on reuse, and when every name is reopened before completing the pass. Existing namespace, module/device and deadline checks remain. The proof is discarded on return; subsequent calls hash afresh. It is not a cross-request cache or scheduling authority.

Six tests cover same-inode sharing and fresh later calls, separate-inode hashing, conflicting digest/identity, same-length mutation after hashing, symlink replacement, mutation of an earlier inode before final recheck, and expiry before reused proof can complete. All six pass in workspace and CUDA builds. The new module passes rustfmt. Current checks pass 1,135 workspace tests (63 ignored), 289 architecture checks, 36 guards and development/release CUDA builds with existing warnings.

The CUDA suite records 609 passes, one failure and 68 ignored tests. `worker_fence::tests::format3_missing_roster_and_unrecorded_roots_refuse_without_rewrite` fails at its final immediate reopen with "worker fence lease is still held". This is the previously unresolved lease failure; it has not been retried into a green gate or repaired. The source deliberately retains the lease across fork-to-exec. That is a diagnosis lead, not proof of this failure's cause.
