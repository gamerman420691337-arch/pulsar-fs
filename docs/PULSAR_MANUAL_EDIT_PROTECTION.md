# Automatic native manual-edit protection

New native values-only edit commits automatically protect their changed motion support. The engine compares authoritative before/after programs, including changed interpolation segments, knots, gaps and deleted support. It unions the footprint with existing protection in the same SQLite transaction as the new revision, history and lineage. Uploaded review envelopes do not define this policy. Staging a candidate does not change the master or protection.

Overlapping or adjacent regions of the same axis coalesce. Global protection remains present. More than 1,024 resulting regions refuses the entire commit; ranges are never silently dropped. No-op motion does not add protection. Native authored candidate merges protect only their actual committed changes. Imported archival authorship declarations do not become native edit authority.

`pulsar edit-values PROJECT FILE --revision REV` accepts bounded values-only JSON and stages a candidate. `pulsar commit-candidate PROJECT CANDIDATE --revision REV` explicitly commits it. `pulsar protection status PROJECT` exposes current protection through diagnostics. `pulsar protection set PROJECT REGIONS --revision REV` explicitly replaces the complete policy; an empty JSON list unlocks it. Policy replacement requires ManageProtection and creates a fresh revision. Request IDs support exact replay.

`pulsar regenerate PROJECT SOURCE_VERSION --revision REV` generates a retained candidate and applies its present axes through protection-preserving merge. It preserves absent axes and protected interpolation stencils. Optional settings/model/preset use existing declared generation contracts. Candidate warnings are printed and retained; generation quality remains unqualified. Concurrent changes refuse the merge rather than silently rebasing. No output file is exported by this operation.

Compiled desktop controls show per-region explicit unlocking and applying all candidate axes while preserving protection. They use the shared authenticated authority and exact revision. Rendered usability remains unmeasured.

Undo and redo restore exact motion and protection history. Restoring motion across current protected support requires fresh ManageProtection, even if the policies happen to compare equal. Ordinary edits cannot use that exception. Scoped Edit alone cannot unlock or unwind protected motion. Durability and request replay retain the same policy.

Existing historical manual edits are not retroactively protected by a migration. Users must explicitly review and set policy for those edits. This increment does not close EDIT-02 broadly: legacy history, richer regeneration controls, manual usability, model/media quality, Handy and platform/human/release qualification remain open.

Evidence is recorded separately under `docs/evidence/roadmap-2026-10-01/manual-protection/`. The negative baseline uses the preceding target-seed production source with only the new CLI adapters, allowing the same native workflow to reproduce overwriting an unprotected authored point. It is not the untouched preceding production executable. The positive scenario checks protection, regeneration, missing-axis retention, explicit replacement, rollback, replay and actual restart using generated finite media; it does not contact a physical device or use training/sterile references.
