# Format-4 cgroup creation journal primitive

Status: PARTIAL. The format-4 primitive passes current-source verification: 971 workspace tests (39 ignored), 509 CUDA-feature tests (33 ignored), nine selected native cases, eight application cases without skips, builds and 238 structural checks. All 319 archived/live source records match. Production admitted creation custody is pending, and the final current-source legacy counterexample still fails with exit 101. See the [checkpoint](evidence/roadmap-2026-10-07/cgroup-creation-journal/checkpoint.json).

Format 4 adds a mandatory creation roster while retaining staging, active groups, retirement tombstones, scope and lease identity. Formats 2/3 omit the new field and keep their canonical representation. Schema 20's minimum-4 requirement is now understood by the worker-fence reader; a native engine fixture activates the primitive, publishes the requirement, reopens schema 20 with the same scope, and preserves it through ordinary worker/staging rearming. There is no production caller activating the primitive or the schema-20 admission writer.

The creation namespace records the canonical delegated parent, its device/inode and the current Linux boot ID. New leaves include the fence scope and a canonical UUID. A bounded scan checks only this scope's entries against creation/active/retired ownership; unrecorded entries refuse without deletion. Other scopes are not inferred to belong to this owner. Changed boot or parent identity refuses even if the roster is empty; automatic reboot/root relocation recovery remains an explicit unfinished product requirement.

Intent records absence before a creator may mkdir. An existing resource backed only by Intent is ambiguous and refuses. Bound records the identity of a directory held by its caller; missing, replaced or populated bound resources refuse. Retirement is journaled before deletion, and only a matching retired identity may recover an already missing path. Actual absence precedes durable clear. Registration atomically transfers the bound identity into the existing active worker roster; direct format-4 registration cannot bypass that transfer. IO failure retains attempted publication in memory. Capacity refusal is checked before mutating the attempted ledger.

Startup validates every active, retired, staging and creation obligation before any resource cleanup. Native fixtures preserve a good bound group and ledger bytes when another record has existing intent, a missing/replaced bound root, changed boot/parent identity, a missing roster or an unrecorded scope entry. Separate fixtures check failed publication, record capacity, populated refusal without signaling, and preservation of a different scope's group.

The first full workspace run retained one failure: the older unknown-version fixture used format 4 and expected the unknown-version error. With format 4 now supported, the malformed subject still refused, but failed that error assertion. The corrected fixture uses future format 5; the initial source/log and derived aggregate counts (786 passes, one failure, 39 ignored before the suite stopped) are retained under initial/. The original count parser omitted failed-suite summaries; its corrected derived count file is retained alongside the raw original.

Five actual owner-process termination cuts cover absent Intent, existing ambiguous Intent, Bound, a removed retired group and registered ownership. The parent independently observes exact group identity and empty population before recovery. Ambiguous Intent preserves the resource and ledger until the fixture explicitly removes its own exact empty group; restart then clears the absence obligation. These are production journal primitives with actual cgroups/process death, not full shipped-engine creation cuts, power-loss qualification or reservation-custody evidence.

The tests still use the raw cgroup creator to exercise journal transitions. They do not establish intent-to-mkdir parent-FD continuity or binding before limit configuration. Required next work is an admitted creator that owns the reservation and lease before fallible effects, creates through the held recorded parent, captures identity before fallible handoffs, journals binding before configuration, retains failed acknowledgements/cleanup, and transfers registered ownership to worker custody before spawn. Production ordinary/live/native-capture paths must then adopt it only after ledger publication and committed schema-20 admission. Until then the current production mkdir-to-register window remains open.

Legacy cgroup/staging recovery, native-image/capture ownership, remaining engine crash/I/O coverage, portable format-4 correspondence and model, platform, real-media, physical Handy, human and release qualification remain open. Production GPU admission remains disabled.
