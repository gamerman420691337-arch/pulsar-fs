# Durable worker fence primitive

This private Linux primitive is implemented and tested, but engine startup/admission, launch guards and a conditional DB reader barrier are not integrated yet. Production restart fencing and GPU admission remain incomplete. It does not change the engine's current behavior.

The later [pre-spawn custody increment](PULSAR_WORKER_PRE_SPAWN_CUSTODY.md) adds optional fence ownership through registration, failed spawn and durable-clear reaping. Production callers still supply no fence; engine startup/scope and reader-barrier integration remain pending.

The primitive holds an exclusive lease on a private read-only descriptor with CLOEXEC set. A child inherits that lease across fork until exec. The intended launcher must register and synchronize its cgroup record before fork, keep the lease alive through process creation, and perform cgroup placement in pre_exec before exec closes the inherited descriptor. This covers the pre-membership interval without exposing a host-write descriptor to the guest. A later engine can acquire the lease only after all holders have released it; it must then also inspect recorded cgroups before admission.

The bounded canonical ledger retains a UUID scope, lease-file device/inode and up to 4096 cgroup records, with a 1 MiB serialized cap. Each record binds an absolute canonical cgroup-v2 path and its device/inode. Population reads use a held directory descriptor and openat. Startup validates every recorded group before clearing any retired records. Populated, absent, altered or unreadable groups refuse opening; it never signals or moves processes. Missing ledgers and replaced lease files refuse instead of silently creating a new ownership scope. Parent-side clearing requires an exited direct child and an empty matching cgroup, and synchronizes ledger replacement before callers may remove the cgroup.

The [packet](evidence/roadmap-2026-10-01/worker-fence-primitive/validation.json) records five file/lease cases plus two explicitly executed native cases. One native case proves that a pre-exec child retains the lease after its parent owner drops it and releases it at exec. The other registers an actual owned cgroup, refuses populated and altered identities without signaling its child, then recovers after confirmed retirement. The fork case must run serially: fork inherits other test threads' file descriptions, temporarily retaining their leases. The initial parallel fixture failure is retained; the final native gate uses explicit serial execution. A full feature-suite fixture also encountered a lease briefly inherited by other tests' FFmpeg forks. File-validation fixtures now retry only bounded `WouldBlock` lock contention before checking their intended outcome; production opening still refuses immediately. Both failure logs are retained.

Remaining integration must bind the durable scope to engine state, add an older-reader barrier before tracked launches, transfer ledger ownership through success/error/cancellation/reaper paths, and cover failed registration/spawn and crash windows. These methods are private building blocks; callers are not yet qualified to use them for production restart admission. GPU/native-image/device lifetime, portable accepted CUDA evidence, blocking host IO and model/media/hardware/platform/human/release gates remain open.
