# Annotated generation receipt correspondence

The Engine completion path now validates annotated generation metadata before publishing a candidate. It binds schema 3, the recipe and unqualified status, project/base/job/attempt/source identities, exact program identity, preset/settings and their configuration digest, original source dimensions, 64×64 analysis dimensions, native view plan and transform, ordered dependencies and returned review data. It replays the shared numeric planner instead of trusting a receipt filter. Existing whole-frame completion behavior is unchanged.

Model correspondence is checked against the declared model bytes. A bounded streaming ONNX parser validates the annotated tensor/recipe metadata and training-intake digest. The same model reader is hashed before and after metadata inspection. Receipt contents must match that validated metadata. Neither metadata inspection nor the validator runs inference.

The shared reader-based entry point never resolves source, model, runtime or output paths from an archived request. Its current-attempt wrapper opens only the declared model and retained receipt. Receipt parsing streams irrelevant analysis fields rather than retaining sample arrays. The byte limit is the minimum of 16 MiB, one sixteenth of the attempt memory budget and the remaining output budget after the program; dependency and review arrays also have explicit count bounds. Callers retain responsibility for reader provenance and memory admission. Excess receipts refuse rather than being truncated.

Five unit tests cover 21 metadata mutations, exact ordered extra-dependency duplicates, malformed/duplicate fields, additional native-plan fields, array and byte bounds, receipt digest/length mismatch, and short/extra model bytes. The authored native file test additionally verifies the actual receipt/model, verifies from retained readers with nonexistent archived source/model paths, and refuses changed model bytes and rehashed receipts with changed plan/intake/configuration metadata. Its original 28-frame and 14-estimate Python correspondence assertions remain in place.

This is metadata/result correspondence, not a new clock/sample verifier or a quality claim. Existing placed-clock checks still require schema 2; annotated schema-3 clock closure remains required. Portable export/import still refuses schema 3, pending an explicit portable reader requirement and retained model-object admission. Public annotated Engine submission, Stash batch/model-pack admission and client controls remain guarded. See [ADR B2-008](../research/phase-b/ADR-B2-008-annotated-receipt-correspondence.md).
