## Restriction and authority

`PackageCandidate.project_interval` is an optional checked half-open project-time application restriction. Original jobs, receipts, actors and execution paths remain archival. A clone keeps `job_id=None`; scope cannot restart a worker, grant a permission, promote imported authorship or authorize a project mutation.

The existing typed worker-evidence parser supplies native restrictions, keyed by exact canonical manifest and candidate identity. A pure resolver follows verified candidate namespace edges through successive clones. Native job bindings must match original project, job, attempt, base revision, primary source and content identity. All original paths remain inert. Namespace paths must agree on scope. A new declaration cannot widen, narrow, omit or invent its verified restriction. Legacy field absence recovers the original declaration from retained checked ancestry; it does not prove whole-project scope.

Fresh import publication stores a resolved policy row for every inert alias: a range for an interval proposal, explicit `null` for a proven whole-project proposal. The engine exposes that restriction through the existing candidate snapshot. The same authoritative guards used by native proposals refuse whole replacement of an existing master and require an explicit contained merge range. Fresh empty projects retain deliberate explicit-commit behavior. Rebase copies alias and restriction in the same transaction, including a proposal stale after a master revision advances. Outside motion, protections and axes absent from a candidate retain the underlying merge rules.

## Compatibility and recovery

Portable format **7** is required when a candidate carries an interval or its retained ancestry requires format 7. Simpler packages retain their minimum existing version. Supported formats 1 through 6 remain readable; their byte-exact original manifests are preserved. New readers recover interval settings from checked legacy worker evidence. Older format-6 readers refuse a format-7 subject before project publication.

Database schema **9** prevents older schema-8 engines from ignoring imported restrictions. Layout validation runs before writable opening of an existing schema-9 subject. New policy publication and the migration barrier commit together after recovery; an existing barrier never downgrades.

Recovery checks bounded root archives, hash-bound identity maps, canonical origin manifests, transitive mappings, typed original worker settings and local candidate/motion/lineage correspondence. It resolves missing alias rows, including aliases rebased before migration, then inserts all recovered rows and advances the barrier in one transaction. Original worker/media paths need not exist. Motion, revisions, edit history, protections and archival manifests remain unchanged. Migration does not repair outside motion already deleted by an older engine; its existing committed history stays authoritative.

Missing, oversized, corrupt or inconsistent required evidence refuses recovery and engine startup with an explicit error. No unresolved alias becomes a whole-project proposal. Failed schema-8 recovery publishes neither restriction rows nor schema 9; auxiliary layout preparation may already exist. It does not imply byte-for-byte rollback of the whole database. Runtime lookup also refuses unresolved, oversized, invalid or project-inconsistent policy cells. Bounded SQLite reads precede allocation; graph/alias counts, checked arithmetic and aggregate memory admission limit parsing. Recovery does not execute retained jobs, open their source/model/tool paths or contact devices.
