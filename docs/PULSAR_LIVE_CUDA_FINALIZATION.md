# Engine-owned live CUDA finalization

The private Engine finalizer consumes its actual live CUDA worker and returns a completed capture only after original native evidence is committed to SQLite. A caller cannot submit a finished envelope as publication authority. Public GPU capture routing and a public Finish command remain unfinished.

Before closing, the Engine checks the original explicit Start/Continue intent, session authorization, owner, boot, project revision, worker fence, registry membership, actual runtime's opaque worker scope, provider, Ready manifest, profile and completed work. It requires no in-flight pair, enters `Finishing` and clears provisional output. Intake, analysis dispatch and continuation refuse this phase. The runtime stays under the existing cancellation and lease supervisor; Stop, grant revocation, revision changes and expiry still retire it. An encoded source's expected closing refusal does not turn Finish into a worker failure.

Consuming Finish verifies the scope-bound transcript, original receipt/trace, EOF, successful child exit and native custody retirement. Evidence memory admission precedes receipt loading. Storage is reserved from the actual database filesystem before opening the publication transaction. Under the database/registry lock order, the Engine repeats current authority and closing-membership checks, validates the proposed report against the admitted evidence, retains original bytes, checks the fence and lease, and commits.

After commit, the Engine checks its original monotonic deadline again. A filesystem commit cannot be preempted; if it crossed the deadline, the capture expires and no completed report is published. Any committed row remains unqualified historical diagnostics. Otherwise the capture retires at the observed Engine tick and its report carries SHA-256 identities and lengths for the canonical manifest and original receipt/trace, plus the checked stream summary. All evidence is explicitly `qualified: false`. A subsequent Stop retains the completed report. Failure after entering closing retires without relying on a healthy database.

Protocol validation requires matching CUDA provider/manifest, completed counters, retained identities, bounded bytes, source/frame bounds, a retired capture and an elapsed clock within its lease. It refuses CPU completion claims, qualified evidence, inconsistent metadata and in-flight finishing reports. Optional fields preserve ordinary CPU report bytes. Parsed report metadata establishes consistency; the Engine's consuming worker and transaction establish the private publication path.

Verification is retained in [the evidence packet](evidence/roadmap-2026-10-07/live-cuda-finalization/). Authored phase tests exercise intake freeze, continuation refusal, cancellation and revision/revocation/expiry supervision, plus failure retirement while the database mutex is held. The native fixture uses private startup and a test-inserted registry entry with authored RGB/source timestamps, three real GPU exchanges and the Engine clock; it checks exact SQLite/report linkage, resource release and Engine reopen. It does not prove public GPU lifecycle, sustained acquisition, decoder custody retirement before publication, learned model quality or latency qualification.

Final serial gates pass 1,022 workspace tests (55 ignored), 543 CUDA Engine tests (54 ignored), explicit native live/offline/eight-case stream checks, nine CPU application cases without skips, the default build and 263 structural checks. All 355 source/archive and 80 native/model records match. Independent SQLite readback verifies exact report-linked bytes, one schema21 row, three GPU runs/nine CUDA computation events and no foreign-key errors. Completion was observed at 16,558,972,676 ns within the original 30-second lease; this is one observation, not latency qualification. Current compiled readers accept the final reports; the closest preceding reader refuses Finishing/Completed while preserving exact CPU bytes. The initial authored queue-fixture failure and three type-comparison compile errors remain retained; failed-subject source archives were not captured. Blocking-commit deadline crossing and concurrent Stop during the actual consuming finalizer were not fault-injected in this campaign. Phase supervision tests and native stream failures retain their narrower scopes.

Public startup/scheduling/Finish, continuation/recovery and known parallel-test failures remain open. Sterile-reference evaluation, trained model quality, multimodal/six-axis performance, physical Handy, platform, human acceptance and Preview/Stable release gates remain open.
