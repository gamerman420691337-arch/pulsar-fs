# Exact live project phase across epochs

Live presentation clocks and capture options can carry `exact_project_anchor`, reduced rational seconds encoded as bounded numerator/denominator strings. The existing integer `project_anchor` must equal its nanosecond floor. Absence preserves the legacy integer-anchor mapping and serializes without a new field.

Project mapping evaluates the complete exact anchor plus original rational source delta before one final floor. Reanchoring never feeds a rounded project timestamp into the next transform. Local presentation ticks and optional buffer remain separate: each successor starts with presentation anchor zero while retaining the exact original source-to-project phase. These declared clocks do not establish acquisition or player synchronization.

`LiveCaptureReport::continuation_options(source_anchor, lease_ms)` derives a successor declaration from a validated active report, advances beyond the predecessor's last source frame, preserves source/profile/policy, and retains a fractional anchor when needed. It grants no new epoch authority. The explicit options command still validates the full declaration against the actual predecessor, including exact phase even when two proposed anchors have the same integer floor.

`live-capture continue-at PROJECT REVISION PREDECESSOR SOURCE_ANCHOR_JSON --lease-ms 30000 --request-id ID` sends `ContinueLiveCaptureAt` with the source anchor and bounded lifetime. The engine derives options under fresh authority from its actual predecessor report, after exact request replay is checked. A replay returns the current or retired successor rather than deriving from an inactive predecessor. Changed arguments conflict; fresh requests cannot continue a retired predecessor. Existing boot/actor/revision/grant/source/profile/policy, pixel admission, receipt rollback and worker cancellation fences remain in force.

The source JSON contains original rational seconds, for example `{ "numerator": 4, "denominator": 30 }`. The resulting exact project anchor is 2/15 seconds when the original project/source origin is zero. A later original timestamp 6/30 maps to exactly 200000000 project nanoseconds; it does not become 199999999 after adding two rounded intervals. Standard funscript export separately rounds project nanoseconds to milliseconds using its existing rule, so the authored pair at 5/30 and 6/30 exports at 167 and 200 milliseconds while its retained project timestamps remain 166666666 and 200000000 nanoseconds.

Checked arithmetic refuses overflow, zero denominator, unknown fields and integer/exact-anchor disagreement. Models and native replies retain the full clock in their exact manifest/pair identities. No ambiguous fallback or rounded replacement is accepted.

Regression evidence includes 120 successive rebases for each of 24, 30, 24000/1001 and 30000/1001 fps, signed original origins, comparison with the original unreanchored clock, malformed anchors, same-floor phase substitution, fresh/replayed/retired authenticated capture commands and native original-PTS NUT segments. The authored CPU model and finite captured-pair worker carry the same exact phase through inference and exported action timestamps. This is functional wiring and arithmetic evidence; real continuous acquisition, automatic segmentation, measured source/player gaps, qualified models/GPU and Handy/platform/human/release gates remain open. Training and sterile evaluation are unchanged.
