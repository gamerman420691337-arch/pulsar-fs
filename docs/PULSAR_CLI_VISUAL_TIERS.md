# CLI visual tier parity and bounded background recovery

2026-10-12. Shared generation/consumer software increment; full roadmap remains PARTIAL.

The public `generate` command now accepts the Engine's `default`, `fast`, `maximum` and `quality` spellings. Maximum/quality require a declared visual detector and still refuse model-free or temporal-regression recipes. The shared file-generation helper checks the execution contract before creating a project or importing source bytes. The preceding shipped CLI refused Maximum/quality before generation despite the Engine and desktop already offering the tier.

`--source-sample-stride N` exposes the existing original-frame sampling contract. It defaults to one and accepts positive u32 counts; original source PTS and frame ordinals remain authoritative. It does not convert cadence to a guessed FPS or retime output. Unsupported legacy FPS/window/batch/projection switches remain explicit refusals. Temporal raw-pair and source-bound annotated profiles retain their existing stricter admission rules.

The real offline CLI campaign exposed a Maximum sampling defect: its eight-pixel search needs a thirteen-pixel margin, while the full-frame background grid on a 64×64 view places usable candidates either outside that search margin or inside the target exclusion. All 64 target flows were accepted, but zero background flows supported either the moving or stationary control. Standard export correctly refused unresolved gaps. Those preceding metadata and failures are retained.

Maximum now uses `visual-flow-maximum-v2`. When fewer than three original background flows are supported, it seeds bounded distinct additional points inside the exact full-resolution search margin, outside both previous/current expanded target boxes. It retains the original grid and adds only up to the remaining capacity of the unchanged 64-point background limit. Core's forward/backward, photometric, texture, consensus and three-point support checks remain unchanged. Default/Fast do not enable this recovery. Receipts expose actual background sample counts when the recovery path runs; legacy receipts omit the optional field. Maximum checkpoint hashes change with the explicit plan version; incompatible previous checkpoints refuse.

The new regression fails against the preceding worker with 64 accepted target points and zero background points. It verifies supported stationary motion after recovery, while flat or fully occluded backgrounds still remain unavailable. An intermediate attempt exceeded the unchanged point limit; that failure is retained and final recovery stays within it. Headless tests and synthetic fixtures do not establish real target/camera accuracy or a Maximum quality improvement.
