# Desktop WASM editor workflow

Status: controller and local IPC implementation verified; graphical window rendering and human usability unverified. GB-12, B6 and release qualification remain incomplete.

The desktop WASM editor tab inspects engine worker identity and bounded module/manifest declarations, then requires explicit approval of the captured module and worker for one invocation. It sends a fresh identified start against the displayed project revision. The engine receives the captured bytes rather than reopening a user path. Loading new declarations, changing paths/label/memory, changing project/revision or observing changed worker availability/identity invalidates the disposable draft or approval. Guest compilation, scope/revision/epoch admission, resource supervision and candidate effects remain engine-owned.

The panel's bounded background queue keeps declaration reads and engine calls off the GUI thread. Unix file opens are nonblocking and reject nonregular handles, including named pipes; byte limits refuse without truncation. This does not prove preemption of arbitrary filesystem/metadata calls. The panel displays module/native identities, resource declarations and native runtime qualification status before approval. It imports no Wasmtime, decoder, database or physical-device implementation.

A lost start acknowledgement retains the original identified intent in memory. Explicit retry uses those exact captured bytes, original ID and revision. Catalog discovery reconciles the owning session's original request, base revision and declared module/worker receipt identities. An empty catalog does not prove that execution never happened. Setting aside a local retry neither cancels nor removes engine work and clears approval; a new invocation requires fresh approval and a new ID. The original controller checkpoint retained pending intent only in memory. The subsequent [durable recovery increment](PULSAR_DESKTOP_WASM_RECOVERY.md) preserves original invocation metadata across controller restart, with fresh approval required for retry; it creates no standing grant.

Attempt selection supports current status refresh and explicit cancellation. A completed report exposes Open candidate for review, which uses the existing hydrated candidate/timeline and separately authorized protected commit/merge/rebase/undo controls. The panel never automatically commits a guest proposal. Status display retains at most 64 latest observed entries; fresh catalog discovery returns the engine's current bounded records. Replies for an earlier project revision refuse rather than updating the new view. Approval is never restored by catalog discovery.

The same controller functions were explicitly exercised against a disposable native Engine through actual authenticated control/bulk sockets and a real authored WASM worker. Guest output becomes a hydrated candidate while master descriptor/revision remain unchanged. Original-request discovery, identified start replay and terminal cancellation preserve the original candidate. This uses the qualification host and existing production handlers/SessionClient; it is not a test of the packaged default service or graphical event dispatch.
