# Assistant journal capture admission

Status: PARTIAL full roadmap progress; qualification INCOMPLETE.

Assistant startup, status/list, cancellation, owner revocation, profile withdrawal and Start capacity checks use a shared typed capture reader. SQLite returns only text identity fields between 1 and 128 bytes and report text between 1 and 65536 bytes. At most 128 reports can be returned; row 129 refuses before its fields are captured. Decode and validate each bounded report, then match attempt/project/session/original request against the stored columns. The schema declaration read is bounded to 4096 bytes and still requires exact canonical equality.

Report creation and updates serialize through a writer that never retains more than 64 KiB, including JSON escaping. Updates require the exact identity tuple. A report valid on the wire does not automatically qualify for private journal admission. Historical oversized or damaged records refuse explicit recovery without truncation, pruning, signalling or opportunistic repair. The normal restart transaction still marks valid running reports interrupted and preserves original identity.

This bounds serialized report capture to 8 MiB plus bounded identities and decoded metadata. It does not qualify SQLite pager allocations, filesystem reliability, native process death/power loss or whole-application peak RAM. No schema/wire change or new credential persistence is introduced.
