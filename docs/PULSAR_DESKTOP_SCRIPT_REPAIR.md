# Desktop script repair

Doctor provides explicit neutral-script repair controls using the shared Core policy and Engine edit authority. Select a project, enter the funscript path and import for repair. The import produces a sanitized candidate. Review and commit that baseline through the existing candidate controls before proposing numerical repair.

Set maximum script slope, jitter window and jitter threshold, then propose repair. This captures the committed program, project, revision and checked policy and runs off the event loop. The proposal produces a candidate; review and explicitly commit it. It never commits or exports automatically. Existing history and protected-region checks remain authoritative. Numeric script slopes do not qualify physical motor safety or motion quality. The [shared repair policy](PULSAR_SCRIPT_REPAIR.md) describes sanitation, timestamps and numerical limits.

Busy requests disable duplicate actions and policy changes. Invalid policy, missing project/master and unsupported input refuse. The RPC layer refuses missing or rebound request context before uploading, then validates candidate project, base revision and numerical values. If the current view changes before the reply, the result is discarded from display with its candidate ID and captured project for manual inspection. There is no automatic replay or rebase.
