# Live CUDA provisional reporting and Engine completion

The shared live result contract now has a distinct `CudaProvisional` variant. It binds an estimate to its stream manifest as well as the existing attempt, capture identity, profile, issued frame pair and pixel identities. It does not represent consuming Finish, original trace verification, learned quality or device authority. Capture reports carry an optional CUDA manifest digest after Ready; ordinary CPU report serialization omits it and remains byte-identical.

GPU Ready requires an actually launched private worker matching the capture runtime's opaque owner scope. Equal capture metadata from another runtime is insufficient. The Engine rechecks the durable fence, current registry membership, lease/revision/grants and profile/worker binding before installing the digest and Running state. GPU completion borrows that worker and the issued work, converts its current exchange into the provisional variant, and uses the shared Engine completion path. That path checks provider, manifest, attempt, profile, exact sequence, pair/pixel binding and elapsed bounds before completing work against the Engine's original lease clock. Stale completion remains counted without publishing a new latest estimate. Stop, revision change, revocation and expiry discard current authority; retirement clears latest.

Report validation previously allowed an ordinary estimate under a CUDA profile declaration. The compiled preceding reader reproduces that metadata gap; the current reader refuses it. Public CUDA capture startup was already disabled, so this reproduction is not evidence that the old product launched an unqualified GPU stream. CPU estimates now require CPU admission, while CUDA provisional estimates require the matching report digest. Both keep `qualified: false`.

Five protocol tests cover equal CPU bytes, provider/manifest mismatch, missing readiness, retirement and altered qualification/clock/duration facts. Seven focused Engine tests cover existing CPU behavior plus CUDA provisional acceptance/staleness, sequence/provider/manifest refusal and revision/revocation/expiry disposal. The authored cases that directly install reporting metadata do not establish native execution.

A separate native fixture launches the actual Engine-owned CUDA stream, then checks scope binding, authenticated RGB upload, registry-issued work, real-clock completion, status reporting, consuming Finish and Stop cleanup. It retains another accounting worker slot throughout under the default two-slot pool. Its registry entry is explicitly test-inserted; it does not exercise `StartLiveCapture` GPU admission or the automatic analysis scheduler. Source timestamps/pixels are authored. Capture ticks are sampled from the same monotonic origin used by the Engine, and completion ticks come from the Engine. Independent readback reconstructs manifest/transcript hashes, checks frame pixels/source clocks, numerical results and report age calculations, and verifies three model runs/nine CUDA computation events in the original trace. All three observed results were accepted by the configured 200 ms freshness policy and remained provisional/unqualified. Three scalar-graph observations do not qualify a live latency distribution, actual capture-to-command performance or six-axis output.

The [evidence packet](evidence/roadmap-2026-10-07/live-cuda-provisional-report/) retains the frozen preceding/current readers, original CPU bytes, disguised-provider counterexample, negative reader cases, native reports/exchanges/receipt/trace, source archives and regression logs. Both readers export identical CPU bytes; only the current reader accepts the provisional CUDA report. The preceding reader refuses all four native status/retirement reports. Original native evidence is separate from the reports' provisional metadata.

Final serial gates pass 1,008 workspace tests (54 ignored), 532 CUDA engine tests (53 ignored), the explicit native reporting case, nine CPU application cases and one compiled-reader compatibility case without skips, the default build and 260 structural checks. All 351 source/archive records and 80 native/model inputs match. Frozen worker/reader identities remain unchanged. Initial focused logs retain their own scope; final workspace/CUDA coverage establishes the final archived source.

Public GPU live routing remains disabled. Automatic startup, graceful finalization/persistence and its durable reader barrier, continuation, sustained scheduling and exhaustive recovery remain open. The earlier eight-case private stream campaign is a preceding source subject and was not rerun for this additive reporting change. Previously retained parallel-test failures remain unresolved. Model/media, fastest-preset six-axis, physical Handy, platform, human and release qualification remain open. See [ADR B3-060](../research/phase-b/ADR-B3-060-live-cuda-provisional-report.md).
