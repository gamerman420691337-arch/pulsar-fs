# Stopped playback recording-index retirement

Read the selected recording's first page, acknowledge **Retire the selected stopped
playback from the active index, preserving its records**, then choose **Retire stopped
playback index**. Retirement identifies the original request and moves every retained
continuation scope of that playback into bounded local history as one transaction.
The preview must be stopped; every group member must still be authenticated, stopped,
retained and readable through the current Engine. Active, discarded or unavailable
records refuse without changing the index. Unknown old-boot records are not silently
adopted or removed.

The operation frees active-index entries without deleting Engine buffers, samples,
candidates, sources, projects or exports. **Inspect retired recording index** lists
identity metadata without Engine work. Historical IDs remain readable/downloadable
through the existing recording routes while the original Engine buffers remain.
Server restart restores the same history; Engine boot loss still makes buffers unknown.
No stage or commit approval is created. New candidate preparation selects active
playback groups only, so a retired group cannot accidentally become a partial take.

Active and historical indexes each admit at most 64 scopes under the existing private
journal byte limit. Duplicates and splitting one playback between active/history refuse.
Older journals with no history remain readable. Explicit repeat retirement returns the
same whole-group receipt and preserves newer active entries. History-capacity release
and unavailable-record disposition remain separate future work; no file reclamation
occurs here. Private storage is unsupported on non-Unix platforms.

four historical references with one unknown active reference. Worker custody is empty
