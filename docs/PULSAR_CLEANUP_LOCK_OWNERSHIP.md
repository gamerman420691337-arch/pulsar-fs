# Cleanup receipt lock owner lifetime

The preceding selected-pack checkpoint exposed an intermittent parallel test error: `Cleanup receipt is owned by an active helper`, caused by `Resource temporarily unavailable (os error 11)`. Eight unmodified parallel repeats and a syscall-traced repeat passed. Those passes did not repair or explain the failure.

A deterministic regression now keeps the actual cleanup receipt open-file description alive in an owned child after the parent Record ends. The child holds a duplicate as stdin, never reads receipt bytes, and waits on a separate control socket. Recovery refuses while the Record owner remains active. Before the fix, closing the parent Record still leaves recovery blocked with the exact error while the child stays alive. The regression retires and joins the child even on assertion failure. Source versions and the failing output are retained.

Record now explicitly unlocks its receipt when its helper lifetime ends, following the existing private recovery-journal guard pattern. Field close alone cannot define that lifetime when descriptors are inherited.
