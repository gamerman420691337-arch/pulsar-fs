CandidateImageOriginStatus is a read-only, authenticated project/candidate query. It returns a bounded CandidateImageOriginReport with the exact current motion binding and retained historical image approval. The report names original project, candidate, assistant attempt and generation attempt separately. It retains the original approval request, proposal/configuration correspondence, source/RGB/model/runtime/projector identities, record identity, worker manifest, producer receipt and raw worker program identity. Canonical candidate motion remains distinct from raw worker bytes.

The query retains a 32 MiB report admission through metadata validation/encoding, bounds candidate review cells before allocation, and separately admits object/motion verification. Local inspection rechecks the accepted job and candidate, retained origin/RGB snapshots, exact producer receipt and original worker motion against current canonical motion. It derives owned attempt paths from the validated attempt identity; it never opens a path from a historical worker request. Clone inspection verifies the retained namespace graph, candidate alias/motion/lineage correspondence, required evidence roles and original producer correspondence, then reads inert retained objects by identity. It does not restore jobs, attempts, grants or workers.

The desktop offers Verify image generation origin in candidate review, displays source/pixel/approval hashes and original namespace, and exposes the typed details. It discards responses whose project, candidate, base revision or exact motion descriptor differs from the visible candidate. CLI access is `pulsar project candidate-image-origin-status PROJECT_ID CANDIDATE_ID` through the usual authenticated Engine session.

CandidateImageOriginPixels is a read-only authenticated query selecting a retained origin by record SHA-256. It revalidates the complete origin report and reads only the current engine-owned RGB object in local snapshots or imported-project-evidence. Its typed response binds the selected record, exact RGB identity, dimensions, packed RGB8 layout and current candidate motion. The existing local raw-frame client decoder checks regular-file layout, bounded length and SHA-256 before converting RGB to RGBA; historical media and worker supplier paths are never opened. This uses the existing shared-filesystem local frame ABI and does not qualify remote filesystem access.

The desktop's Show conditioning image action displays those stored pixels separately from video playback. It discards responses whose selected origin or current project/candidate/motion binding differs, preserves aspect ratio and limits display size. CLI access is `pulsar project candidate-image-origin-pixels PROJECT_ID CANDIDATE_ID RECORD_SHA256`. Neither query performs inference or restores a job, approval grant or worker.

Every report fixes execution_authority, observed_temporal_motion and qualified to false. The typed validator binds the original compact approval record to its hash and byte length and enforces approval/proposal/configuration correspondence, candidate motion scope, unique sorted origins and the control-frame budget. This query supplies historical evidence, not permission to execute the retained proposal again. It does not claim that an authored test proposal was learned or useful.
