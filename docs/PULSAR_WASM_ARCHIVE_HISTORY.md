# Retained WASM invocation history

Status: bounded engine/CLI/desktop-controller and actual runtime checks PASS; full roadmap PARTIAL.

Explicit archival separates operational visibility from retained custody (ARCH-046). Local recovery records can be dismissed after acknowledgement, so they cannot serve as the authoritative historical browser. ListArchivedWasmEdits now discovers retained completed invocations directly through the authenticated engine. CLI wasm-edit list-archived accepts a page limit from 1 through 32 and an optional exclusive attempt cursor. The desktop keeps one bounded page and offers refresh, continuation and protected candidate opening through its existing review flow.

Every query checks current Read authority and filters by owning session and project. A single read transaction observes archive membership and receipts together. Results contain original attempt/start IDs, base revision, candidate and receipt metadata, never original execution bytes or credentials. They remain historical facts, not execution, commit, archival or disposal authority. Candidate retrieval and subsequent review actions retain their independent engine authorization and revision checks.

The protocol echoes cursor and limit, validates project scope, completed report shape, strictly increasing attempt order, no duplicate attempts/requests and bounded encoded response. A continuation must identify the last record of a full page. Engine queries at most limit plus one IDs to establish whether another page exists. Pages observe current membership independently; a new archive before the cursor can be found by refreshing the first page. They do not claim an immutable multi-page snapshot or chronological order. Desktop results from earlier project/revision bindings or unmatched page requests refuse, and binding changes clear displayed history. Browsing neither acknowledges unknown local requests nor grants pending execution or approval.
