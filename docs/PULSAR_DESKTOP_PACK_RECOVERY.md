# Persistent desktop pack recovery

Desktop pack import, selection and deactivation now retain the original request ID and typed intent in a private client journal before dispatch. Closing a window does not erase an operation that reached this boundary. Opening another window restores the paired session's entries, without automatically replaying them, setting the approval checkbox or populating current selection. Current owner status remains a separate engine query.

The panel lists the retained directory or manifest/revision and whether an engine receipt was acknowledged. Select an entry and use **Replay retained pack operation** to submit that exact ID and intent. Replay may finish an operation that was never accepted; an accepted request returns its historical receipt. A historical selection receipt cannot restore an old choice. The client still invalidates selection after mutation/replay and queries current status separately. An import directory remains a locator: engine intake rechecks the actual source bytes; the journal is not a snapshot of those assets.

**Dismiss acknowledged recovery entry** removes only that local entry after a validated engine receipt has been acknowledged. Unacknowledged intent cannot be silently pruned or dismissed. No pack, selection, job or project is removed by dismissal. The journal holds at most 64 entries and 1 MiB; a full journal refuses new pack mutations until an acknowledged entry is explicitly dismissed.

Journal schema 1 lives under the engine's private state directory in `desktop-pack-recovery`. Each paired session has its own namespace. Entries hold intent, request ID, acknowledgement and a SHA-256 owner-capability binding; the envelope also binds the session and bearer credential through a digest. Neither owner-capability nor bearer bytes are stored. These hashes and private client metadata establish no engine authority, publisher trust or qualification. Changed credentials, owner bindings or original intent refuse replay while preserving the journal. A different paired session cannot renew an old request namespace.

The Unix adapter opens owned private directories and single-link 0600 regular files without following final symlinks, locks the per-session file across windows, merges against the current record, writes a private unique staging file, syncs it, renames it atomically and syncs the directory before RPC. An acknowledged receipt is saved after a valid engine response. If that save fails, the client reports the returned receipt ID and retains the original operation for reconciliation. Corrupt, oversized, nonprivate, symlinked or hardlinked journal files refuse rather than being overwritten. Interrupted staging files are inert; this change adds no automatic orphan cleanup. Non-Unix storage is explicitly unsupported. No database or portable format changes are introduced: conditional schema 13 and format 9 remain unchanged.

The [local receipt](evidence/roadmap-2026-10-01/desktop-pack-recovery/validation.json) binds final source and executable identities. Unit cases check exact persistence/replay, changed bindings, corrupt/oversized/unsafe files, concurrent windows, full-journal refusal and acknowledged dismissal. The actual headless egui case renders and clicks the restored replay/dismiss controls, refuses dismissal without acknowledgement and keeps restored intent separate from generation authority. The initial five fixture failures used default temporary-directory permissions; private fixture roots corrected that setup without weakening production checks.

The authored native fixture invokes the same store and replay runner as the desktop. It stages an intent without dispatch, receives a real engine deactivation receipt while deliberately leaving the client acknowledgement unwritten, restarts clients and engine, advances current selection to revision 2, then replays the original request and receives historical revision 1 without changing current revision 2. Wrong credential binding preserves bytes and refuses; bearer/owner bytes are absent from the journal; explicit acknowledged dismissal survives restart. This simulates the acknowledgement loss after an actual engine response. It does not execute a native window or kill an engine during its transaction.

Native-window/human usability, non-Unix storage, installed Stash, learned-model/media quality, trusted publishers/rights, distribution, Handy and platform/release qualification remain open. Training and sterile evaluation were not rerun.

## Catalog intents and the newer journal barrier

[Desktop catalog workflows](PULSAR_DESKTOP_CATALOGS.md) extend this same runner/store to exact catalog refresh and catalog-bound selection. Client journal schema 2 is activated atomically with the first such intent; old entries are preserved and older clients refuse unknown state. Dismissal never lowers that barrier. Engine database schema 14 and portable format 9 remain separate boundaries. These additions do not renew historical catalog trust or restore generation authority from recovery history.
