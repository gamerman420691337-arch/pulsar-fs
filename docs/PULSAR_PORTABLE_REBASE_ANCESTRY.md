# Portable unchanged-motion rebase ancestry

Portable format 9 adds an optional `rebased_from` candidate identity in the manifest's own namespace. A rebase keeps motion, lineage, historical job identity, review flags and interval restriction unchanged; its current admission base can advance. Capture records native parent links explicitly. Clone planning translates parent identities alongside candidate identities. Re-export restores imported parent facts from the retained projection instead of guessing from content equality or dropping them.

Manifest validation requires an existing parent, identical motion/evidence/restrictions, nondecreasing admission base, and acyclic ancestry under the 128-step bound. Origin graph validation checks parent correspondence through the declared namespace maps; a clone cannot discard an original rebase fact or invent an unrelated parent. Older packages without sufficient facts remain unknown; matching bytes alone do not establish a historical rebase.

Archived publication ancestry follows an imported rebase's checked parent and retained admission base. Both must have the same ordered retiming history. The local candidate base must equal the immutable projection. Original imported generation anchors remain the publication selectors; this addition does not adopt an active historical job or make different clocks interchangeable.

Imported candidates cannot acquire a shadowing native SQL rebase link. The retained parent is authoritative for their ancestry; an unexpected local link refuses. The [attribution audit](PULSAR_REBASE_ATTRIBUTION_AUDIT.md) corrects an earlier receipt: the saved supposed pre-fix binary was identical to the corrected binary and passes the regression. Executable bytes for the original mixed-run failure remain unknown. An isolated offline build of the exact retained pre-fix production archive now reproduces acceptance of the forged link; the corrected pinned binary passes the same frozen fixture. Both binaries and the fixture remain byte-identical before and after their respective runs. Original logs and receipt bytes remain retained.

The first ready format-9 export or completed import advances the database reader boundary to schema 11 atomically with its stored record. Startup and existing archival publication preserve that barrier. Native-only subjects without new records retain their preceding version. Format 9 propagates through wrappers containing format-9 namespaces, including wrappers whose own candidate list is empty. Readers supporting at most format 8/schema 10 must refuse these subjects.

The [local receipt](evidence/roadmap-2026-10-01/portable-rebase-ancestry/validation.json) binds the final source and checks. Protocol and clone tests check missing/cyclic/changed parents, old-format refusal, translated parents and dropped correspondence. Native forward/reverse fixtures rebase an authored edit, re-export it, clone again, publish from retained clocks, refuse changed imported admission bases, restore the owned fixture, survive restart/replay, and refuse the preceding package/database reader. These authored fixtures do not establish model/media quality, installed Stash behavior, rendered GUI usability or Handy operation.

Mixed or differing retiming histories still need explicit piecewise correspondence. Different generation clocks, mixed live/archived origins, legacy missing facts and broader roadmap qualification remain open.
