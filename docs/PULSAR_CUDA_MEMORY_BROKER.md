# Supervised CUDA memory broker

Historical checkpoint: the subsequent [Engine CUDA generation integration](PULSAR_ENGINE_CUDA_GENERATION.md) enables configured explicit generation. The statements below describe this earlier subject and its verification scope.

Status at this checkpoint: PARTIAL. An internal confined probe now measures device-bound memory and can admit a fresh cooperative GPU claim while retaining its image/device owners. Production GPU inference jobs remain disabled.

The memory worker uses captured CUDA and NVML libraries after mounted-byte/device verification and a role-tagged sealed loader transition. It checks the runtime's real UUID, PCI address and logical ordinal, queries NVML by that UUID and checks the driver identity again. The authority process loads no supplier native libraries. Native initialization/query effects occur in the supervised child; this is not an inference session or a claim of zero driver memory use.

The probe performs its initial query and full image recheck before taking the final memory sample. The original final-query CLOCK_MONOTONIC start time survives transport and exact retirement; neither retirement nor admission renews it. An actual preceding run measured before the final hash and correctly failed as stale. A new API query after that work corrects the ordering while preserving the one-second gate. The parent rejects wrong request/device identities, malformed or inconsistent capacities, future/stale samples, trailing transport and failed exit, with bounded retained diagnostics and cancellation.

A typed asset handback returns the same image and device pins after confirmed users, staging cleanup and exact group retirement. The image remains charged to storage, avoiding a new multi-gigabyte capture between observation and admission. Admission rechecks loaded policy/profile/priority and captured declaration, derives conservative capacity from the smaller of the distinct CUDA/NVML totals, caps NVML free bytes by that total and enters the existing atomic accounting pool. The original API counts remain auditable. These observations and process-local claims do not exclude other GPU users, enforce total VRAM consumption or prevent capacity changes after a sample.

The native fixture uses 75 declared libraries (1,945,994,000 bytes on the tested host), actual NVIDIA node/module pins, the confined probe and a durable admitted group with a CPU claim. It verifies actual measurement, returned image/storage, a measured 64 MiB offline claim, refusal of a second offline claim, release, cancelled-probe cleanup and empty rosters. It does not establish committed Engine GPU-job admission. Deterministic cases cover identity/capacity/schema/freshness refusals; shipped direct roles refuse unconfined execution.
