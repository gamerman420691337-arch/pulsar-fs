# Annotated CUDA Stash batches

Annotated Stash batches now accept an explicit version-2 CUDA profile under a Linux CUDA-enabled Engine with an owner-configured policy. Admission validates the implemented annotated tensor recipe, exact thread/resource envelope, the Engine's pinned runtime, the declared device and the owner's offline priority ceiling before Stash discovery. This is intent admission: actual generation still requires supervised native capture, fresh device/resource admission, private verified worker bootstrap and strict candidate evidence. No provider substitution is introduced. Ordinary nonannotated batches retain their existing admission rules.

Use the existing `stash generate-missing` command with a file-backed model, its CUDA inference profile and the [per-source annotated-view catalog](PULSAR_ANNOTATED_STASH_BATCHES.md). Start the Engine with its private `PULSAR_CUDA_OWNER_POLICY` and matching `PULSAR_ORT_DYLIB`. A client-supplied CUDA profile cannot supply owner authority. Each selected source retains its own content hash, eye/projection and target declaration; replacement catalogs still require explicit observed-ledger migration followed by separate resume.
