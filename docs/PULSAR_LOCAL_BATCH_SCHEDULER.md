# Bounded retained local batch scheduling

`library-batch-run ID --publication-state DIRECTORY --steps N --poll-ms M` connects an already captured local audio batch to generation and per-entry publication. DIRECTORY must exist, be private/owned (0700), and belong to this workflow. Steps are 1..=1000 (default 1000); polling delay is 1..=1000 milliseconds (default 25). Intake still uses `library-batch-prepare FOLDER --audio-bundle-recipe RECIPE.json`, so source bytes and the checked recipe are frozen before work. The scheduler never reopens changed/deleted originals or changed recipe files to reconstruct intent.

Each scheduler decision advances the retained generation chain, observes its existing job, or attempts one ready entry's publication through the existing publisher. A publication attempt can include six exact export acknowledgements; a completed-job observation can precede its generation advance in the same decision. Report counters distinguish scheduler decisions, generation attempts, publication attempts and job-status polls. The step budget is not an overall wall-clock deadline; existing control and verification deadlines still apply. Budget exhaustion retains state and returns completed=false and budget_exhausted=true. Repeat the same batch/state command to continue. Engine restart dispatches no new work without another explicit command.

The scheduler's private journal is written before its first generation advance. Local reader schema 2 adds awaiting_generation while retaining source/destination/digest/length and already acquired project/source/job/candidate/effect identities. Generation may advance monotonically from the actual Engine ledger, but may not regress, change input selection, replace an acquired job/project/candidate or discard retained effect identities. Ready and published identities require exact correspondence. Schema-1 publication journals remain readable; standalone prepare/publish/status commands also consume fully ready schema-2 journals without downgrading them. No Engine database schema or neutral script format changes.

Ready entries publish before the scheduler starts later input generation. An earlier accepted receipt remains recorded if later generation or publication fails. Running/queued/assistant-paused jobs are observed through read-only JobStatus, rather than repeatedly caching durable generation-advance replies. Completed jobs advance the original chain; unsuccessful/interrupted or unrecognized states require attention and create no replacement job. A retained unresolved outer advance ID is reused exactly. Existing revision/grant/tool/source fences remain authoritative, and uncertain publication acknowledgement states retain the prior refusal rather than adopting files or creating another intent.

`library-batch-workflow-status ID --publication-state DIRECTORY` returns current authenticated Engine generation/job status alongside retained client publication history. It checks current identity correspondence without updating journal bytes, advancing generation or publishing outputs. Publication history can lag current generation until an explicit run reconciles it. Completion means the retained generation is ready and every selected entry has an accepted publisher receipt; it is not fresh destination existence/integrity proof or quality qualification. The Engine batch's publication_completed remains false. qualified remains false everywhere.

Release, cancellation and migration remain separate. Keep the Engine generation ledger while continuing this workflow. A failed source/job remains identified and requires explicit ordinary recovery or disposition; there is no implicit source replacement or new job. No continuous directory watcher, automatic intake, background daemon, new model selection, general snapshot/stage/journal garbage collection, unknown-acknowledgement disposition or human acceptance is supplied. Ordinary batch/scan syntax and their immediate behavior remain unchanged.

Status preserves journal bytes; invalid bounds, unsafe storage and a wrong-batch journal refuse before generation. All twelve scripts match preceding independent authored PCM/timing oracles after originals and recipe files changed.

The prior publication restart/conflict/exact-resume/lost-local-ack-state campaign and native controller regression remain separate checks. These are authored software inputs, not real-media/model, interactive GUI, non-Linux runtime, physical-device, physical-durability, human or release qualification.
