# Durable desktop removal recovery

Capture evidence now saves the exact removal intent before sending it to the Engine. The private `desktop-evidence-recovery` journal is separate from model-pack recovery. It records project, original revision, capture epoch, manifest SHA-256, request ID and an optional validated removal receipt. It stores no bearer or owner capability. Session and credential-binding checks plus an endpoint digest prevent another client namespace from silently adopting its entries. Engine authentication and current authorization remain mandatory on every retry.

Opening the panel loads recovery on the background worker, including when no project is open. It does not retry or remove anything automatically. **Retry retained removal** sends the saved intent unchanged. A new removal remains disabled until private recovery storage loads successfully. Browsing and artifact downloads remain available. Recovery can be reloaded explicitly after a storage or contention error.

An acknowledged entry shows its historical receipt and may be dismissed explicitly. Unknown outcomes remain retained; clearing the current retry selection does not delete the journal entry. The journal holds at most 64 entries within a 1 MiB bound and refuses new removals when full instead of evicting unknown requests. Acknowledged entries can be dismissed to reclaim capacity. A refused request without a durable Engine removal receipt remains unacknowledged; the client does not infer that an earlier attempt could not have committed.

Storage uses the existing pack-recovery filesystem discipline through a shared private storage module: owner-only directories and single-link 0600 regular files, no-follow opens, nonblocking process locks, bounded reads, synced temporary files, atomic rename and directory synchronization. Pack journal path and schema remain unchanged. Unsupported non-Unix storage fails before removal dispatch; this is not Windows qualification. Corrupt, oversized, nonprivate, symlinked, hardlinked or mismatched journals are preserved and refused.

If the Engine returns a validated receipt but saving it fails, the original intent remains recoverable and the client reports the acknowledgement error. Retrying uses the same request ID and original revision to obtain the Engine's durable receipt. Logical artifact removal is not physical erasure, and a local acknowledgement is not current device, model or release qualification.

Verification is recorded under [the recovery packet](evidence/roadmap-2026-10-08/desktop-cuda-removal-recovery/). Tests cover prepare-before-dispatch, lost acknowledgement, exact receipt correspondence, binding conflicts, corruption/private-file checks, bounded capacity, explicit acknowledged dismissal and unchanged pack-recovery behavior. The explicit process test kills an owned child with SIGKILL after durable preparation and restores the exact unacknowledged intent. The selected native desktop worker refuses a wrong hash, reopens a new panel, restores the intent without automatic replay, and retries the original request explicitly while preserving the authored capture. Successful Engine removal/replay retains the preceding scratch-handler evidence; these cases do not establish physical power-loss durability or every commit/network crash cut.
