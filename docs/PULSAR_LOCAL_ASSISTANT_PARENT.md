# Engine-owned local assistant execution

Date: 2026-10-10. Status: **PARTIAL; trusted Engine execution implemented; full roadmap INCOMPLETE**.

`Engine::propose_assistant` now runs one learned proposal under the Engine's shared resource pool and durable worker fence. This trusted Rust embedding API receives owner-supplied paths and an exact cancellation flag. It grants no client/session/project authority, effect approval, model selection or generation resumption. The desktop assistant remains disabled.

Before reading asset contents or reserving resources, the parent validates the typed request and its actual serialized 32-KiB transport bound. It opens no-follow regular descriptors for the configured worker, declared runtime and declared model, checks length/mode, reserves child RAM plus the complete parent image copies and bounded transport, then captures all three into write/grow/shrink sealed memfds. Capture checks hashes, source metadata, cancellation and the original deadline. Replacing source paths cannot change captured bytes. Executables are bounded to 128 MiB each; models to 2 GiB. Child RAM must include copied mounts plus at least 256 MiB of native-state allowance.

The same namespace/cgroup launcher mounts the sealed worker and runtime executable and read-only model at fixed guest paths. It clears the environment, retains read-only system libraries, isolates the network and bounds threads, memory, address space and private tmpfs. All images and the full admission claim enter worker custody before fallible command preparation or spawn. A durable ownership fence is committed before dispatch. Output is bounded to 8 KiB; identity and proposal scope are checked against the original request. Success requires whole-tree, owned-group and fence retirement, rather than direct-child exit alone. On failure, unresolved retirement retains custody and admission in the existing reaper.

One parent deadline begins at API entry and spans capture, launch, transport and completion. The child receives only the remaining duration. Capture and database/filesystem syscalls are not preemptible; these checks do not qualify hard end-to-end host-I/O deadlines. Error cleanup observes retirement for a bounded two seconds. Ambient system libraries are not a captured dependency closure. Worker exit failures currently return bounded status, not a published diagnostic transcript.
