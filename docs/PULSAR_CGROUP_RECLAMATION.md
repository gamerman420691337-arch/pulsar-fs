# Journaled reclamation of recorded Linux cgroups

Status: implementation connected; 482 engine tests pass with native cases included. The application reader migration/refusal check passes; 930 workspace cases and 469 CUDA-feature engine cases pass; all 104 configured JavaScript cases pass without skips.

Host-local worker-fence format 2 separates active groups from retirement tombstones. A canonical version-1 ledger is read with its original strict layout; its scope and lease identity are preserved when migrating. Unknown versions, malformed/noncanonical data, missing version-2 fields, overlapping records and excessive combined record counts refuse. Database schema remains 17 and portable format remains 9. A preceding version-1 fence reader cannot interpret version 2; the retained source-bound reader demonstrated positive version-1 opening followed by version-2 refusal without changes to committed database, WAL or ledger bytes.

The existing guard still requires direct-child reaping, transport-thread completion and an empty held cgroup. It then commits the group's exact retirement identity before removing its directory and clears the tombstone only after removal. A clear failure keeps admission and ownership with the reaper. Peak memory is observed before removal and retained in the held group object so completion receipts do not substitute a fabricated value after kernel files disappear. An acknowledged reclaimed group cannot be spawned again by its custody.

Startup validates the complete active and retired roster before cleanup. A missing active path refuses. A durable tombstone may recover an absent path, after validating the current owned cgroup-v2 parent. Existing recorded directories require the original device/inode and bounded empty-population evidence. Populated or replaced groups refuse without signaling or partial cleanup. Startup never enumerates unrelated directories or signals a recorded process. It commits retirement identities before deletion and clears them after reclamation.

Native fixtures explicitly seed valid cuts in the production retirement-marker helper before and after directory removal. They are journal-boundary fixtures using real owned cgroups, not actual process-crash or power-loss execution. Separate fixtures cover missing active records, replacement refusal and a populated tombstone preventing cleanup of another empty group. The focused native checks passed, including the retirement-directory and capacity-release assertions. These do not establish exhaustive crash behavior. The application-reader check passed; Workspace/feature checks pass; all 104 configured JavaScript cases pass without skips. Source/build/test identities and completed checks are retained under `docs/evidence/roadmap-2026-10-01/cgroup-reclamation/`.
