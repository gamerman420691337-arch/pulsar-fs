# Handy RPC error correlation

Status: **IMPLEMENTED / focused checks PASS / physical qualification UNKNOWN / roadmap PARTIAL**.

The previous offline stop decoder returned `RemoteError` as soon as a response error field appeared. It had not yet checked the request ID or remaining response envelope. The regression reproduced a stale ID 2 error being classified as a remote error for outstanding request ID 1: `left: Err(RemoteError)`, `right: Err(MismatchedId)`.

The decoder now consumes and validates the entire response envelope before reporting its error. The exact request ID is required for remote errors as well as successful replies. Duplicate IDs/errors, unknown trailing fields, an error combined with a typed result, and truncated keys refuse. Error fields may precede or follow the ID. Error payload bytes remain opaque and are discarded without being exposed; the change validates envelope structure and correlation, not the internal vendor error payload. Session binding and outstanding-ID ownership still belong to a future authenticated transport.
