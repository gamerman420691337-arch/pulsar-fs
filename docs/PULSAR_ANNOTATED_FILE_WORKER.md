# Source-bound annotated file generation worker

The file worker now applies annotated eye/projection/region preprocessing before temporal inference. Explicit `annotated_temporal_view` profiles require `GenerationSettings.annotated_view` with a source SHA-256 and the existing annotated declaration. Whole-frame profiles retain their earlier meaning; there is no metadata-driven fallback.

The worker checks source content and encoded dimensions, admits intermediate buffers, and uses the same native numeric planner as training. The request-owned CPU adapter validates named tensors and exact recipe/intake metadata before execution. Schema-3 lineage retains the complete plan, source-bound settings, transform digest, model contract and training-intake digest. Static regions do not establish tracking or target identity.

The authored native test decodes a stereo file with a deliberately different left eye and right-eye borders. All 28 selected frames match the retained Python input bytes exactly. All 14 intended estimates match the retained Python positions within 1e-6, with original frame ordinals and 125ms sample times. Invalid encoded geometry refuses before native session/artifact creation. This demonstrates worker correspondence on authored data, not real generation quality or a qualified sandbox/device workflow.

Public Engine generation is deliberately still disabled for this mode. Engine submission refuses before model snapshotting or job publication; internal attempt preparation, generic profile admission used by Stash batches, and offline/selected model packs also refuse it. CUDA and raw/live profile substitution refuse. No database or portable format is migrated, and current portable imports refuse the new receipt schema. First-party client controls are not yet implemented. See [ADR B2-006](../research/phase-b/ADR-B2-006-source-bound-annotated-file-worker.md).

The [checkpoint](evidence/roadmap-2026-10-08/annotated-file-worker/checkpoint.json) records final gates and source/archive correspondence. An initial native test compilation referenced the wrong decoded-pixel field; this was corrected to `pixels` before execution. Existing warnings are retained in gate logs. No Python training code, live/sterile inputs, existing models or historical datasets changed; no physical device was actuated.

Final checks: 1,068 serial workspace tests pass (60 ignored), 81 CUDA-feature worker tests pass (three explicit fixture cases ignored by default), the new native CPU file test passes separately, and the default binary builds. All 278 architecture checks and 36 source guards pass. The active source archive/readback covers 382 records: 370 preceding records unchanged, nine existing paths changed and three added. Python tests were not repeated in this cohort; the authored expected positions remain bound to the retained prior Python fixture. These gates do not establish annotated CUDA execution, public Engine generation, portable closure or real learned quality.

Next: implement durable reader barriers and bounded startup/retry validation, then exact receipt/origin correspondence for portable import/export. Remove Engine guards only with those gates passing, add explicit CLI/desktop selection, and exercise the actual public path. Real annotations/alignment, useful learned quality, Stash/product closure, platform, Handy, human and release acceptance remain open. Roadmap status: PARTIAL.
