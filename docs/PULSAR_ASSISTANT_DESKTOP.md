# Local assistant in the desktop

The Doctor tab now exposes the authenticated local assistant. Open a project, refresh local models, select an owner-registered profile and enter a request. **Save request for review** writes a new private start intent without running inference. Review the captured prompt/model/request and separately approve local inference before starting. The saved path also works with the assistant CLI.

Start and reconciliation use the original saved request ID, project revision and complete profile. The desktop captures a semantic digest and refuses changed intent contents before dispatch. It reads one checked intent into an owned value, then dispatches that same value; it does not reread a replaceable file between checking and submission. Inference approval, private-file rules, endpoint/session/credential namespace and project/revision checks apply independently. Existing files are never overwritten. Failed or uncertain writes remain on disk for explicit recovery; there is no automatic inference or deletion.

The panel uses a separate bounded channel and RPC thread, sharing the normal SessionClient and engine protocol. It displays Running/Completed/Failed/Cancelled/Interrupted states, polls a visible Running attempt once per second, supports explicit cancellation, lists retained attempts and displays returned proposal JSON. Read errors stop automatic polling. Cancelling and cancellation retries do not require inference approval. Start retries require approval and retain the exact prepared work. Read-only model/list/status refreshes preserve an unconfirmed mutation, and preparing/restoring/starting another request is disabled until the current retry is confirmed. Errors remain conservatively pending. Explicit start resolution now recovers an accepted attempt or permanently withdraws an unpublished original ID; see [resolution semantics](PULSAR_ASSISTANT_START_RESOLUTION.md). Restart-persistent cancellation reconciliation remains open. No model/runtime library, engine implementation, project database or device driver is linked into the client.

Changing project or revision clears disposable proposal/profile/approval state. Replies bound to the previous view do not update the new view. The saved path remains available for explicit restore, which checks the current namespace and project. Historical revision metadata can be restored for resolution; Start still requires the current revision. A retained attempt from an earlier revision can be inspected through the list and is visibly marked stale. Closing the panel or desktop does not implicitly cancel engine inference or remove a saved request.

Current Engine context offers sample stride for a future generation request, plus no_action. It does not yet offer observed targets, review entries or approved edit recipes. This panel displays proposals; it does not apply an edit or generation setting, generate motion, drive playback or authorize device movement. Approved effect dispatch, protected history/undo and checkpoint/assistant/resume remain roadmap work. Installed offline models and default selection remain unqualified.
