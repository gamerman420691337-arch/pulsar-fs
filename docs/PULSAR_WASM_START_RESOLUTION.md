# Authoritative resolution of unknown WASM starts

Status: scoped software and explicit native checks PASS; full roadmap PARTIAL.

An absent operational catalog cannot settle a lost start acknowledgement. ARCH-047 adds explicit ResolveWasmStart with bounded captured reference metadata: original request ID, project revision, manifest, worker, guest memory and label. It requires the owning session's current Read and Edit authority. It carries neither module bytes nor execution approval.

Under one immediate SQLite transaction, resolution first finds the owning project's retained original invocation. All reference metadata must match. If accepted, it records the observed report without cancelling work, committing a candidate or mutating master. Exact resolution replay returns that recorded historical outcome; use status for subsequent progress. This also discovers archived accepted invocations.

If no accepted invocation exists, resolution checks the actor's global original request-ID namespace. A free ID is permanently reserved with a distinct domain-separated digest of project/reference metadata. The reservation and resolution acknowledgement commit together. A delayed start, including one already past preflight, must recheck that namespace in its publication transaction and refuse. An occupied unrelated namespace, removed accepted row, changed reference or missing original revision refuses; absence alone is never advertised as withdrawal. A repeated matching reservation returns the same withdrawn outcome. No original invocation, artifact or accepted request record is deleted. No storage schema or portable format changes; existing readers already implement the original-ID fingerprint fence, which the exact preceding executable is exercised against.

The desktop reuses the already durable private start journal. A schema-1 metadata-derived resolution ID survives reconnect without another journal or automatic dispatch. Only an explicit action queries resolution. Accepted results acknowledge the original attempt. A checked unpublished withdrawal permits removal of exact unknown local facts; unsafe storage or changed facts refuses local settlement. If the server acknowledgement or local publication is lost, original facts stay unknown and explicit retry uses the same resolution ID. Restoring facts grants no pending action, approval, executable bytes or commit authority. Independent acknowledged start records remain intact.

CLI wasm-edit resolve-start requires a project, bounded reference JSON and an explicit resolution request ID. Reference JSON contains original_request_id, base_revision, manifest, worker, guest_memory_bytes and label. The resolution ID must differ from the original. This command may permanently withdraw an unpublished ID; accepted work remains unchanged and requires separate status/cancellation/review. The desktop states that distinction before the action.
