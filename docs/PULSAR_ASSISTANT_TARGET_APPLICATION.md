# Assistant target application

Status: PARTIAL full roadmap progress; qualification INCOMPLETE.

After an ordinary detector preview, query `pulsar assistant targets PROJECT` or refresh observed targets in the desktop assistant panel. Prepare an inference request with up to eight exact target IDs (`assistant prepare ... --target-id ID`, repeatable). The Engine resolves only the authenticated session/project catalogue at the current revision, captures the full recorded frame/model/observation/source/view facts into bounded assistant context, and offers those IDs to the proposal decoder. Empty target focus preserves the previous context and omitted wire-field bytes. Duplicate, missing, stale or excessive focus and contexts over 8192 bytes are refused; facts are never silently truncated to fit.

A completed `select_target` proposal requires separate generation approval. The Engine recomputes current context and proposal digests, checks original owner/project/revision/Engine lifetime, and resolves the retained target again. It derives the unclassified observed box-centre seed and captured video view. A different source, an existing seed, annotated view, placed generation or an explicitly competing video view is refused. Ordinary generation validation still requires a declared detector contract, compatible sampled-frame lattice and normal model/worker capture. Caller model selection and inference options remain explicit; the preview observation is not proof of the future model's quality. Application is checked both before preparation and in the job publication transaction.

CLI immediate generation and saved generation support stride and target proposals. Private saved schema 1 keeps legacy numeric stride JSON byte-compatible; target intents omit the stride field and record exactly one target ID. The displayed proposal must hash to the retained approval digest. Restore resets desktop approval. File review remains pinned by semantic digest; dispatch reloads and checks the same original complete command, revision, request ID and credential namespace. Desktop target refresh is read-only and cannot displace a pending mutation. Generation retries use the generation approval checkbox. Accepted job responses continue through the existing candidate/review/protected-commit handoff.

New preview completion, eviction or restart can expire a target proposal even at the same project revision. An exact historical retry can recover an already accepted job through the existing receipt path; a new request must pass fresh validation. Saving an intent preserves retry identity, not ephemeral observation availability or future model bytes.

Native learned end-to-end assistant/target generation, undoable assistant recipes, checkpoint/resume, installed/offline defaults, source-matched annotations/training, platform/media/Handy 2 Pro/human/release gates remain open. No annotations were fabricated. Sterile references remain evaluation-only; live references remain permitted training material.
