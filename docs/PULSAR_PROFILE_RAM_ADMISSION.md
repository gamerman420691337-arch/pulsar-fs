# Profile RAM admission

Generation, preview and live inference now use a shared private RAM admission function. A fresh request receives the larger of the existing 1536 MiB baseline and its declared model minimum, within the configured owner pool. The actual generation/preview reservations use that same claim. A model asking for 3 GiB can therefore reserve 3 GiB in a 4 GiB pool; another overlapping 1536 MiB claim refuses until the reservation retires. The catalog reports the owner ceiling, with the floor and aggregate limitation disclosed.

CPU limits and output classes are not expanded: ordinary generation retains two CPU threads and 64 MiB output, preview retains two threads/8 MiB, and live keeps its existing provider-specific CPU/output limits. Original wall times and CUDA arena/device/address-space rules remain independent. A retained resume budget is copied exactly, then checked against the profile and current owner limit. Insufficient retained RAM refuses rather than being silently repaired. A smaller new owner pool refuses rather than shrinking a captured attempt.

The tests bind 3 GiB to the durable attempt manifest and aggregate token, verify release and refuse over-owner claims before job/attempt/output creation. Metadata cases cover CPU/CUDA sizing, exact retained serialization and CPU/output refusal. They do not run the non-executable model identity fixture. The real pinned YOLO11 CPU harness separately passes Fast, Default and Maximum with a deliberately enlarged 2 GiB declaration, four inferences per tier and an assertion on each Engine manifest's RAM claim. The final native CUDA Default run also passes with the same 2 GiB declaration: four inferences and 956 CUDA computation events, with receipt/candidate/trace identity binding and worker retirement checked. The final CPU run uses the newly built worker and passes in 2.10 seconds.

The first aggregate test caught that the reservation still used 1536 MiB after the manifest had grown; both reservations were repaired. The first full suite found the catalog's stale 1536 MiB expectation; its assertion now verifies the owner's 4 GiB ceiling and unchanged CPU/output limits. One host-filesystem test timed out while its test thread waited in `jbd2_log_wait_commit`; the longer bounded run passed, and the full library runs use private RAM filesystems. Those different timings are not model-speed evidence. The initial CUDA launch refused a copied policy's public file mode; the owned test policy was made private, preserving the startup guard.

Final checks pass: default Protocol 123, Clients 253 (5 ignored), Engine 824 (63 ignored); all-feature Engine 838 (89 ignored); default and all-feature strict Clippy, workspace binary build, formatting, 401 architecture checks and 36 source guards. Ignored and unrun qualification cases stay open.
