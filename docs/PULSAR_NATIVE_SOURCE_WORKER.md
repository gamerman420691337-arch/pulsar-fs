# Bounded encoded-source worker role

The private `capture-worker` role now accepts one bounded engine manifest followed by an encoded byte stream. It emits scoped readiness, fixed-size timestamped RGB frames and an exact intake-hash completion record. The subsequent [parent source launcher](PULSAR_PARENT_SOURCE_LAUNCH.md) establishes private snapshots, aggregate resource admission, confinement, stateful output acceptance and independent supervision. The subsequent [authenticated encoded adapter](PULSAR_AUTHENTICATED_ENCODED_INGRESS.md) now launches it for capture leases, streams authenticated encoded input and publishes immutable clock/body facts with an explicit delivery age basis. Direct camera acquisition and continuity remain open; `native_acquisition` remains false.

The strict manifest declares the complete capture identity, worker attempt, exact FFmpeg/worker artifact identities, explicit YUV4MPEG2/NUT/Matroska demuxer, resource budget, input-byte limit and frame limit. There is no automatic format guess or arbitrary FFmpeg argument string. Input is at most 512 MiB, output is at most 9,000 fixed 64x64 RGB frames, lifetime at most thirty seconds and CPU threads at most two; the caller must additionally bind those limits to its actual aggregate/platform admission. The role verifies FFmpeg bytes before launch. A confinement environment marker rejects accidental direct invocation; it is not evidence that the parent actually established confinement. Other platforms return unsupported. Tool/runtime redistribution and platform qualification remain separate.

Linux entry reads the framed manifest from an owned unbuffered, close-on-exec stdin descriptor duplicate. It cannot prefetch and lose encoded bytes at the manifest/body boundary, and the original intake duplicate is not inherited by the native consumer. The encoded forwarder polls that owned descriptor every ten milliseconds, checks absolute lifetime/cancellation, bounds reads and writes fixed-size chunks into the owned native decoder pipe. At the input limit it can read at most one extra byte to detect excess and refuses without forwarding it. Completion retains SHA-256 and byte count of the exact complete forwarded stream. Empty, excess, incomplete or failed intake cannot produce successful completion. Native network/file protocols are not admitted for encoded input; only the forwarded pipe is exposed to FFmpeg.

The native process uses the [timestamp-bound decoder](PULSAR_TIMESTAMPED_NATIVE_DECODE.md), explicit demuxer, bounded initial probing, strict decode-error handling and per-packet sink flushing. Ready precedes forwarding. Each framed output carries exact source rational PTS, selected decode ordinal, verified fixed RGB identity and worker-relative stdout-delivery elapsed time, followed by exactly 12,288 pixel bytes. Reply validation checks full identity/attempt, limits, artifact and lifetime. It does not replace stateful parent checks for sequence, pixel bodies, source/clock progression, ready/frame correspondence, completion counters or fresh lease authority. The same bytes can be framed for transport without becoming model or device authority.

Delivery elapsed time includes time since worker initialization but is not camera exposure time or an engine lease-clock sample. A future engine adapter must conservatively bracket worker/engine clocks, retain the age basis, and keep source/decoder buffering visible. Copying decoder delivery time onto a physical-capture claim would omit real acquisition/decoding delay. No calibrated source/player clock, capture-to-command latency or physical response follows.

On failure the worker cancels intake, closes/reaps its native consumer, joins its owned forwarder and emits a bounded typed diagnostic when possible. Native consumer cancellation breaks blocked writes; source polling observes cancellation even while idle. The subsequent parent launcher supplies an independent process/cgroup watchdog and poisons ambiguous transport rather than retrying or rearming. Output failure and resource/lifetime admission cannot be treated as source completion. Parent child/worker reap and physical stopping remain different acknowledgements.

Native authored tests verify explicit YUV4MPEG2, FFV1-in-NUT and FFV1-in-Matroska intake, exact complete-stream hashes and RGB packet hashes, source PTS, wrong format/tool bytes and intake/frame-limit refusal. A real unknown-length source emits three framed pixels while its producer remains open; EOF cannot substitute for streamed output. These direct worker-adapter tests do not establish production confinement. The compiled CLI separately refuses accidental unconfined role invocation. A deliberately unconfined child-role fixture sets the marker solely to exercise the actual stdin manifest/body boundary, framed RGB replies and exact intake completion hash; its retained report explicitly records `confined: false` and no lease integration or physical dispatch. Ordinary admitted confined finite/inference paths remain regression-tested. Model weights, training and the prior negative sterile evaluation are unchanged. Live source admission, continuity, actual camera/media/clock/model/GPU/Handy/physical/platform/human/release qualification remain open.

Native build and diff checks passed. Exact request/reply bytes, source/manifest and the explicit unconfined report are retained alongside final capture CLI traces and historical intermediate logs. These gates do not establish lease source launch or real acquisition/confinement/physical qualification.
