# Durable custody for live Linux workers

Status: ordinary and live Linux ownership is locally demonstrated; full lifecycle qualification remains incomplete.

Authenticated capture admission arms the existing schema-17 worker scope in the receipt transaction when inference or an encoded source is requested. Before native launch, inference checks current capture authority and scope; encoded-source admission checks its bulk authority and scope. Engine callers pass the durable fence into their actual persistent workers. Public standalone fixture constructors retain process-local confinement and custody without claiming engine restart protection. Portable format remains 9.

The common worker guard owns the child handle, held cgroup, admission, staging directory and transport/watchdog/diagnostic thread handles before fork. It registers the group before spawn and retains ownership on registration, spawn, transport and retirement failures. Retirement requires child reaping, observed transport-thread completion, an empty held group and durable roster clearing. Staging ownership drops before the admission reservation. Failed staging-directory deletion and orphan reclamation remain independent storage obligations.

Watchdogs signal only their held cgroup and poll their direct child for up to 250 ms without blocking child waits. Closing a worker disconnects its channels and polls confirmed retirement for up to 250 ms; unresolved ownership transfers to the existing reaper. The encoded-connection reader retains its worker guard when detached. Successful decoded-source completion checks confirmed retirement before publishing completion facts. Host filesystem/control IO still lacks an independent wall deadline; these polling budgets do not qualify all host IO.

The new native staging/transport case initially found admission release before staging cleanup. Reservation field order was corrected; the unchanged assertion passed. Initial focused application checks also exposed unreaped idle-expired children and an incorrect raw-UUID roster assertion. Watchdogs now poll reaping, and roster assertions use the actual cgroup key. The idle-reaping assertions and existing timeouts remain unchanged. Evidence is retained under `docs/evidence/roadmap-2026-10-01/live-worker-custody/`; earlier checks and failed subjects remain separate from final current-source gates.
