# Engine-owned private live CUDA startup

The Engine now has a private startup path using its authenticated capture intent, configured owner policy, actual resource pool and committed worker fence. It captures the native image and stages the pinned worker/model under the original lease, observes CUDA/NVML memory, admits interactive GPU resources and starts the persistent stream. It creates no offline generation job. Boot, model/profile/clock/lease declarations and project revision are checked; authority and fence binding are rechecked after preparation and GPU observation. Native work occurs outside database/registry locks.

The relay deadline is conservatively converted from the original local lease end. Sampling CLOCK_MONOTONIC before the remaining `Instant` interval prevents conversion overhead from extending the lease. The focused clock check verifies that decoding cannot produce a later local end and that expired/oversized/invalid budgets refuse.

An authored native test calls this private Engine path directly with runtime-owned RGB work. It does not enter the public capture registry or route through `Engine::handle`. Using the default two worker slots and captured 75-library image, it completes three exchanges through one loaded CUDA model and verifies consuming Finish. Independent readback reconstructs manifest/transcript identities, checks overlapping frame pixels/clocks and the authored oracle, and verifies three model runs/nine CUDA computation events in the original trace. It confirms the frozen worker identity, zero offline jobs and complete custody retirement. Boot/clock mismatches and cancelled startup preserve the pre-start fence bytes and reserve no capture storage.

The original 30-second lease includes native capture, snapshots, GPU observation, model startup, the three exchanges and final retirement. The native fixture completed that span in 14,526 ms. Its capture/completion frame ticks are authored, so this does not measure product capture-to-command latency or six-axis/model quality.

The [evidence packet](evidence/roadmap-2026-10-07/engine-live-cuda-start/) retains initial and corrected source subjects, the frozen CUDA worker, declared inputs, raw receipt/trace/exchanges, independent readback and regression logs. The first native attempt refused before capture because its test budget allowed 16 MiB output while the profile required 64 MiB. The corrected fixture respects the declaration; no production admission was weakened.

Final gates pass 997 workspace tests serially (54 ignored), 526 CUDA engine tests serially (53 ignored), both explicit native live/offline scenarios, four CPU live application cases, five shipped CPU regressions, the default build and 260 architecture checks. The nine application cases have no skips. All 347 archived/live source records and 80 declared native/model inputs match after execution. The frozen worker's production source is unchanged between the refused and corrected fixture subjects; only the native test budget/diagnostic changed.

Public GPU live remains disabled. The next integration must bind startup to actual capture-registry membership, complete work against the real runtime clock, expose provisional results honestly, finalize/persist evidence and handle explicit stop, expiry, revocation and continuation. Derived-anchor continuation is deliberately not accepted by this private helper. Cooperative preparation accounting, blocked host-I/O/crash coverage, unresolved parallel failures, fastest-preset six-axis/latency and model/media, Handy/platform/human release gates remain open.
