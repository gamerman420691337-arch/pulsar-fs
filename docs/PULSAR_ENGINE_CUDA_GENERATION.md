This does not qualify a model or release. CUDA Preview and automatic interrupted-job GPU recovery remain unavailable.

Preparation selects the explicit generation or model-pack profile, verifies owner/runtime/resource correspondence and requires captured NVML. Failed or replayed publication drops the local owner into checked cleanup.

Queued work carries the owner rather than resolving its image from a pathname later. Dispatch atomically moves the job and attempt to running and checks the immutable CUDA intent/current engine epoch. The queued CPU claim powers the supervised memory observer; its RAM/job slot retires before fresh cooperative GPU admission. The existing output-storage charge is split and transferred into the new GPU reservation without being released or counted twice. The same admitted claim remains referenced through ordinary completion parsing and candidate acceptance. Captured image/device/mount lifetimes continue through shared worker retirement and its reaper.

The existing completion path verifies original CUDA receipt/trace bytes and their exact request/profile/device binding, then retains evidence membership with the generated candidate. A generated candidate is not human acceptance or permission for physical playback. Reopening preserves accepted evidence and marks pending work interrupted. Automatic recovery continues to skip CUDA; explicit Resume requires the same owner policy, validates the old checkpoint/dependencies, captures a new image and declares a new attempt in the current engine epoch. It never reuses the vanished prior image or promotes old intent into fresh admission.

The catalog advertises CUDA only for an enabled build with worker confinement, matching startup owner/runtime policy and declared NVML; qualified profiles remain empty and the Preview/recovery limitations remain explicit. Selected model-pack validation has the same configured-profile checks, but native selected-pack CUDA execution is not separately qualified by this checkpoint.
