# Selected model packs in retained local library batches

A visual library recipe can declare `model_pack` with the exact `manifest_sha256` and `selection_revision` of the current owner selection, and `model_path: null`. CLI `library-batch-prepare --visual-recipe` and desktop JSON intake share this contract. Import is inert; the batch does not select or approve a pack. File models and packs are mutually exclusive.

Preparation uses ordinary selected-pack admission to bind the checked profile, model, manifest, profile document and original selection approval. It captures selected sources and retains separate model/document memberships. The final transaction checks the selection fence again. Retained settings include the admitted profile and tensor contract. Future generation submits GenerateFromModelPack using the original choice and settings; it cannot fall back to a loose model path. Fresh admission repeats installed integrity, current selection, profile and resource checks. Captured model/document corruption also refuses before generation.

Deactivation affects future admission. Already accepted jobs retain their ordinary immutable job inputs and can finish. A waiting phase retains its old choice, request and error. Selecting the same digest with a new revision does not renew that phase. [Explicit stopped-batch migration](PULSAR_LIBRARY_MIGRATION.md) now captures a linked successor; disposition of unknown acknowledgements remains unfinished.

Release removes owned memberships, not media, models, project history or published outputs. The release membership count includes sources, the model and three pack documents.
