# Shipped-engine staging crash recovery

Status: three selected Linux engine/CLI crash scenarios pass with authored CPU fixtures. This closes those scenarios, not the full creation/identity/retirement/clear crash matrix or roadmap qualification.

The [test](../scripts/staging-engine-crash.test.mjs) starts the shipped engine in a new private state directory, creates an authored temporal model/profile and project through the CLI, and starts actual confined live inference. It independently checks schema 19, minimum ledger version 3, matching scope, exact staged input hashes and the recorded directory identity. No hardware commands or real-media training/evaluation are involved.

| Scenario | Cut and observed recovery |
| --- | --- |
| Failed deletion after retirement | Remove directory write permission, stop the live lease, confirm a retirement tombstone and empty recorded cgroups, then kill/reap the owned engine. Restart exits 1 before a listener, preserves database/WAL bytes and retains the staging obligation. Restoring permissions permits checked deletion and recovery. |
| Replaced root after retirement | Move the original root aside, install an authored replacement canary, stop the lease and kill/reap the engine. Recovery refuses the changed inode before mutating database/WAL or fence bytes. Restore the original directory; recovery removes only the recorded root and preserves the replacement canary. |
| Owner killed during running inference | Confirm a bound root and populated worker cgroup, then kill/reap the engine without stopping its lease. Before any recovery opener can reclaim cgroups, directly observe the captured cgroup identities becoming empty. The bound journal record persists until recovery. Blocked deletion then refuses admission; restored permissions permit recovery. |

Each recovered engine retains its scope and reader requirement and has empty staging, active-group and retired-group maps. Old epoch status refuses. Reusing the CLI start request ID either refuses or returns an inactive response, and does not rearm observed staging/worker ownership. These are CLI retry checks, not an exhaustive raw-protocol replay proof. Only direct engines created by this test are signaled/reaped; the active-case worker retirement is directly observed without group signals.

The [evidence packet](evidence/roadmap-2026-10-07/staging-engine-crash/validation.json) retains final commands/results, private fixture locations, exact directory/cgroup identities, before/after database/WAL and fence hashes, staged-source hashes, refusal errors and recovered rosters. The production source and native worker/runtime are unchanged from the [format-3 integration subject](PULSAR_STAGING_FORMAT3.md). Its 964 workspace and 502 CUDA-feature passes remain evidence for that exact production subject; Rust suites were not rerun for this verification-only increment. All 316 archived/live source records match, including the 315 unchanged preceding records and the new crash test. All 236 structural checks, JavaScript syntax and diff checks pass. The pinned worker/runtime identities still match the preceding integration. No authored fixture databases or authentication material are copied into the evidence packet.
