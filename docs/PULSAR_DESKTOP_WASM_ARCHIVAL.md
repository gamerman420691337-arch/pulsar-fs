# Desktop completed WASM archival recovery

Status: bounded desktop/controller and actual IPC increment PASS; full roadmap PARTIAL.

The desktop exposes explicit archival of an observed completed WASM invocation. It captures project, attempt, original start request, a new archive request ID, observed revision, candidate and the full receipt before dispatch. Checked acknowledgement must match that complete snapshot. Engine archival retains invocation evidence, candidate and master while hiding the operational catalog row, as specified by ARCH-046.

The private desktop-wasm-archive journal publishes intent before sending. Unix storage uses the shared private-recovery helper: owner-only directories and regular single-link files, no-follow access, nonblocking locking and atomic synced publication. Admission is bounded at 64 entries, 1 MiB per journal and 16 KiB per intent. Endpoint, session and credential digest bind the journal; credentials and execution bytes are absent. Unsafe, malformed, competing unknown or full storage refuses before dispatch.

Fresh controllers restore facts only. They restore no pending action, selection, draft, execution approval or automatic dispatch. Retry requires an explicit action in the owning project and reuses the original archive request ID. An absent operational catalog does not acknowledge an unknown archive. Only a checked response permits local dismissal. Setting aside an in-memory pending action retains the journal and server state. Acknowledged recovery entries offer protected candidate opening through the existing review flow; they grant no commit authority.
