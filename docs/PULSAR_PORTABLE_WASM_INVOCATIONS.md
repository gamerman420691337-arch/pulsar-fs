# Portable WASM invocation evidence

Status: targeted local implementation and lifecycle checks pass; GB-12 and release qualification remain incomplete.

Portable format 12 adds an optional inert invocation record to authored edit lineage. It retains the original attempt/request identifiers, engine epoch, original candidate/base revision, Editor manifest and resource declaration, approval declaration, native worker identity and execution receipt. The referenced module and original guest input become declared package objects. The guest output remains the existing core edit input object, and the core receipt remains unchanged. Rebased candidates can retain the same original invocation through their shared core receipt.

Capture reads these records and bytes inside the same authenticated SQL snapshot as the project graph. Hash, byte and metadata bounds remain enforced; module/input bytes count toward capture admission. Source manifests with no plugin evidence retain their existing serialization and format version. Imported origin manifests retain original identifiers and bytes rather than being rewritten as current execution records.

Import checks module/input/output hashes, the original input against base revision values, and the output against the existing edit kernel. The recomputed program, authored/inherited ranges and provenance must agree with the candidate and core receipt. The importer never compiles or executes the module, restores a WASM operation, installs a native worker, adopts an old grant or treats an old approval declaration as fresh authorization.

Formats containing these facts, including later exports referencing an original format-12 manifest, require the format-12 reader. Completed export/import publication arms a schema-25 barrier above the existing annotated and CUDA/storage barriers. Each preserved layer is validated before delegation. Stripped markers and changed layouts refuse; older engines must refuse the new database before writable startup effects. Format declarations alone are not possession, provenance truth or release qualification.

Native worker identity is retained as historical metadata. This does not package the captured native executable or its runtime libraries, establish original execution authenticity, grant new execution authority or close native runtime qualification. Current execution still requires fresh approval and matching current native/module bytes.

Operation cleanup, GUI approval/status, processor/native extension roles, runtime closure and broader adversarial/crash/resource qualification remain required. Media/model quality, platform, physical Handy and human/release gates remain open.

The explicitly run Linux fixture executes a real authored WASM editor, captures its candidate and verifies module/input/output corruption refusal, worker-identity mismatch and missing-module refusal. Authenticated upload/import, clone/restart/re-export/second clone and nested-origin retention pass. Imported projects contain no WASM operations or workers. The pinned older executable refuses the new database without changing committed database/WAL bytes; modifying a retained module also prevents current restart without committed writes. These checks use engine handlers and package endpoints directly; they do not qualify rendered GUI or a socket transport campaign.

The final run passes 216 protocol tests, 11 storage-barrier regressions, one explicitly executed lifecycle fixture with zero ignored, 313 architecture checks, 36 source guards, scoped formatting and both application feature checks. Earlier frame-codec (17) and capture-review (6) regressions also pass. The actual fixture took 2.09 seconds, which is not a product benchmark or hard host deadline claim. Engine test compilation reports 27 warnings; each application check reports 37. Full workspace, Clippy, formal, platform, real-media, device and human/release gates were not run for this increment.

The [checkpoint](evidence/roadmap-2026-10-10/portable-wasm-invocations/checkpoint.json) retains the initial runtime restart failure and its version-delegation repair, compilation/type diagnostics, protocol compilation timeout and long temporary Unix-socket path failure. The latter was resolved by a short disposable test directory, without changing production path guards. Original approval and worker declarations are historical claims, not cryptographic execution attestation. Native worker/runtime bytes are not packaged. The architecture-first goal remains active.

[Catalog discovery and unsuccessful-attempt removal](PULSAR_WASM_CATALOG_RECOVERY.md) now recover retained original request IDs and explicitly remove retired failed/cancelled/interrupted operations under current Read+Edit authority. Completed invocation bytes remain protected and still count against the 64-operation limit; separate durable candidate evidence and broader retention policy remain open.
