The full application campaign and all engine crash cuts were not rerun or qualified by these targeted checks.

Format 3 requires a staging map keyed by canonical `pulsar-stage-UUID` names. Each record binds the private canonical parent, parent identity, creation intent and subsequent root identity/retirement phase. The map cannot be omitted. Format 2 remains canonically readable without this field; the schema-19 minimum-ledger requirement refuses a downgrade for a staging-enabled engine. Startup inspects only this private ownership directory and refuses staging-prefixed roots that lack records. It never sweeps shared temporary directories.

Before recovery effects, startup validates the entire cgroup roster and every staging identity. An existing intent-only root, replaced parent/root, missing active bound root or unknown staging root refuses admission. All cgroup users must be independently empty before staging reconciliation. Retirement tombstones survive failed deletion, and durable exact-record clearing follows confirmed absence. Live publication enforces parent/identity continuity and monotonic phases; it cannot clear an active bound record.

Engine live-inference admission durably enables format 3, then commits the schema-19 reader requirement with its admission transaction, before starting preparation. Failed reader-requirement transactions cannot authorize new creation. The preparation task reserves storage before creation and retains the admitted reservation and fence through blocked host I/O, late replies, cancellation and failed publication. Successful staged ownership transfers into worker custody, which waits for child, transport and cgroup retirement before journaled cleanup. Untracked helper calls retain their existing in-process behavior and do not establish durable engine ownership.

The new actual process-kill test uses the production creator, ledger and worker custody with an authored directory, admitted resources and a real owned `/bin/true` cgroup. It confirms retained resources and refusal while the owner lives; kills/reaps only its own test process; confirms that staged bytes remain and restart refuses failed deletion; restores permissions; and confirms recovery deletes the exact root and clears all rosters. It does not drive the full engine application through process death or qualify every crash cut.

The original unjournaled-owner counterexample remains retained and failing. Old format-2 state may have staged bytes outside the new namespace; this implementation does not claim retroactive discovery or cleanup of those resources. A complete legacy migration/recovery policy remains required. Native capture images, cgroup creation-before-registration, full engine kill cuts, healthy format-3 portable clone/re-export correspondence, hostile same-UID races and host-I/O deadline qualification remain open. Production GPU admission stays disabled. Model, platform, real-media, Handy, human and release gates remain independent.
