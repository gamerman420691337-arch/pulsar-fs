# Handy REST v3 wire codecs

`crates/pulsar-engine/src/handy_wire.rs` implements offline request encoding and bounded response decoding for Handy REST v3. It performs no network calls and has no credentials, upload, BLE, arming or playback-dispatch implementation. The engine's physical-effect commands remain unavailable pending qualification and transport integration.

Implemented requests are `GET /info`, `GET /connected`, `PUT /hssp/play`, and bodyless `PUT /hssp/stop`. Play preserves caller-supplied integer milliseconds with snake_case fields, normal playback rate and looping disabled. The local codec refuses zero server time and timestamps greater than `2^53 - 1`; this is an exact-integer interoperability restriction, not a manufacturer timing or stopping limit. It does not estimate server time or prove clock freshness.

Responses require HTTP 200, at most 64 KiB, and typed `result` fields. Any `error` member, missing required identity/state, duplicate recognized field, incompatible camelCase spelling, unknown play state or invalid clock/rate is refused. Errors contain no remote message or response bytes. Unknown extension fields are discarded. Identity text has local bounded ASCII validation; all model fields are required locally to support exact configuration binding, even where the vendor makes them optional. A syntactically decoded firmware identity does not establish v3 firmware compatibility or physical qualification.

`HsspObservation` reports remote play state, stream ID, clock, rate and loop/starvation settings. It cannot construct core stop evidence or a qualified admission. Remote `Stopped` is an API observation; stop acknowledgment does not establish physical stopping. Future transport must verify operation-specific expected state, session/stream identity, qualified firmware/profile, exact revision and controller ownership, clock uncertainty and command age before using a response.

The protocol basis is the [manufacturer's v3 OpenAPI](https://www.handyfeeling.com/api/handy-rest/v3/docs/spec.yaml), re-fetched on 2026-10-03 with SHA-256 `9ad90e385ff1bf5f454a9af5f02862ca6cb064654b30df873d7d7389198cb684`, matching the earlier [Handy research](../research/phase-b/handy-integration-research-2026-10-01.md). Fixtures are synthetic protocol cases. No device was contacted or actuated. HSP position-bound contradictions, script hosting/consent, authenticated fixed-origin transport, lifecycle dispatch and recovery, current BLE encoding, and physical qualification remain open under GB-07/08.

Focused validation: `cargo test -p pulsar-engine handy_wire --lib` passed all nine tests. The [incremental evidence receipt](evidence/roadmap-2026-10-01/handy-wire/validation.json) records 645 passing workspace Rust tests, zero failures, seven ignored qualification cases and 145 passing structural architecture checks. Native binaries/examples, JavaScript integration and historical-reader cases were not rerun for this codec-only increment; their earlier identities and results remain in the [archived review-decision checkpoint](evidence/roadmap-2026-10-01/checkpoint-review-decisions/validation.json).
