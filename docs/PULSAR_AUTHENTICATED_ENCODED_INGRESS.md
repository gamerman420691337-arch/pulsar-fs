# Authenticated encoded source ingress

Capture leases now optionally admit an `encoded_source` with an explicit YUV4MPEG2, NUT or Matroska format, input-byte cap and frame cap. A separate `live_encoded_source` bulk channel authenticates the existing actor/project/revision/boot/capture scope before claiming one source attempt. Claims are exclusive: completed, failed or disconnected sources cannot reconnect or rearm that lease. A start receipt replay returns current or retired state rather than launching another worker.

The engine snapshots pinned worker/FFmpeg bytes and launches the confined source worker outside authority locks, using the actual capture entry origin and absolute end. A separate owned reader publishes immutable native frames only after fresh authentication, grants, revision, boot, exact attempt/order and lifetime checks. It retains original rational source PTS, body hashes and measured worker/parent delivery brackets. RGB ingress is refused for encoded leases, preventing producer metadata from replacing native delivery facts.

Capture and accepted inference reports explicitly use `decoded_stdout_local_monotonic_equal_rate` as their age basis. Their legacy `capture_tick`/age fields refer to the earliest conservative native delivery bound in this mode. They do not measure physical exposure age, source/encoding/decoding buffering or camera/player clock calibration. Producer RGB leases retain `producer_declared` semantics. Position results remain inferred and unqualified; no durable motion or device dispatch follows.

Each encoded request has an exact sequence, a nonempty body of at most 65,536 bytes and a SHA-256. Fresh authorization precedes the SendBytes response, body intake, native forwarding and the post-I/O counter effect. The connection uses a fixed bounded body buffer and bounded native backpressure. Malformed, conflicting, oversized, partial, timed-out or ambiguous exchanges retire the source without retry. Grant/revision/lease loss blocks publication and cancels native workers. Retirement can still cancel/reap native execution without requiring a healthy project database.

Explicit Finish closes the parent's sealed input and awaits exact native completion. Success requires matching parent/native intake count/hash, exact published frame count, terminal EOF without appended output and native exit success. The report retains the scoped completion facts. A successfully finished source leaves the lease active for pending automatic analysis until stop/expiry; it cannot accept another source attachment. Dropping unfinished input cancels and joins the owned source reader/worker. Process reap remains separate from physical stopping.

`LiveEncodedClient` exposes bounded incremental push and explicit finish. It binds replies to the initial exact manifest digest as well as capture scope, and permanently poisons remote/I/O ambiguity. Status reconciliation does not authorize replay or rearm. The shipped `live-capture encoded PROJECT REVISION EPOCH FILE` command streams a bounded nonempty regular file through this channel; it refuses symlinks/nonregular files and size changes. A file consumed through this API is an encoded stream, not proof of real-time camera acquisition.

`encoded_source_ingress` advertises the pinned Linux confinement adapter. `native_acquisition` and `physical_dispatch` remain false: direct camera/device admission, source continuity/renewal, actual exposure and player clocks, buffering execution, qualified models/GPU six-axis, Handy firmware/transport/physical stopping and platform/human/release qualification remain open. Training and the negative sterile evaluation were unchanged.

Authored native fixtures use the actual authenticated endpoint and confined decoder to publish three frames before producer EOF, verify complete intake, refuse duplicate attachment and RGB-mode mixing, cancel on drop/stop/expiry, and feed the persistent CPU analysis actor while preserving the delivery age basis and pixel/tick correspondence. Raw peers separately refuse invalid authentication, retired boot, foreign source/revision, conflicting sequence, oversized headers and mismatched body hashes. Credentials remain in fixture memory and are never included in retained requests or receipts. These checks establish software correspondence for authored streams, not camera/media/model/Handy qualification.
