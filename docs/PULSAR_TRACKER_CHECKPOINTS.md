`TargetTracker::checkpoint` returns an inert, serializable `TargetTrackerCheckpoint`. It preserves the association configuration, active tracks, velocities, scores, missed-frame counts, last observed centers/ordinals, source context, dimensions and identity allocator. Floating state is stored as integer IEEE-754 bits so JSON serialization does not round velocities, geometry or scores. The collection decoder stops at the 256-track budget; unknown fields refuse. No filesystem, runtime, model or authority dependency was added to Core.

`TargetTracker::from_checkpoint` requires independently expected origin namespace, complete last frame context, configuration and dimensions. It checks the schema, context/configuration/geometry correspondence, topology, class range, finite scores/velocities/centers, clipped positive boxes, missed-frame/observation chronology, unique canonical allocated identities and budgets before returning a tracker. Parsing a snapshot alone does not restore it. The caller must additionally validate the containing artifact's size/hash and its source, model, job, revision, transform and custody bindings before use; this API grants none of those authorities.

Restore can explicitly rebind the allocator and active identities to a fresh attempt namespace while retaining their ordinals. `rebind_identity` also maps an allocated expired identity, allowing a later worker integration to rebind previously accumulated sample lineage and selection state without conflating attempts. It refuses another namespace, noncanonical suffixes and unallocated ordinals. It is a pure identifier transformation, not evidence that a target is currently observed.

Three authored integration cases compare serialized/restored tracking against uninterrupted tracking after every transition through missing detections, ambiguity, cut, resize, seek and expiry; check fresh-namespace continuation/allocator behavior; and refuse malformed or mismatched state. Exact snapshot bytes and actual observations/reviews/classes/ambiguity decisions agree, including nontrivial floating geometry. These are deterministic state tests, not real-media tracking qualification.

## Vertical integration contract and remaining campaigns

The worker currently writes only into its quota-bounded private temporary filesystem. The Engine persists validated bounded egress; no writable project mount may be added to implement progress recovery. The existing immutable `WorkerRequest` checkpoint does not contain partial tracker state.

The CPU integration now follows this contract: capture the full generation computation: checked tracker snapshot, selected identity and previous grayscale/RGB support, normalized position, completed actions/gaps/review spans/sample lineage and exact next source/presentation index. Bind all of it to the immutable source, tools, model/profile, configuration and job/revision. Transfer it through a bounded separately identified worker stream, with quotas, deadlines, cancellation, atomic Engine publication and confirmed process custody before reuse. Rebind all accumulated attempt identities consistently. Preserve the original pixels/PTS and refuse mismatched or incomplete checkpoints; never infer a completed prefix from pending process custody.

A final candidate must retain the checkpoint origin and actual resumption facts. Native interruption after completed inference must demonstrate progress reuse and equivalence with uninterrupted output, including target seed, ambiguity, missing intervals, cuts, projection/placement, mixed audio and secondary provenance where applicable. Decoder restart/discard behavior and measured work avoided must be reported separately. Live/GPU continuity, whole-application memory and physical playback require their own evidence. The current CPU case is recorded separately; it does not establish this broader campaign matrix.
