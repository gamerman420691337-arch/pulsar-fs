# Owner-selected packs for live capture

LiveCaptureOptions now has an optional model_pack choice containing the manifest digest and exact owner selection revision. A pack-only request omits inference; the Engine resolves its model/profile from the current approved pack. Raw/file options with no pack choice keep their previous contract and omit this new field during serialization.

In Pulsar Desktop, refresh the owner selection in Generator, then choose **Owner-selected pack** in Browser live and **Capture owner-selected pack**. Review the captured manifest/revision and model/runtime identities and the live timing settings before launching. The form requires the existing 64×64 temporal profile; a detector is not interchangeable. Capturing the choice neither imports nor approves/selects a pack, and never extracts its path into a raw-file request. JSON/CLI options can also supply model_pack with no inference.

Every fresh Start or continuation uses the normal selected-pack integrity/profile/runtime/provider and snapshot admission. The artifact gate covers the pack lookup through lease insertion; actor/project/revision are checked before preparation and again by the live handler. The caller's original request fingerprint and ID remain authoritative even though the Engine resolves an internal model/profile. Conflicting caller-supplied inference refuses instead of overriding it. Continue-at derives the same pack choice from its predecessor and rechecks it freshly; a raw continuation cannot erase that choice.

The registry retires pack-bound leases with AuthorityLost if their choice no longer matches the current selection, including approval withdrawal. This requests analysis cancellation, not physical stopping. A finite lease and existing Worker custody rules remain in effect. Accepted historical Start replay returns the original scope/current retirement facts without fresh execution; stale choice with a fresh request ID refuses. Pack deactivation or byte corruption refuses new admission. A previously captured immutable model is not retroactively rewritten by filesystem changes. No source or native reply may authorize a new default or silently switch provider/model.

Recording pages retain the admitted pack choice alongside the exact profile and source-clock declaration. Assembly refuses mixing pack choices or pack/direct pages. Archive metadata checks include the choice, and the Engine-owned durable recording source proof records it when present. These identifiers are provenance, not reusable current approval. Approval-document portability, broader races/cancellation/faults and long-term provenance qualification remain separate acceptance work.

Useful trained models, actual desktop/browser/platform acceptance, source-player and device timing, physical Handy/six-axis, edition/vendor coverage and human/release gates remain open. No device capability changes. Full roadmap PARTIAL. See [desktop settings](PULSAR_DESKTOP_LIVE_OPTIONS.md), [server ownership](PULSAR_DESKTOP_BROWSER_LIVE.md), [ADR B3-213](../research/phase-b/ADR-B3-213-live-model-packs.md) and [checkpoint](evidence/roadmap-2026-10-13/live-model-packs/checkpoint.json).

## Scoped verification

The final subject passes 882 Engine library tests with 70 ignored, 299 Protocol tests, 434 Client tests with eleven ignored and 24 player mocks. Eleven validation commands pass, including strict Client and workspace/all-feature Clippy, native App/Worker builds, format and architecture/source guards. Protocol checks admit explicit unresolved pack requests, omit legacy fields and reject mixed pack/direct assembly; the Client check preserves the choice without a raw-file extraction.

The private real Engine/CPU campaign imports and explicitly selects an authored diagnostic pack. Native packed Start/Stop and browser RGB inference match 0.375488758 within 0.0001 of the independent scalar oracle. One prepared continuation retains the same choice across two recording scopes. Approval withdrawal retires active captures; stale fresh requests and corrupted installed model bytes refuse. Historical Start replay returns the original inactive scope without execution. Explicit reselection and restoration admit a new lease. Historical recordings stage one uncommitted candidate without a native job; its durable source proof retains the original pack choice in the top-level record and every page, despite the newer current selection. Final state has one project, one candidate and zero ordinary jobs/exports, empty Worker custody and joined owned server/Engine processes. This is a native adapter campaign, not actual browser or desktop rendering.

Initial failures are retained: a 300-second full-suite timeout including 58 seconds of compilation (the named final test passes independently), an invalid pagination fixture, a too-long harness Unix socket path, identical retirement branches reported by strict lint and an HTTP-module/helper name collision in the native harness. Fixtures/limits/lint are corrected without weakening transport deadlines or model/actor checks. Final full validation and native proof checks pass. Learned quality, broader races/faults, approval-document portability, real rendering/platform, source-player timing, Handy/six-axis and human/release qualification remain open.

The established file-model CLI/HTTP campaign also passes through the rebuilt Engine: two recording/repair/export cycles, prepared continuation, original reply-loss/server/Engine recovery and recording/export history remain intact, with four candidates, two exports and no ordinary jobs. This retains legacy behavior rather than selecting a pack implicitly. No Core implementation changes occur in this slice.
