# Explicit detector letterbox

Profiles declaring `letterbox` are now admitted for the implemented RGB/NCHW/YOLO channel-major detector. The first-party CLI can create the declaration with `model profile MODEL --width 640 --height 640 --class-count 80 --letterbox`; `--padding-byte` optionally changes the explicit border value from 114. It refuses combining detector letterbox with either temporal recipe, specifying padding without letterbox, or an out-of-byte-range border. Existing stretch profiles keep their previous nearest-stretch behavior. Profile generation is metadata work, not pack activation, native execution approval or model qualification.

The isolated adapter uses fixed target dimensions, centered borders, ties-to-even resized dimensions, scale-up and byte-space half-pixel linear sampling with 11-bit separable weights. Odd extra border pixels go on the right or bottom. Invalid buffers, unsupported contracts and scaled dimensions that round to zero refuse before allocation/inference. Every observation is inverted with the exact rounded resized dimensions and integer padding, then clipped and normalized to the decoded selected source view. Padding-only boxes disappear. Preprocessing, native execution and decoding retain the same failed-session scope. Preview and generation share this adapter; selected-eye/projection and PTS binding remain intact.

The recipe was checked against [the pinned publisher LetterBox source](https://github.com/ultralytics/ultralytics/blob/69c95d1add13a232382e53b3aa5094ec0c7738db/ultralytics/data/augment.py) and [OpenCV 4.13.0 resize source](https://github.com/opencv/opencv/blob/fe38fc608f6acb8b68953438a62305d8318f4fcd/modules/imgproc/src/resize.cpp). The retained primary-source metadata pins that OpenCV commit and source-file digest. This is the fixed centered mode, not the publisher's dynamic minimum-rectangle/stride-reduced predictor. Integer resized dimensions determine actual per-axis inversion rather than assuming the ideal unrounded gain.

Thirteen independently generated OpenCV 4.13.0 / Ultralytics 8.4.175 fixture tensors matched bit-for-bit, including non-square inputs, odd borders, single-pixel dimensions, up/down sampling, half-scale and a 1920x1080 input. On the pinned ordinary bus image, Torch and Pulsar consumed bit-identical letterbox tensors. All five selected detections matched; maximum raw coordinate difference was 0.0101470947265625 model pixels, and maximum raw score difference was 0.00004303455352783203. Against publisher NMS followed by the declared inverse mapping, maximum normalized box difference was 0.00000022283444802047303 and score difference was 0.0000005662441253662109. The earlier stretch comparison still passes. These are numerical tolerances/results, not calibrated accuracy or timing measurements.

The final Engine suite passed 790 tests with zero failures and 61 ignored; client235, both strict lint configurations, all-feature binaries, formatting, architecture387 and source-guard36 checks passed. The actual first-party CLI/Engine/worker campaign returned five source-view detections with matching frame contexts and normalized bounds. Independently decoded source frames were byte-identical to one another and to the returned preview pixels. Standard export produced four constant actions at position 50, with zero neutral travel. This is a static-input invariant, not target-specific script accuracy.
