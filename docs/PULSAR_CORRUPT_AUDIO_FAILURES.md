# Corrupt audio decoding failures

2026-10-12. Scoped authored audio worker regression PASS; roadmap PARTIAL. No real-media, model, device, platform or release qualification.

The native audio worker previously generated a successful-looking motion candidate from an AAC file whose first source packet was damaged. FFmpeg dropped that packet, reported a codec error, and exited successfully. The decoded remaining timeline was internally continuous and its sample count matched the shortened PCM, so the existing timeline/count guards could not identify this leading loss. The authored clean source yielded 32,000 samples; ordinary decoding of the damaged source yielded 30,976.

The shared audio PCM command now supplies `-xerror`. It returns a terminal decoding failure for the reproduced leading AAC error before feature extraction or any candidate artifacts. Audio-only and mixed/independent-audio preparation use this same decoder. The timeline, source origin, resampling, RMS/onset recipes and synthesized-motion disclosure remain unchanged; no implicit repair is introduced.

The permanent `scripts/qualify-corrupt-audio.py` probe authors two-second sine controls in AAC, FLAC and MP2 and damages packet ordinals 1, 3 and 7 using recorded positions. It retains metadata/error diagnostics, output hashes, counts and exact source/tool identities. AAC/FLAC controls reproduce ordinary decoder success despite errors, while strict decoding fails. The MP2 mutations produce no reported codec errors and remain accepted by FFmpeg in both modes. This is an explicit limitation: strict exit handling detects reported codec failure, not arbitrary corruption or incorrect but decodable content. The supplied runtime lacks the requested libmp3lame encoder, so MP3 was not qualified by this campaign.

The opt-in native Engine regression executes the production audio generation worker. Clean AAC, FLAC and MP2 still return checked generated programs and receipts with 32,000, 32,000 and 32,256 samples respectively. Six damaged AAC/FLAC controls refuse and leave empty output directories. The leading AAC case now returns the native-tool exit error; the other cases already fail timeline or missing-timestamp admission. Only that leading-loss case establishes new repaired behavior. This is direct worker generation evidence, not shipped CLI/GUI/Engine publication or physical playback acceptance. Mixed/independent audio use the shared implementation but were not separate corruption campaigns.

Evidence: [checkpoint](evidence/roadmap-2026-10-12/corrupt-audio/checkpoint.json). The default Engine library suite passes 832 tests with 70 ignored; the new ignored audio campaign passes separately. Both strict workspace all-target lint configurations, workspace all-target check, formatting, 431 architecture checks, 36 source guards and App/Worker build pass. Other library, feature/platform runtime and prior opt-in native campaigns were not rerun here. The permanent reproducer's twelve authored input identities match the native campaign's inputs exactly.

The original successful-looking damaged AAC candidate is retained as a failing regression log. Broader codecs/containers, malformed but decodable signals, delay/edit-list/rate-change behavior, real audio and all model/media/platform/device/human/release gates remain open. Sterile evaluation and live training references were not accessed; no annotations or acceptance records were created.
