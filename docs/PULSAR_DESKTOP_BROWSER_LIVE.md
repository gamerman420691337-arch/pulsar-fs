# Desktop launch of the shared browser player

Current successor, 2026-10-22: [independent player control and optional Handy stop guard](PULSAR_BROWSER_PLAYER_CONTROL.md). Player heartbeats and exact native release are separate from Preview work; all worker ownership is joined. The optional guard requires an exact existing-play JSON selection and explicit monitoring checkbox, and never starts or synchronizes playback. Historical evidence below retains its original scope.

Pulsar Desktop now has a **Browser live** tab. Open a project, choose [captured Generator model/profile settings](PULSAR_DESKTOP_LIVE_OPTIONS.md) or an absolute live-options JSON path, plus a server lifetime of 1 through 600 seconds, then choose **Launch browser player**. The launcher captures the open project ID and revision; changing the form does not retarget a running server. It shows **Open local browser player** after the shared adapter has validated options, bound its loopback listener and restored retained recording metadata. Launch itself does not start capture. In the browser, choose media and press Play explicitly.

The options use the same LiveCaptureOptions schema as the [CLI browser player](PULSAR_BROWSER_LIVE_PREVIEW.md): an explicit compatible RGB temporal model/profile, immediate mode, freshness/clock declarations and a bounded Engine lease. Model and runtime admission still belong to the Engine. No default or diagnostic graph is silently selected. The options file is bounded regular input; its bytes are read once by the launch worker. Credentials stay in the native SessionClient and do not enter the page or URL.

**Stop browser player** removes the visible launch URL immediately, prevents newly parsed HTTP operations from being dispatched, waits for any operation already in flight, and uses the same capture cleanup as normal server expiry. Changing the desktop project or revision requests the same stop. A replacement server cannot be launched until the original server thread actually finishes and is joined. Normal desktop close is held while the worker stops, allowing the UI to continue rendering; non-window destruction also requests stop and joins ownership.

Stop is not instantaneous cancellation of an Engine operation. Its original request/outcome remains authoritative. Existing bounded HTTP, Engine control and bulk waits still apply. Unknown stop outcomes remain errors with retained recovery state and lease expiry as fallback; they are not reported as successful cleanup. Force-killing the app can bypass cooperative shutdown. Closing the browser page requests capture Stop, while the desktop owns the separate finite server lifetime.

CLI and desktop share one run_controlled adapter, private recording/export/candidate recovery, same-origin HTTP policy, freshness rules and prepared continuation. No second generator, decoder, database or device driver is added to the GUI. A browser commit does not silently refresh the desktop's project snapshot; open/refresh the project before editing or relaunching. Revision checks remain authoritative.

The launcher does not establish useful learned motion, actual tab capture, source-player clock calibration, desktop rendering/platform acceptance or synchronized Handy output. Optional guard retirement is documented in the successor above. See [tab-sharing limits](PULSAR_BROWSER_TAB_CAPTURE.md), [timestamp domains](PULSAR_LIVE_TIME_BASIS.md) and [current status](PULSAR_CURRENT_STATUS.md). Full roadmap PARTIAL. Software evidence is retained in the [checkpoint](evidence/roadmap-2026-10-13/desktop-browser-launch/checkpoint.json).

## Scoped verification

Client tests pass 429 in total (427 library and two integration) with eleven ignored. Four new ownership/headless tests cover changed selection, late readiness, duplicate launch, joined destruction, invalid bounds/missing config and inert controls. The ignored native controller is run explicitly against a private real Engine: active-capture Stop, changed revision, owner Drop and finite expiry all retire their captures and join the server. The first case also matches the authored scalar oracle at 0.375488758 within 0.0001. Worker custody is empty, with one project and zero ordinary jobs/candidates/exports. No desktop window or toy is operated.

Twenty-four browser player mocks, strict Client and workspace/all-feature Clippy, native App/Worker builds, formatting, architecture and source guards pass. Engine/Core/Protocol source identities are unchanged; no fresh suites for those libraries are claimed. The existing full CLI/HTTP continuation, two-cycle recording/repair/export and original-request recovery/history campaign also passes through the rebuilt adapter, retaining four candidates/two exports and no ordinary jobs. Its first sandbox launch lacked an empty mountpoint and failed before Pulsar started; that failure is retained, then the setup is corrected and the campaign passes. Broader in-flight cancellation faults, rendered window-close/platform behavior and model/media/device/human/release acceptance remain open.
