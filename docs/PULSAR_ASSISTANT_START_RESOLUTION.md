# Recovering an assistant start

A saved assistant request now supports explicit resolution after a lost acknowledgement. Resolution returns the accepted attempt, or durably withdraws the original request ID if no attempt was accepted. A delayed submission of that withdrawn ID is refused. Resolution never starts inference, cancels an accepted worker, changes project motion or deletes the saved intent.

The CLI command is `pulsar assistant resolve --intent PATH --acknowledge-withdrawing-unpublished`. The Doctor panel provides **Resolve start; withdraw original ID if never accepted** for a prepared request, including an uncertain Start. The private intent must still match the endpoint, session, credential binding and project; its semantic digest and exact owned value are checked before dispatch. A historical revision may be restored for inspection/resolution. Starting inference still requires a current revision and separate approval. Pending cancellation remains a distinct operation.

## Authority and transaction

`ResolveAssistantStart` carries the complete original ID, captured revision and typed invocation. It requires current Read and Edit grants and an existing referenced revision, rather than a current-revision precondition. For an accepted attempt, the Engine reconstructs the original authenticated Start request and checks its stored full request fingerprint, including the prompt/profile/invocation. A mismatch is a conflict.

Otherwise an immediate SQLite transaction reserves the actor's original request namespace with a domain-separated withdrawal fingerprint. A namespace already used by another declaration/workflow/project is refused. Reservation and resolution receipt commit together; failed receipt insertion rolls back the reservation. Original Start checks the same namespace, including inside its transaction, so an ordered late submission cannot execute. The first-party client derives a stable resolution ID from the exact project/reference. Replays return the immutable original resolution receipt. An accepted Running receipt may be historical: use status to obtain a fresh report.

The reservation uses existing durable request identities; there is no schema migration or deletion. Retention policy, bounded corrupt-cell handling, simultaneous-start race injection, assistant-specific formal checks, restart-persistent cancellation and saved-intent lifecycle remain open. Credential rotation conservatively refuses a saved intent from the old credential namespace.
