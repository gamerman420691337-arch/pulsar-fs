# Captured native dependency bytes

`pulsar_engine::native_dependencies` now captures an explicitly declared set of native library bytes into an engine-owned private temporary directory. A Linux authored CUDA probe executes using that set without mounting host runtime directories. This supplies byte-capture and namespace evidence for the GPU adapter; enabled production inference remains CPU-only. [ADR B3-015](../research/phase-b/ADR-B3-015-captured-native-dependency-sets.md) records the boundary.

The schema-1 specification requires 1–128 unique SHA-256 identities, positive lengths of at most 2 GiB per library, an aggregate limit of 8 GiB, absolute input paths and 1–4 unique loader aliases per library. Aliases have bounded ASCII filenames including the `+` needed by `libstdc++`; traversal and collisions refuse. Unknown specification fields refuse. This is an internal capture interface, not a new engine command or stored inference profile.

Capture opens final components without following symlinks, refuses non-regular inputs, snapshots the opened descriptors and compares copied lengths/digests with the declarations. Original paths are not used after capture. Aliases are hard links to the read-only snapshots. Verification rehashes captured content, checks alias identity and rejects undeclared/missing files. The caller owns the capture lifetime and must verify before read-only confinement. Explicit `close` reports cleanup errors; ordinary `Drop` only attempts cleanup. Failed captures remove their temporary directory in the tested ordinary-file cases.

These limits bound bytes and entries, not wall time on a stalled filesystem. Admission, storage scheduling, cancellation/deadlines, trustworthy namespace ownership, device authorization and mount lifetime remain the integrating caller's responsibilities. Files owned by the same user remain alterable outside a read-only namespace; this helper does not claim protection from arbitrary same-user processes or descriptor-bound mount atomicity. It does not parse ELF, discover SONAMEs, approve executable permission or load native code in the engine.

The subsequent [held device binding](PULSAR_CUDA_DEVICE_BINDINGS.md) adds explicit kernel expectations, inherited device descriptors and a mounted-node gate before CUDA preload. The capture receipt below describes its earlier source; the new receipt binds the integrated authored scenario.

## Actual authored execution

The [native example](../crates/pulsar-engine/examples/native-dependency-probe.rs) holds the capture through an experimental Linux namespace. The declared set came from the preceding authored probe's observed mappings, with explicit aliases extracted using `readelf`. It captures 74 libraries totaling 1,943,035,224 bytes, including the loader, runtime, provider, CUDA, cuDNN and observed driver libraries. The example explicitly enables its captured loader's executable permission, mounts only the captured library directory at `/runtime`, and invokes that loader with cache lookup inhibited and an explicit library path. The namespace does not mount `/usr`, `/lib`, `/lib64`, host cuDNN/CUDA directories or `/etc/ld.so.cache`. The glibc manual documents [explicit loader invocation](https://sourceware.org/glibc/manual/latest/html_node/Dynamic-Linker-Invocation.html); the exact isolated success is local evidence rather than an ABI portability claim.

The experiment exposes the same three explicit GPU nodes and restricted read-only sysfs paths as the preceding feasibility probe. It uses a separate 16 GiB virtual address-space limit, bounded file/CPU limits and a 30-second child deadline. It has no physical RAM cgroup or aggregate GPU reservation. GPU node identities are fixed research inputs, not production device brokering. The existing authored C++ binary and graph are separately pinned before/after; they are outside this library capture interface.

Four authored inferences pass the numerical oracle and the production strict trace validator, which records twelve CUDA computation events. Every reported library mapping is under `/runtime` and has a declared alias. This proves sufficiency for this graph and observed execution, not completeness for arbitrary future lazy loads, other models, operations, drivers or platforms. Trace consistency is not authenticity. The copied libraries are private temporary validation inputs and are not redistributed in the evidence packet.

The [current receipt](evidence/roadmap-2026-10-01/native-dependency-capture/validation.json) retains final source/binary identities, Rust/build checks, the native CUDA result, eight capture refusal cases, a current native CPU compatibility scenario and cleanup readback. Initial rejection of the legitimate C++ alias and the campaign preceding explicit cleanup reporting are kept separate. No private media/model, training, sterile evaluation or physical Handy contact occurs.

Production integration still needs an owner-authorized dependency set bound to the profile/attempt, a recovery and reader boundary for durable GPU facts, device identity/capacity observation and aggregate scheduling, confined Rust selected sessions, and actual model/provider/resource qualification. Observed byte capture alone is insufficient to enable CUDA.
