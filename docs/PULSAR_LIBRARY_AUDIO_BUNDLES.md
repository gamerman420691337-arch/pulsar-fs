# Explicit six-axis audio folder synthesis

`batch FOLDER --multi-axis --audio-bundle-recipe RECIPE.json` and `scan FOLDER --generate --multi-axis --audio-bundle-recipe RECIPE.json` now generate explicitly synthesized audio bundles through the same checked recipe, immutable source, one-decode DSP, candidate/commit and atomic neutral publisher as single-file audio synthesis. Model/view/preset/stride controls must retain their default visual values; audio choices belong to the six per-axis recipes. Raw and selected-pack visual generation remain available separately. Visual six-axis reconstruction remains unimplemented.

Discovery retains the existing bounded, non-symlink-entry traversal and adds common audio extensions only in this explicit mode. The output target appends `.pulsar-audio-bundle` to the full original filename, so `clip.wav` and `clip.flac` have distinct targets. Existing stroke scripts remain untouched. Any existing bundle target, including an unrelated file or directory, is skipped and preserved. Presence is not content verification or a completeness claim.

Each successful source publishes one private directory with six neutral scripts and hidden recovery metadata. Batch writes one JSON line immediately per successful entry, with source, bundle receipt, synthesized evidence and `qualified:false`. Scan retains its inventory output before these generation records. Failure stops future entries; prior publications remain intact and stderr retains the failed entry's project/job identity. Publication failures retain the helper's staging/outcome details for explicit `export-bundle-resume`. There is no aggregate folder transaction, durable queue, automatic failure replay or overwrite. A retry is not a substitute for inspecting retained state.

Dry-run validates the bounded checked recipe and lists pending entries using the legacy entry array (`script` names the bundle directory; `has_script` means target presence). It creates no Engine generation state. Recipe parsing rejects duplicate/missing axes and unknown fields; mixed visual/model controls, missing multi-axis intent and unsupported overwrite refuse. Planning is platform independent; execution refuses unsupported atomic-publication platforms before source effects. Current implementation is Linux/Android; only Linux runtime is tested.

The [checkpoint](evidence/roadmap-2026-10-12/library-audio/checkpoint.json) records actual network-disabled native WAV and FLAC batches and scan generation. All six scripts per input match the preceding independently authored PCM/timing oracles, including same-stem distinct-extension sources. Existing stroke/media/unrelated targets are unchanged. Dry-run/repeat and eight refusal cases create no generation state. A later invalid-media failure preserves the first publication and emits retained project/job IDs. The extracted shared publisher also passes the single-file atomic command regression. Separately rerun raw-model and selected-pack folder campaigns preserve exact profiles/outputs, companions and deactivation-after-restart behavior.

Final parallel client tests pass 344 with ten ignored plus two integration tests. Both strict workspace lint configurations, Windows all-target source compilation, native App/Worker build, formatting and architecture/source guards pass. Four client source paths changed; Engine/Protocol sources remain unchanged and their library suites were not rerun. Initial nonexistent-method compile failure and a native verifier's wrong stderr-label assumption are retained with corrections; the latter followed correct partial output.

Only authored WAV/FLAC media were exercised for this scoped software correspondence. Other accepted extensions/container/codec/platform combinations remain to be exercised. Creative or real-media quality, faithful visual/physical axes, durable folder scheduling, GUI/platform/edition, useful model/default, Handy and human/release gates remain open. Full roadmap PARTIAL.
