# Portable annotated generation and source clocks

Annotated generation now has a conditional portable format, version 11. Its generated origin names the exact retained model identity, and the object closure requires an `AnnotatedModel` payload. Import verifies the immutable request, receipt, candidate, native view plan and ONNX recipe/intake metadata using retained objects. Archived source/model/output paths remain inert. Missing model membership, marker downgrade and inconsistent completed origins refuse admission. Older formats retain their existing representation when annotated facts are absent.

Placed annotated generation uses schema-3 source-clock receipts. The shared reader validates mapping, ordered samples, stride, quantization, declared trim and uncovered boundaries, alongside exact receipt/program identities. This establishes internal clock correspondence; independent natural-media PTS/alignment remains a separate gate. Current-file and retained-object readers use the same annotated lineage bound.

A conditional schema-24 wrapper preserves the underlying schema 18 through 23 and its existing CUDA/worker/local-annotation requirements. Import and completed export publish that requirement in their SQL transaction. Exact layout/row/header checks and retained archive/export facts prevent forgetting the requirement. Rollback and both activation orders are tested. Historical schema-23 executables refuse this database explicitly.

The authored native campaign uses a real worker result with 28 exact transformed RGB frames and 14 Python-corresponding estimates within 1e-6. Its initial portable container is authored from that result. Actual Engine import, restart, archived-generation status, re-export, second clone and another restart succeed after the owned original source/model paths are renamed unavailable. The resulting ancestor graph preserves the 28 sample clocks without creating executable jobs. Four rehashed clock corruptions and a stripped annotated marker refuse production evidence validation.

The frozen preceding executable refuses the new database without changing the observed database or WAL bytes. The current executable also refuses changed retained model bytes with unchanged observed database/WAL bytes. The retained-byte check runs before writable SQLite recovery, but after some startup custody and filesystem preparation; this campaign does not establish unchanged custody or all filesystem state on that failure. Marker/layout checks run earlier. No archived request path becomes a resolver and model metadata validation does not execute the model.

Public annotated Engine submission, generic/Stash batch and model-pack admission, and first-party controls remain guarded. This campaign does not prove active Engine generation/capture, shipped CLI/desktop usability, broad power-loss recovery, real-media quality, platform packaging or physical Handy playback. No live/sterile fitting, historical input modification or physical actuation occurred.

Earlier compilation and fixture failures remain in the evidence packet rather than being presented as passing gates.

The default binary builds; 282 architecture checks and 36 source guards pass. The source archive/readback covers 386 records: 365 preceding unchanged, 19 existing paths changed and two added.
