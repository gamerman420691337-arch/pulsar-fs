# Inherited model attempt deadlines

Generation, detector preview and raw frame-pair analysis now pass their existing monotonic attempt deadline into the model factory. The private CUDA worker supplies the deadline preserved across its verified loader transition. Model and captured-library hashing uses that deadline rather than starting another whole request budget.

The shared session stores the inherited deadline. It refuses initialization after expiry, rejects initialization that returns late, checks before and after adapter execution, and refuses late finalization. An expired execution poisons the session. CUDA trace finalization and receipt publication check the same deadline before attaching successful evidence. Existing public research constructors may establish a budget at construction; production generation and preview use the explicit inherited-deadline methods. Persistent live sessions retain their separate lease/process-supervision contract.

These checks reject late output; they do not preempt a blocked native call, filesystem read, destructor or profiling finalization. Parent supervision and confirmed process-tree retirement remain necessary. Expiry can leave partial worker-private diagnostic files, but they are not successful CUDA result evidence. Independent parent filesystem deadlines and complete engine GPU lifecycle integration remain open.

The source demonstrated a reset inside `ModelSession::from_request`: CUDA artifact hashing created `Instant::now() + request.budget.wall_time_ms` after bootstrap work. The corrected factory receives the caller's `Instant`. The expired temporal factory regression reaches the production adapter and refuses before native loading, with no telemetry or CUDA evidence. There is no controlled pre-change native timing baseline for this reset; the source defect and post-change checks have distinct evidence scopes.

`model-deadline-check` exercises an authored model on the actual CPU runtime in fresh processes. Its `fresh` case produces the expected value. Its `expired` case constructs a native session, lets the caller's shorter deadline expire, then verifies run and finalization refusal. The initial helper retained CUDA profile schema version 2 when selecting CPU, and its subsequent version attempted two runtime initializations in one process; both refusals are retained as helper failures. The final helper uses CPU schema version 1 and separate process invocations without weakening runtime initialization rules.
