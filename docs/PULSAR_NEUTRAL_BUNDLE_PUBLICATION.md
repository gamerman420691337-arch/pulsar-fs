# Atomic neutral bundle publication

On Linux/Android, `export-bundle PROJECT NEW_DIRECTORY --revision REVISION` publishes all six neutral tracks from exactly that current master revision. `export-bundle-resume STAGING_DIRECTORY` resumes the exact retained intent with the same authenticated credentials. Source generation, candidate approval and private project packaging are separate actions.

`audio-synth SOURCE --bundle --bundle-recipe RECIPE --atomic-bundle --output NEW_DIRECTORY` uses the same publisher after its explicit synthesized candidate/commit. Individual audio bundle export remains available without --atomic-bundle. Other platforms refuse atomic mode before audio generation; Windows source compilation does not qualify filesystem publication.

The publisher writes private sibling staging before any export effects. A durable hidden intent binds project/revision, destination, credential namespace and one explicit request ID per named neutral axis. Every attempt or resume goes through Engine export authorization and exact acknowledgement checks. Engine receipts enable replay of completed dispatches; unresolved outcomes refuse. Existing matching files alone cannot manufacture an authorized export. Changed current revision, credential binding, duplicate axes/IDs or invalid intent refuse; no automatic rebase or fresh identity is created.

Only after all six exports match the exact neutral master, bounded regular members and held directory identities are verified, and file/directory sync succeeds, does one no-replace rename make the bundle visible. An existing destination remains unchanged. The published private directory contains six axis-named `.funscript` files and `.pulsar-bundle.json` recovery metadata; ordinary scripts contain no provenance or device adaptation. Source media and full project packages are not included.

A failure reports the retained path and publication outcome. NotPublished means the aggregate directory was not published, although individual Engine effects can be complete or unknown. Resolve your conflicting destination deliberately, then resume the same staging intent. OutcomeUnknown requires inspection of both paths. PublishedDurabilityUnconfirmed means visibility occurred but identity/durability was not fully confirmed; do not start another publication. A successfully published directory cannot be used as a staging resume path. Staging can remain after validation failure; it is never silently removed.
