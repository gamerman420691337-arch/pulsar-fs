# Native capture limits and custody interface

Native capture now carries its preparation resource budget and address-space ceiling through a named `CaptureLimits` value. The private copying implementation receives staging parent and worker fence through `CaptureCustody`. These values are metadata and custody references; they grant no launch permission. The tracked entry point still checks current committed format-4 admission, worker scope, ledger version and staging-parent correspondence before creation. Its original inherited deadline remains a separate input.

All generation, live-capture and independent preparation callers retain their exact budget calculations, 1536 MiB address-space ceilings, cancellation flags, worker fences and original deadlines. The copying implementation after unpacking the named inputs is byte-identical to the preceding source. No timing, memory, storage or synchronization barrier was relaxed. The legacy test-only entry point remains separate from production tracked admission.

The regression covers both 1-second and 1-hour preparation budgets with expired or cancelled inherited leases. Every combination refuses before database/staging access, preserves the ledger and retains no storage reservation. All 703 all-feature engine tests pass, with 79 ignored. The engine all-feature/all-target compile check, 350 architecture checks and 36 source guards pass. Engine strict Clippy still fails with 22 library and 69 test-target errors; the three native-capture argument-count findings are eliminated without suppression. Broader lint and formatting gates remain open.

Two existing explicitly ignored Linux native cases pass separately under owned delegated systemd units with a 1 GiB ceiling and pinned test/worker identities. The inherited-lease case observes the confined idle worker after 1000 ms of the original 2000 ms lease has elapsed, retires without renewing the clock, and clears checked custody. The storage case verifies authored bytes, committed admission, process/group retirement, retained storage through blocked deletion, failed-capture cleanup, image-owned lease after engine drop and same-scope restart. These are actual confined processes using authored non-executable capture input; they do not execute CUDA libraries, measure real-media quality or qualify a physical device. The lease case's output file contains a partially overwritten diagnostic line because its stdout and stderr used different file modes; systemd exit status, test result and pinned executable/source remain available. The storage case uses append mode for both streams.
