# Snapshot capture with a restored-mtime source rewrite

This owned native diagnostic uses the production artifact snapshot helper through a small Engine example. Its Linux-only interposer recognizes the exact FICLONE request, inspects the actual held input descriptor, requires a five-byte regular authored source containing `first`, rewrites it to `other`, restores its original modification timestamp and confirms a different change timestamp. It then refuses clone support so Pulsar must take its existing copy path. The consumer is run with read-only host mounts, one writable owned scratch root and private PID/network namespaces. No live/sterile media or secrets are used.

The diagnostic substitutes only the preceding length/mtime predicate into the otherwise current artifact module for its negative subject. The negative control demonstrates publication of changed bytes under restored mtime. It restores final production source before ordinary verification and retains the distinct source and executable identities. This is a scoped fault injection into a library consumer, not a shipped GUI or whole-application workflow.

The final subject must refuse with `source changed while snapshotting`, emit no success descriptor, leave the snapshot folder empty and preserve the unrelated marker. Both subjects also run a clean control that publishes the exact SHA-256 and bytes of the unchanged authored source. The interposer must confirm its injection; a missing hook, unchanged ctime, different mtime or wrong source cannot count as passing refusal. Temporary-file cleanup is checked by enumerating the actual store after process termination.

This verifies one observable rewrite during the normal copy fallback. It does not exercise successful reflink capture, change during later hashing/publication, process death, power loss, every filesystem timestamp granularity or hostile privileged writers. The content hash still identifies captured bytes; universal atomic source capture is not claimed. Windows private capture remains unsupported. Model/media/device/annotation/platform/edition/human/release gates remain open and the roadmap remains PARTIAL.
