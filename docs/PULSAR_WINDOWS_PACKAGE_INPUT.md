# Windows retained package input

**Client input implemented; scoped emulated checks PASS. Native Windows qualification remains UNKNOWN.** This implements selected archive byte intake; it does not implement Windows Engine clone publication, private storage or the complete portable-project product flow.

Previously every non-Unix package source refused before intake. Windows now opens an existing selected filesystem file once through safe Rust OpenOptionsExt. It requests read access, FILE_SHARE_READ without write/delete sharing, FILE_FLAG_OPEN_REPARSE_POINT and anonymous security QoS. The held handle must report a regular file without FILE_ATTRIBUTE_REPARSE_POINT. Relative/device namespaces and UNC pipe shares refuse before open. Normal and extended drive/UNC filesystem prefixes remain eligible, subject to actual open/metadata checks. Paths are never sent to the Engine; the existing bounded header/version, size, exact SHA-256, cancellation/deadline and retained-handle upload code remains shared.

The [Rust API contract](https://doc.rust-lang.org/std/os/windows/fs/trait.OpenOptionsExt.html) defines sharing, custom flags and security QoS. [Microsoft CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) defines the matching open/share/reparse behavior; [Rust held-handle metadata](https://doc.rust-lang.org/std/os/windows/fs/trait.MetadataExt.html) exposes file attributes. These contracts guide implementation, not native qualification. No unsafe code or dependency is introduced. Other unsupported platforms continue to refuse.

The first targeted Wine Client campaign passes **207 tests, 0 failed and 3 ignored**. It executes the existing three-version exact-hash/rewound-handle/source-unchanged test and restores both real retained-source ambiguous-Start/recovery tests on Windows. Those recovery tests deliberately encounter unavailable Engine sessions; they demonstrate retained-client scope, not successful import publication.

Two Windows tests additionally check an existing writer blocks preparation; retained input rejects new writers through the selected path and a pre-existing hard link; rename and removal fail; exact retained bytes remain readable; and dropping the retained handle permits a write visible through the hard link. The reparse test verifies that a real symbolic link exists, has the reparse attribute and reads the original bytes before proving intake refuses it with idle progress. Directory and relative/device/UNC pipe namespace cases also refuse without hashing. The initial Windows compile failure from a formerly Unix-only test import is retained and corrected by matching its supported test scope.

The final rebuilt Windows GNU portable suite passes **38 executables, 630 tests, 0 failed and 3 ignored**. The initial targeted Client result remains retained. The rebuilt Linux Client suite passes **322 with 8 ignored**. Both strict Linux lint configurations, Linux and Windows workspace/all-target source checks, formatting, native App/Worker build, 445 architecture checks and 36 source guards pass. Windows target lint warnings remain open. Linux Core/Protocol/Engine suites are inherited from the preceding unchanged-source checkpoint and are not rerun here. These results and the first compile failure are retained in the [checkpoint](evidence/roadmap-2026-10-12/windows-package-input/checkpoint.json), with current scoped source and executable identities rather than hermetic build provenance.

Owned scratch is removed after known handles terminate and accessible process references are checked. Both private Wine prefix servers are waited for; namespace teardown removes their RAM state. Borrowed runtime/model payloads, shared build cache/toolchains and unrelated work remain preserved.

Wine uses its own RAM prefix, PID/network isolation, private device surface and no display. Its Windows sharing/reparse emulation cannot prove native NTFS/ReFS/SMB behavior, filesystem/parent-reparse races, inherited handle rules, writable mappings, crash/power-loss behavior or native MSVC/runtime integration. Required Windows private storage, confinement, secure IPC, full clone import/export, native GUI, media/model/device execution, editions/packaging/signing/clean-machine and human acceptance gates remain open. No model/media accuracy, annotation or Handy qualification is inferred. Roadmap remains PARTIAL.
