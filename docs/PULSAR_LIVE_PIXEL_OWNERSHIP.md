# Bounded captured-pixel ownership

The engine library now owns a conditional captured-RGB runtime in `live_frames`. It combines the checked metadata scheduler with actual immutable pixel buffers and aggregate memory admission. The production captured-pair worker uses its shared packed-RGB parser. The [authenticated capture leases](PULSAR_LIVE_CAPTURE_SESSIONS.md) and [frame channel](PULSAR_LIVE_FRAME_INGRESS.md) now own this runtime. Camera acquisition, continuous worker sessions, model-result authority and device dispatch remain open.

Each frame contains exactly 12,288 packed RGB bytes at 64 by 64 pixels. The runtime derives the artifact identifier from the accepted bytes. It does not trust a producer-supplied pixel hash. Metadata admission precedes copying, and rejected byte counts, clocks and frame identities leave the existing pending pair intact.

The runtime retains the previous chronological capture independently of the last analyzed capture. Thus a long-running inference on frames 1/2 does not force the next inference to pair frame 2 with frame 100: continued capture replaces pending work and eventually issues frames 99/100. The old issued pixels remain unchanged. There is at most one pending pair and one in-flight pair; the latest capture aliases the pending current frame. Persistent ownership therefore holds at most four distinct frames. Replacement may temporarily allocate a fifth frame.

Construction reserves 61,440 pixel bytes from the shared `ResourcePool`, without taking a worker slot. That conservative reservation is shared by the runtime and its captured buffers. Issued work is opaque and cannot be cloned or deserialized to obtain another ownership lease. Borrowed pixel slices can be read, but their backing buffers and admission cannot be detached. If the runtime is retired and dropped while inference still holds work, the reservation remains until that work is released. Admission covers these pixel buffers; caller-owned acquisition buffers, metadata, model state, input preprocessing and worker memory require their own budgets. This is not a measured whole-process memory qualification.

Work has a private runtime owner identity in addition to its sealed scheduler token. Two runtime instances cannot accept each other's completion even if a caller incorrectly reuses the same declared epoch and frame metadata. Invalid-clock or wrong-owner completion returns ownership of the issued pair with the error, permitting retry against the correct runtime and clock. Successful/stale/retired completion consumes its issued work. Retirement closes the metadata scheduler and releases runtime-owned pending/previous pixels; it does not acknowledge a physical stop or authorize resumption.

A source-clock interval or capture-clock interval over 500ms clears pending temporal pairing and seeds from the newest capture. The next increasing capture can form a new pair. This does not invent an observation across a discontinuity, and it does not relabel an already issued result. Expired pending analysis releases its pair while retaining the latest capture for continuity checks. Capture/source clocks still come from the caller; their provenance and calibration are not established by this API. Clock-bound instances additionally require the checked project/presentation mapping and retain it in issued declarations.

The status reports admitted pixel capacity, unique pixel bytes held by the runtime, pending/in-flight metadata counts, pairing discontinuities and whether a new pair is awaited. Runtime-owned byte counts exclude pixels currently owned by the issued consumer; the conservative reservation includes their permitted capacity. A retired runtime retains its reservation while its object remains alive, so the engine must remove it from the active registry after retaining bounded status facts.

Local tests exercise real byte contents under 100-frame overload, exact byte-derived identity, latest chronological pairing, admission refusal/release, retained ownership after retirement/drop, pending expiration, source/capture gaps, invalid metadata, completion retry, same-epoch cross-runtime refusal and the shared packed parser. Native worker/CLI regressions exercise that parser in confined inference. These scenarios are synthetic ownership/software evidence.

Required successors remain engine session/grant/revision integration, bounded acquisition and authenticated byte transport, persistent confined inference, cancellation/retirement, source/player clock provenance, presentation buffering, visible sustained timing/skips and actual device admission/dispatch/qualification. This module neither supplies model-result authority nor replaces any of those obligations.

The retained [validation checkpoint](evidence/roadmap-2026-10-01/live-pixel-ownership/validation.json) binds current source and native binaries to 715 passing Rust tests, seven ignored qualification cases, all 74 passing native-configured JavaScript cases without skips and 167 passing structural architecture checks. Seven pixel-ownership regressions, raw gate logs and rebuilt worker relative/buffered/unbuffered parser receipts, programs and exports are retained. Native build and diff checks passed. These results do not qualify continuous live sessions, model quality, whole-process memory, physical timing or Handy behavior.
