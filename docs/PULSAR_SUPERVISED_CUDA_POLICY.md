# Supervised CUDA policy binding

Verification: 973 workspace tests pass (49 ignored); 511 CUDA-feature tests pass (43 ignored); the new native case passes explicitly in both configurations and again in default against the rebuilt app; 243 structural checks pass. All 324 archived/live production and verification records match.

Status: PARTIAL. CUDA transport metadata can now be built from the retained supervised capture owner without parent-process content rehashing. This is a prerequisite for production GPU integration; production GPU jobs still refuse before capture/launch.

`LoadedCudaOwnerPolicy::worker_execution_supervised` checks the exact loaded policy against the captured declaration, the completed copy's declared length, profile/runtime/device/priority constraints and current image metadata. It borrows the owner without releasing storage or assuming GPU admission. The existing generic-capture builder retains full content hashing; common metadata assembly preserves dependency identities and protocol validation.

The native regression uses an actual confined copy of six authored non-library inputs. It compares both builders' transport metadata, rejects priority/runtime/foreign-specification and writable/missing-alias cases, preserves storage throughout construction and releases it through explicit image close. Supplier pathname changes cannot change the captured image. A same-size in-place content change with restored readonly permissions deliberately passes metadata construction while independent full hashing refuses. This establishes the boundary: completed copy verification is historical evidence, not byte immutability. The existing confined CUDA bootstrap's fresh mounted-alias hashes remain required and unchanged.
