# Inert bundled generation pack delivery

Current integration update: [verified CLI discovery](PULSAR_BUNDLED_MODEL_DISCOVERY.md) now exposes bundle identities and import paths from the installed runtime or an explicit retained cache. Graphical admission and useful default model/preset policy remain open. The transport evidence below retains its original artifact subject.

Linux runtime candidates can now carry explicitly declared generation packs through assembly, archive installation, first-use cache verification and AppImage extraction. This closes the missing payload transport identified in the earlier model-delivery inspection. It does not select an edition default, approve native execution, qualify a model or complete Core/Complete delivery.

The assembler accepts `--generation-packs /absolute/declaration.json` alongside the existing CPU-runtime and assistant declarations. A supplier declaration has schema version one and a `packs` array of absolute directory paths and pinned manifest SHA-256 identities. Up to eight packs are admitted, subject to existing pack asset/total limits and the runtime manifest's 64 KiB bound. Each is copied under `generation/<manifest-sha256>/`, including its original manifest, model, profile, runtime and license assets. The outer manifest embeds the validated pack declaration and binds every delivered file's length and hash. Both native archive publication and installation compare the captured manifest bytes against that declaration. No native model loading occurs during transport.

Nested payload directories now receive private permissions, directory sync and exact inventory checks at every level. Cache reuse rechecks all bytes and embedded pack declarations. Unknown entries and changed payloads are refused and preserved. Abandoned-stage recovery preflights every declared level before deletion, retains held parent identities, removes descendants before parents and still requires explicit discard approval. Existing candidates without generation declarations remain readable by the new installer; older strict installers do not understand newly extended manifests.

The [checkpoint](evidence/roadmap-2026-10-11/generation-delivery/checkpoint.json) binds current source and artifacts. Final verification passed 787 default Engine tests with zero failures and 59 ignored environment-dependent tests, both strict workspace/all-target Clippy configurations, all-feature application/worker builds, formatting, inventory unit tests and architecture/guard checks. Standard export refused unresolved motion evidence from authored frames.
- The actual AppImage verified all sixteen delivered payloads after first use. A changed generation model was preserved and refused on reuse. Extraction cleaned up automatically on success and refusal.
