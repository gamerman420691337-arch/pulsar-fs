# Retained local batch cancellation

`pulsar library-batch-cancel BATCH --request-id CANCEL_ID` requests a durable stop. Keep the cancellation ID and retry exactly that command after an interrupted acknowledgement. Status includes the retained cancellation ID, per-job request IDs and ordinary job acknowledgements. Completed projects, source snapshots, candidates, exports and published files remain preserved.

The Engine records stop authority and claims its request identity before dispatching cancellation. Subsequent uncached generation advances refuse, including an unresolved earlier advance. A previously cached positive advance can replay historical state; current batch status remains authoritative. The scheduler reads current stop policy before every decision and again before its final report. Standalone publication reads it before creating an intent and before each bounded publication decision. An independent or already in-flight publication may finish; this command provides no rollback or global export revocation.

Only jobs already identified in a Generating entry receive ordinary CancelJob requests. Their project, base revision and request identity are retained before dispatch. Completed, failed and already cancelled jobs keep their terminal states. Ready and candidate-ready entries are preserved. Missing grants, revision conflicts and unknown outcomes remain visible; no replacement job, source, model or project is created. A different cancellation ID cannot take over an existing stop record.

An unresolved generation effect is reconciled only from its exact cached positive acknowledgement. The original inner operation is never dispatched during cancellation. An absent or conflicting receipt retains both pending identities and keeps cancellation incomplete. Because ordinary request fingerprints include bearer authority, credential rotation can prevent this reconciliation; this is not an implicit identity migration. A known cached create/import/generate/commit acknowledgement can update the retained item and reveal an existing job for cancellation without executing that original operation again.

`cancellation.completed` means durable stop policy, acknowledgement of the known job cancellation requests and no unresolved generation effect. It does not establish physical worker retirement. `worker_retirement_verified` and `qualified` remain false. Workflow reports expose cancellation_requested and cancellation_acknowledged; cancelled workflows never report overall completion, even when publication history is complete. Read-only status preserves client journal bytes and existing publication receipts.

`pulsar library-batch-release BATCH --request-id RELEASE_ID` may release a completed cancelled partial batch after every retained job is currently terminal and absent from the Engine worker-handle map. It removes only this ledger and its source membership pins. It does not remove source/media/output files, projects, jobs, candidates, exports, other batch memberships or client journals. Pending acknowledgements and active worker handles still refuse release. The membership removal and exact release receipt share one transaction.

The first cancellation transaction raises the outer database reader floor from 28 to 29, preserving the existing underlying schema and layouts. Current readers continue to accept uncancelled schema-28 batches. Inner schema writers preserve the outer floor; older schema-28 applications refuse before durable database/WAL mutation. Cancellation-bearing reports use report schema 2. Reports without cancellation retain schema 1 and omit the optional cancellation field. Private publication journals retain their existing schema and history.

This is a software stop and explicit metadata-disposition checkpoint. Continuous watching/intake, general migration, snapshot/stage/journal collection and unknown-receipt disposition remain separate work. Authored software fixtures do not establish model/media quality, interactive GUI, non-Linux runtime, physical-device stopping, physical durability, human acceptance or release qualification. The full roadmap remains partial.
