# Desktop retained CUDA evidence removal

The desktop Capture evidence panel offers **Remove retained originals** after original-record inspection. It displays the capture ID and manifest hash, explains logical disposal, and requires the operator's confirmation checkbox before sending a new removal. The operation runs on the existing background session worker, requiring the Engine's current Read and project-administrator authority and current revision.

A submitted request retains its original project, revision, capture epoch, manifest hash and request ID in the panel. If no validated receipt arrives, **Retry saved removal** sends exactly that intent; navigation does not rewrite it. Receipt validation checks the project, epoch, manifest identity and false physical-erasure claim before presenting success. A successful removal invalidates visible records for the affected project, including after a revision change; it does not replace another project's view.

Pending removal is shown even when no project is open. [Durable recovery](PULSAR_DESKTOP_CUDA_REMOVAL_RECOVERY.md) now saves the exact intent before dispatch and restores it with the same session/credential/endpoint binding. Reopening never retries automatically. A worker failure retains the pending selection but disables dispatch; the saved entry remains available after reopening. Clearing the retry selection never cancels or rolls back removal and never deletes the saved unknown entry. Revision conflicts and refused requests are not silently rewritten as fresh removal requests.

Logical removal does not securely erase SQLite pages, journals, backups, previously exported files or immutable bytes held by admitted downloads. Existing downloads retain their ordinary abandonment, revocation and expiry behavior. See [the Engine and CLI contract](PULSAR_RETAINED_LIVE_CUDA_REMOVAL.md).
